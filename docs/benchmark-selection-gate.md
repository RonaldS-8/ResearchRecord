# Benchmark Selection Gate · Belief-State SSP

日期 2026-11-06。只读代码审计，先 CostBench，后 ToolMisuseBench。CostBench 使用项目基线 `968baa0` 中的源码（该目录最后修改于 `02b5f4f`），并核对上游说明。ToolMisuseBench 在 LabServer 临时检出 `b6ee3412f98d2058ee487e182a72b26c58046d51`。ToolMaze 比较沿用实验 008 的既有 C3 运行。先做源码审计，再做 [实验 009 云端探针](experiments/009-benchmark-selection-smoke.md)。下表为源码证据，云端实测另列。

## CostBench

| 判据 | 原生能力与限制 |
| --- | --- |
| 多步、替代路径与评分 | 有合成旅行规划任务、原子工具和复合工具。工具输入类型形成依赖，原子与复合调用提供替代执行序列。求解器在已拥有的类型集合上搜索，不能据此认定具体参数和数据来源合法。最终答案按目标候选 ID 比较，达到目标类型另记。原生答案准确率未同时强制验证完整合法调用轨迹。见 `env/utils/solver.py:127–205`、`env/run.py:795–811`、`env/utils/eval.py:527–552,649`。 |
| 同状态分叉 | `env/run.py:958–1001` 提供单次工具模拟和工具快照重建，不能由此恢复完整回合。要严谨配对，需要重建或重放工具目录、已取得的值、可见历史、禁用状态、触发游标和参考时间线。随机策略模拟可参考，未验证两个动作是否能从等价的完整运行状态分叉。 |
| 隐藏故障、转移与反馈 | 原生禁用在触发回合选择 Agent 当前调用的工具，并另外按参考路径禁用参考工具。后续调用已禁用工具继续失败，分支返回禁用提示。状态、转移和反馈缺少可独立替换的配对接口。见 `env/utils/blocker.py:770–874`、`env/run.py:439–485`。成本和偏好变化属于原生动态事件，可以作可见变化的对照。 |
| 成本与诊断 | 原生异质成本。原子成本可设区间，复合成本由组件成本及噪声生成，工具反馈附带成本。见 `env/domains/travel/tool_registry.py:172–254`、`env/run.py:958–984`。未找到面向隐藏故障的显式诊断动作。拟议扩展至少需要独立回合包装、故障模型和证据接口，并验证费用与反馈隔离。 |
| 无真值恢复 | 看到禁用提示后排除对应工具、按合法可见资源重规划，是可定义的规则。原生求解器可用于类型层面的最短路参照。仅凭可见值执行并通过评分尚未实测，不能把参考时间线当作策略输入。 |

CostBench 值得保留为异质成本和确定性重规划参照。作为主基准，原生价格系统节省的工作会被回合分叉、故障配对和端到端合法完成验收抵消。暂未证明改造量低于 ToolMaze。

## ToolMisuseBench

| 判据 | 原生能力与限制 |
| --- | --- |
| 多步、替代路径与评分 | CRUD、检索、文件和调度都有实际模拟状态。原生模板的清洁成功通常只需一次目标调用。v2 加强部分输出与终态检查，但检索仍指定 `get_doc` 或 `search_docs`，不同工具完成同一意图也可能无法得分。多轮纠错可以发生，未形成系统性的多步依赖与等价替代路径。见 `toolmisusebench/generator/core.py:173–388`、`toolmisusebench/version2/generator.py:125–204`、`toolmisusebench/envs/base.py:160–234`。 |
| 同状态分叉 | `BaseToolEnv.reset` 使用任务种子初始化故障引擎，能按相同动作前缀重新回放。公开 `snapshot` 只复制业务状态，未涵盖计数器、随机数和故障触发进度。见 `toolmisusebench/envs/base.py:63–94,172–176`、`toolmisusebench/harness/runner.py:45–80`。分支重放未实测。 |
| 隐藏故障、转移与反馈 | 故障计划支持按工具、调用序号、参数和种子化概率触发。超时输出由单独的注入器构造。v2 默认超时通常只在首次触发，未提供可独立控制的动态潜在状态链。有些故障事件会附在返回或错误详情里，再进入可见 transcript。隔离时必须逐类核查，原样保留合法错误。见 `toolmisusebench/faults/base.py:18–101`、`faults/timeout.py:7–17`、`envs/base.py:92–135,236–260`（均在包目录下）。 |
| 成本与诊断 | 原生按调用、步数和错误重试预算计量，未找到每工具异质计价和付费显式诊断。需扩展计量、工具接口与观察隔离。见 `toolmisusebench/version2/generator.py:37–41`、`toolmisusebench/envs/base.py:138–158,246–261`。 |
| 无真值恢复 | 原生 agent 接口仅接收 Observation，已有指令解析和参数修复基线。从合法超时反馈重试在接口层可实现。仍须逐类检查 Observation 中的注入事件及基线是否依赖它们。见 `toolmisusebench/harness/runner.py:19–22,57–79`、`toolmisusebench/version2/baselines.py`。 |

ToolMisuseBench 的故障与观察接口适合参考，但作为主基准需要增加多步依赖、等价替代完成条件与异质成本。任务与评分的工作量可能高于保留 ToolMaze。

## 决策

**保留 ToolMaze 为原生对照。优先评估 ToolMaze 的独立扩展作为主实验候选，暂不迁移。** ToolMaze 已有多路径、原生扰动与评分、可复用的云端回放资产，Gate 3 扩展已有参数来源检查和隔离的诊断入口。原生 C3 小样本的 6 对首错均不同，且均有共同最优的直接切换首动作。这个反证限制了原生 C3 对信念更新的鉴别力。其原生评分也不能单独证明参数合法性，应保留额外检查。

拟议最小扩展是复用任务和原生评分，在独立层增加可配对的故障持续性、合法证据通道与每工具费用，保留原生对照。诊断精度、恢复时间分布和相对成本都可能偏向某类策略，须在看结果前论证取值、登记范围并用固定重试、One-bit Memory、最短路和历史统计对照。放行条件是同一合法起点能重放多个可完成分支、存在真实的成本与信息权衡、且已排除仅由参考路径或故障标签泄漏产生的增益。独立扩展须另立 ADR；本轮只做选型判断。

## 云端小样本复核

- **CostBench：** 原生住宿工具目录有 79 个不同的成本值。同一个类型起点，原最短路径为两步、97.09，排除首个工具后替代路径为三步、97.24。禁用组件的两次分支均禁用了当次 Agent 所选工具，而参考解所禁工具相同。原生答案评分在未提供执行轨迹时接受匹配 ID、拒绝错误 ID。成本是求解器模拟成本。路径未逐工具执行，真实参数可得性与完整动态回合仍待验证。
- **ToolMisuseBench：** v2 检索超时任务 00063 在重试、切换、停止分支的首错后观测完全一致。只看观测的原生指令解析基线重试成功并通过评分。切换探针用审计器提供的文档 ID，虽然取到正确文档，评分仍失败，原因是成功判据绑定搜索工具。原生错误直接暴露 `recoverability=transient`。审计夹具仅去掉首次调用限制，保留同一错误元数据，首错观测相同、后续重试失败。它验证了机制可构造配对，但也显示默认元数据须单独审计。
- 两项实测强化了原选型判断。CostBench 已证实有价格和替代序列，ToolMisuseBench 已证实能原生重放并执行恢复；两者仍缺少可直接使用的完整研究条件。单例不外推。
