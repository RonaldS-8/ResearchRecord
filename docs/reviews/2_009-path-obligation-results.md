- **002 账户。** 002-R00/R10/R11 都取得正确业务类型和取数回执，也执行了通用归档，但把载荷写为带字段标签的纯文本。冻结验收只解析 JSON 对象，因此三回合的来源绑定和局部业务判为失败。R00 以券商账本引用作账户标识，同时保留类型、余额和币种。R10/R11 以用户标识作账户标识。能核对到这些业务值，不能把三次判负都归因为值丢失。R01 使用结构化载荷并通过。
- **005 和 011。** 四个模型组均先取得目标数据，后用通用归档完成，路径提示和义务清单均无可观察增益。
- **026 天气。** R00 使用未受扰动的通用天气接口，成功保存城市、温度与天气的简报，但漏了用户要求的提醒等级。R01 直接结束，未发工具调用。R10 与 R11 均改用候选中出现的气象来源，后接通用归档。天气候选前五没有通过冻结的完整链覆盖判据，其首条包含可用取数工具却接两个归档工具。两个模型均自行改成单次写入。R10 如实保留结构化回执并通过。R11 的四个业务值与取数信息都能对照，天气状况写为 `conditions`，冻结字段等价表未收录这个键，归档因此判负。两个回合的分数不追认、不重算。
- **回执核对。** 15 个发出归档调用的模型回合全部报告了两个 ID，记录器也匹配到相应的可见核对线索。该线索来自回复或可读推理，不能证明 Agent 做了独立状态查询。无公开归档读回接口，写后状态查询记不适用。没有观察到业务规则通过但因漏报回执而失败的回合。
- **规则参照。** D 为 4/4，21 次顶层调用。模型组 10/16 严格通过，30 次顶层调用。D 在每区组可扫描完整排序，模型候选提示只有前五，且 D 与模型的实际调用约束不同。结果表明公开信息下存在可执行续程，不能将全部差距解释成模型不遵从。

**研究判断。** 值得继续核验的真实行为是天气任务里未取得带提醒等级的数据，或者在入口失败后没有继续调用。候选提示恢复了该任务的取数路线，证据限于一个区组。其余主要落差涉及从真实回执到可验收载荷的交付，当前评分对纯文本和未列字段名的限制妨碍把差额解释成普遍义务执行失败。原生 ReAct 的两个失败没有形成两个同类且独立可复核的行为阻断，未达到预登记的瓶颈门槛。
