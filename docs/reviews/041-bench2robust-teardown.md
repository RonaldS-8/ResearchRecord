# Bench2Robust Benchmark 拆解（Gate 41 任务 C）

2026-11-13。依据论文 v2 的 HTML 全文与附录 A–E（arXiv 2608.11977v2，2026-10-11；v1 标题不同，为 2026-08-12）。读法：先由一个只读代理通读全文并列出逐节摘要，我再直接向论文页面逐项核对了下文标“已核对”的条目；其余条目来自那次通读，标“通读”。全文只转述，不照抄。按用户 2026-11-11 的决定，论文里的结果数字只用来说明“论文怎么说”，不作为本项目的对照数字。

## 结论

1. **没有可用的官方代码。** 论文的可复现性声明只说将来会发布注入框架、领域注册表、信念计算脚本和评测工具，没有给出地址（已核对）。2026-11-13 检索 GitHub、Hugging Face、Papers with Code 和论文页面的代码栏，均未找到官方实现（我与代理各检索一次）。代理另找到一个第三方仓库，它自述因为原代码未发布而重写了一个 Beta 后验基线，并非该 Benchmark 的复现（通读，未逐项核对）。
2. **它的随机错误按构造都是暂态的，持久故障只来自场景屏蔽。** 同一工具最多连续失败两次，之后必然返回干净结果。于是“至少重试一次”在只有噪声的场景里几乎总是对的，这条写在 BTM 提示里的静态约束与环境的构造恰好吻合。
3. **它不计恢复动作的成本，也不评停止是否正确。** 唯一的任务指标是通过率；成本只以 Token 和平均步数的形式附带报告；不可恢复场景只用于训练，评测不计分。Q2 关心的“剩余成本”和“正确停止”在它的评测里没有对应物。
4. **论文自己的消融显示，增益主要来自静态结构和在线更新，而不是历史统计。** 只给动态信念几乎没有提升；给静态结构加均匀信念就拿到了大部分提升；在线版本会用评测回合的结局更新信念。
5. **从论文无法重建这个 Benchmark。** 每个任务的等价类与可行路径集合、屏蔽回执的文本、评测时的场景比例、替代工具的模式、划分方法、Beta 先验等都没有写明。

## 1. 机制重建

### 场景 S1、S2、S3（§1、§2.1、算法 1；已核对）

场景是每个回合在环境层面固定的“可恢复性”，不是任务子集。

| 场景 | 含义 | 规定的正确行为 |
| --- | --- | --- |
| S1 | 原路径仍然可行，没有任何任务相关路径被永久屏蔽，只有随机噪声 | 重试即可恢复 |
| S2 | 从任务相关的等价类里随机选一条路径，整回合屏蔽 | 切换到剩下的等价路径 |
| S3 | 全部任务相关的可行路径整回合屏蔽 | 上报（转人工） |

屏蔽是确定性的，优先于随机注入，被屏蔽的调用不执行、状态不变，也不占随机注入的额度。训练课程的场景比例（表 9，S1/S2/S3）依次为 100/0/0、80/20/0、60/40/0、40/50/10、30/45/25。S3 只在训练里出现，评测不计分，因为原 Benchmark 的评测器对无解任务不给完成分。

论文没有写明：评测时 S1 与 S2 的比例；一个任务有多个等价类时选哪个；每个任务的等价类与可行路径注册表；屏蔽回执的具体文本，以及 Agent 能否把它与随机错误区分开（已核对为未写明）。

### 错误注入（§2、附录 A.1–A.3、表 7；已核对）

每次未被屏蔽的调用独立抽样：以 0.60 的概率干净返回，其余 0.40 分给九种错误。

| 类别 | 错误（概率） | 调用是否执行 |
| --- | --- | --- |
| 显式 | 超时 0.06、限流 0.05、服务端错误 0.05、畸形响应 0.04、鉴权 0.03、模式漂移 0.03 | 不执行，状态不变 |
| 静默 | 部分数据 0.05、过期值 0.04、事实错误 0.05 | 执行，返回被篡改的内容 |

两条上限：每回合至多 5 次随机注入；同一工具至多连续 2 次随机失败。算法 1 的含义是达到任一上限后该调用不再注入、返回干净结果。因此所有随机错误都是暂态的。论文明确说不模拟“请求失败但副作用已部分生效”的中间情形；没有提到丢回执。

论文没有写明：各工具的分布是否不同（表 7 只给了一组）；是否依赖参数或调用位置；连续失败计数何时清零；静默损坏选哪些字段。

### 替代工具（§2.2、附录 A.4、表 8；已核对）

零售领域从 16 个工具增加到 21 个，新增的五个各对应一个原工具：按名称而非 ID 查商品；按选项而非 ID 查条目；一次取回用户全部订单的摘要；凭订单号认证用户；一次性检查换货可用性。论文没有说明这些工具由谁编写、参数与返回字段是什么。切换之后要不要核对字段只是 BTM 提示里的一条约束，环境并不强制。没有 BTM 时，Agent 是否被告知哪些工具互为替代，论文没有写明；显式的“原工具→替代工具”映射只出现在 BTM 提示里。

“注入但无替代”的条件只用标准工具集里已有的等价关系，论文只举了一例，没有给全表。

### 数据与划分（§4；已核对）

合并零售集共 1,339 个任务：114 个来自 τ²-bench 零售，1,225 个来自 Retail-3I。划分为 937 个训练任务与 402 个留出任务，没有验证集，划分方法没有说明。另有航空、电信和一个多轮函数调用集用于迁移（通读）。

### BTM（§3.1、附录 B.1、图 2；已核对）

- **动态部分。** 对每个（工具, 错误类型）维护一个 Beta 后验，估计的是“该工具遇到该错误后，这个回合最终还能成功的比例”；对（源工具→目标工具）另有一组切换信念。论文明确说这些是回合级的可恢复性估计，不是某次重试或切换会成功的因果概率。
- **历史来源。** 基础模型在 937 个训练任务上的轨迹，3–5 个种子。Beta 先验参数没有给出；哪个注入模式下采的、每个键有多少样本也没有给出（切换信念的样本量很小，论文承认有选择偏差；通读）。
- **固定版与在线版。** 固定版停在训练集的估计上；在线版在每个评测回合结束后，用该回合是否恢复来更新信念，供后面的回合使用，每次运行之间清零。主结果表用的是在线版。也就是说，评测器对测试回合的判定会进入记忆。
- **静态部分。** 替代映射加粒度说明，以及六条约束：失败后至少重试一次；切换后核对字段与粒度；不可逆操作前从真实返回里确认字段；价格计算用计算工具；写操作后检查返回；只有重试和替代路径都用尽才转人工。
- **提示模板。** 系统提示里的一个工具可靠性块，含四部分：各工具在九种错误上的信念与替代工具、使用方法的启发式、替代映射、约束。“高”“低”信念没有给数值门槛（通读）。

### 训练（§3.2–3.3、附录 B.2、表 9–10）

BTM 本身不需要微调。论文另用强化学习训练 Qwen3-4B-Thinking-2507（及一个 8B 复现），每回合最多 25 步，用户模拟器是 Qwen3-235B（已核对）。奖励对通过的回合按效率和重复调用打折，对未通过的回合按匹配动作比例给部分分，没有“正确停止”的奖励（通读）。

### 评测（§4–5、附录 D；已核对）

- 指标只有各原 Benchmark 自己评测器下的通过率，分三种条件：干净、注入无替代、注入有替代。成本只报告 Token 总量和平均步数（表 14，单次运行）。没有工具价格、付费诊断或停止正确性指标。
- 评测时的步数上限和温度没有写明（表 10 的 25 步是训练配置；温度 0 只在表 1 标注）。4B 的主结果是 5 个评测种子的均值，每个强化学习模型只训练一次。
- 论文报告的主结果（表 2，402 个留出任务，在线 BTM）：基础模型在三种条件下为 64.3 / 20.1 / 31.9，加 BTM 后为 65.3 / 36.9 / 43.6。
- 论文报告的消融（表 5b，1,339 个任务，注入无替代）：无信念 23.2；只有动态信念 24.9；静态结构加均匀信念 33.7（固定）/ 40.8（在线）；完整 BTM 37.8（固定）/ 41.6（在线）。
- 对比基线是基础模型与两种普通微调，没有 ReAct 式或简单规则基线（通读）。

## 2. 与 ToolMaze C3/C4 和本项目机制的对照

| 维度 | Bench2Robust | ToolMaze C3/C4（本地代码） | 本项目（Gate 34、40、41） |
| --- | --- | --- | --- |
| 故障从哪来 | 每次调用独立注入九种错误，外加场景屏蔽 | 任务文件里预先标定的受害步骤，首次触碰激活 | 隐藏状态决定各工具成功率，按登记分布抽样 |
| 暂态与持久 | 随机错误必为暂态（最多连续两次），持久只靠屏蔽 | P1/P3 只扰动第一次调用，P2/P4 每次都扰动 | 暂态、慢恢复、持续、共享故障、阻断等状态并存 |
| 切换后再次故障 | 替代工具同样受随机噪声，但不会持久失败，除非 S3 | C3 不会；C4 只在后面的槽位 | 可以：陈旧备用、共享网关、同提供方写入器 |
| 替代路径 | 人工加入的等价工具，显式映射只在 BTM 提示里 | 任务自带的完整等价路径，共享工具不必重做 | 进度图，路径可共享工具、分槽位 |
| 不可恢复 | S3，只用于训练，不计分 | C1 的持久扰动要求优雅停止 | 阻断状态，计入完成率与费用 |
| 成本 | 无价格；只附带 Token 与步数 | 以调用次数算恢复成本比 | 每次调用按公开报价计费，失败照收，诊断单列 |
| 公开上下文与诊断 | 无 | 无 | 上下文标签、错误细节、单独计费的有噪声诊断 |
| 评分 | 原 Benchmark 的通过率 | 规则匹配完整路径 | 严格完成（义务、零非法调用、合法终答）与费用分列 |

## 3. 可复用之处

- **场景分层的写法。** “只有噪声 / 屏蔽一侧 / 全部屏蔽”是一个清楚的可恢复性控制，可以直接对应本项目的隐藏状态先验。Gate 41 的 B2R-mini 格就是按这个结构写的。
- **九种错误的分类。** 显式与静默两类、各自是否执行调用，可以作为本项目错误细节标签的来源。静默损坏本项目尚未建模。
- **注入上限的思路。** 每回合注入额度和连续失败上限保证任务可解，适合做“规则足够”的对照格。
- **BTM 的提示结构与六条约束。** 本项目的提示复现（Gate 18 起）已经按附录 B.1 写了，可继续沿用，并应保持固定版，不用在线版，因为在线版会把评测结局带进记忆。
- **论文自己的消融设计。** “只有动态信念”“静态结构加均匀信念”这两个对照值得在本项目的 BTM 基线里保留。

## 4. 无法核实之处

- 每个任务的等价类与可行路径注册表，以及标准工具集和多轮函数调用集里的“自然等价类”。
- 屏蔽回执的文本，以及它与随机错误在 Agent 看来是否可区分。这一点直接决定“重试还是切换”在它的环境里是不是一个可观测的判断。
- 评测时的场景比例、步数上限、温度。
- 替代工具的模式与实现。
- 937/402 的划分方法与任务编号。
- Beta 先验、更新增量、实际信念值、每个键的样本量、历史是哪批轨迹。
- 静默损坏如何选择字段；随机种子如何处理（附录承认不同运行的注入种子可能不同；通读）。
- BTM 块之外的 Agent 系统提示。
- 所有结果数字。没有代码就无法复算，本项目不把它们当对照。

## 5. 对本项目的含义

**B2R-mini 的结果（实验 041 的 A2，CPU 环境模型内的参照值，不是 Agent 值）。** 取一个等价类，按第四阶段的场景比例（40/50/10），在原工具第一次失败之后，主工具被屏蔽的后验概率约为 0.675。在本项目的口径下（每次调用计费、首错后剩 6 次调用）：

- 先切换与先重试的完成率相同（0.775），先切换的费用低 3.5%。“至少重试一次”在这种混合下不是最优首动作；只有 S1 时它才是（3.26 对 4.07）。
- “重试一次再切换一次”这种不坚持的做法完成率低 13.9 个百分点，因为随机噪声下每个工具都可能需要再试。
- 在我们的 6 次调用预算下，“把原工具试到上限再切换”的完成率只有 0.326，因为对一个被屏蔽的工具反复重试会把预算用光。我登记时写的“忽略费用时穷尽式顺序完成率相同”没有考虑这个预算，在登记的格上不成立。
- 事后补算（看到上面的结果之后做的，不属于登记内容）：把预算放宽到 12 次或 25 次调用（论文训练配置的步数上限是 25），两种穷尽式顺序都完成了全部可解回合（0.807），完成率确实相同；但费用不同，先重试到上限为 5.75，先切换到上限为 4.89，最优为 4.60。也就是说，在它自己的口径下（只看通过率）这两种顺序无法区分，在计费口径下先重试贵 25%。

这说明两件事。第一，Bench2Robust 的环境里，坚持尝试比选对动作更重要：步数宽松、错误必然暂态、不计成本，任何肯穷尽的策略都能完成 S1 和 S2。BTM 的增益很可能主要来自让模型不要过早放弃，而不是选了更好的动作；论文的消融与这一读法一致，但没有代码无法核实。第二，一旦像 Q2 那样对调用计费并限制预算，同一条“至少重试一次”的约束就可能有害。本项目与它的差别应当落在这里，而不是落在统计量的形式上。

**公平比较时要注意的三点。** BTM 基线用固定版信念；BTM 的统计来自与评测分离的训练历史，并写明采集策略；在本项目的 Benchmark 上，“至少重试一次”与预算、计费冲突时如实报告它的代价，同时保留去掉该约束的消融。
