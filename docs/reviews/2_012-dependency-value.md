### 依赖审计

按生产工具、输出字段、消费工具、输入参数去重，显式引用有 256 种。其中 154 种同名、13 种异名、89 种取整个返回对象。在原任务记录中分别有 99、11、72 种能找到同一个值或单元素包装传给目标字段的见证。这是已记录路径的值核对，共值和出现次数均不能证明来源唯一、边正确率或在线恢复。缺见证可能源自目录未实例化、封装或执行差异。完整逐边清单记录了分母、所属组及见证数。

| 合同与业务关系 | 已核对例子 | 可检验的结论 |
|---|---|---|
| 同名直接引用 | 库存预留的 reservation_id 进入 confirm_order，同值见证 77 次 | 对唯一来源，同名和类型规则即可连接；来源若有多个仍应核对对象 |
| 异名、语义对应 | optimize_discount.final_total 进入 submit_order.payment_amount，见证 16 次；hold_best_recommendation.recommended_product_id 进入 confirm_order.product_id，见证 26 次 | 强语义规则也可能识别。替代字段表示本次订单应付额或选中商品的角色，不能任取同类型值 |
| 条件依赖 | 原 shortlist_meeting_rooms 插件对同一容量 2 房间，2 人返回 R，3 人返回 No available room can fit 3 attendees | 字段 rooms 可合法传递，结果取决于实值。该 CPU 对照只验证处理器局部前提 |
| 合同不能唯一确定 | snapshot_workspace.backup_id 被登记为 push_alert.message；create_document.title 也被登记为同一输入 | string 类型与通用消息说明无法指定应发哪一字段，需要用户义务或实际证据。两条在本轮原生任务轨迹中均无同值见证，仅作登记映射，不能判真实执行成功 |

条件性与字段同异名可以重叠。整对象引用也可能要求嵌套字段，不直接列为异名正确边。整个清单是隔离评测资料，不能派生策略的别名字典。

### 独立价值与方法边界

图是关系的表示形式，表达能力取决于如何提出和判别边。合适的检验是固定候选、搜索和执行流程，只换边得分器。当多个金额都类型相同、名称不匹配，而上下游合同分别说明折后额、付款用途及对象时，学习到的语义得分可能给强规则遗漏的边更高排名。若合同缺少区分信息，换成图仍无法识别。现有 M4 迁移代码 public_parameters 先从输入字段名寻找同名输出，derive 又按发布专用读回说明定位唯一端点；作者检索还按金标签是否已在候选中决定是否补齐。三处都不能直接用于独立比较。2_012 目前仅提供隔离评测脚本，未交付或运行新的无标签在线策略。

可检验的最小改进是先按类型和单位排除不兼容边，再按来源字段说明与目标参数说明的语义相似度排序。第一、二名得分接近时保留两条，仅对可安全重置、且会导致不同可观察结果的分支验证。把这一启发式先做强规则基线，和相同候选上的作者判边器比较。阈值只在开发集选定。当前结果只定位了候选生成器的同名限制，尚未证明独立任务上图劣于规则。

### 决策

保持 In-N-Out 为主基线。现有库通过独立资格门槛的正式任务为零，暂不申请启动 GPU。若研究问题改为已见家族的新组合，或引入另一个公开环境，须另行批准并重新登记独立性口径。各臂信息、预算、指标及验证消融见预登记；目前构图、在线 Agent、重放均零调用，运行成本只有 CPU 审计，未单独计时。[预登记](../experiments/2_012.md) · [逐边清单](../evidence/2_012/inventory.json) · [复算脚本](../evidence/2_012/audit.py)
