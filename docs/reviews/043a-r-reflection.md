# Gate 43A-R：PR #16 验收失败后的反思、修复与建议

2026-11-13。针对独立验收 `docs/reviews/043a-pr16-independent-review.md`（No-Go；该文件在分支 `review/pr16-acceptance` 上）。仅 CPU，未运行任何模型；未改 main、评分定义和任何已登记结果。登记与完整数值见[实验 043A-R](../experiments/043a-r-gate42b-correction.md)，原始文件见 [`docs/evidence/043a-r/`](../evidence/043a-r/README.md)。

**读数须知。** 所有数值都是 CPU 环境模型内的参照，不代表任何 Agent 的表现。

## 结论先行

1. **七处校验值不符已逐字段定位，原因是记录方式，不是结果不同。** 14 个字段的 `0.0` 与 `-0.0` 之差，由 Python 版本对浮点数求和的方式不同引起。登记的校验值没有改。
2. **似然滞后是真实的实现缺陷，但没有改变任何模型选择。** 2640 个拟合场合里，结构和状态数的选择 0 次不同。
3. **原来的并列带在数学上没有定义清楚。** 已换成两条与比较顺序无关的规则，其中一条对整个计划的完成率损失有可证明的上界。
4. **我在上一份报告里的一个主要结论是错的。** “小样本下完成率更高”不来自隐藏状态：逐节点基线只要不在没有数据的地方停下，就有同样的完成率。上一轮的基线偏弱。
5. **剩下的优势只在费用上，只出现在生成器恰好符合模型假设的格里，并且依赖一个没有整体保证的带宽。** 在有整体保证的规则下，它在共享故障格上不如旧基线。
6. **建议：信念模型不作为方法进入真实 LLM 实验。** 值得带走的是两个便宜且可被否定的发现，见第五节。PR 是否合并由独立验收决定。

## 一、可复现性：七处不符到底是什么

**排查过程。** 先在本机按登记命令重跑不符的 A 格，得到的还是登记值，所以不是随机性，也不是代码版本。两边的差别只剩平台和 Python 版本：原始运行是 Windows、Python 3.14.7，验收是 Linux、Python 3.10.12。Python 3.12 起内置 `sum()` 对浮点数使用补偿求和，更早的版本逐项相加。于是在同一台机器、同一份代码上只把 `sum()` 换成逐项相加再跑。

**字段级解释。** 14 个不同的字段全部是同一类：`belief2_snap` 这个变体的“自估偏差”，一边写成 `0.0`，另一边写成 `-0.0`（13 个是完成率偏差，1 个是费用偏差）。这个量在这些格上的真值是零，舍入前是 ±1e-17 量级的浮点噪声，符号随求和方式变；舍入到五位后变成正零或负零，序列化成不同的字符，哈希就不同。完成率、费用、种子计数、选出的状态数没有一个字段不同。

**性质判断：实验记录方式的缺陷。** 不是随机性，不是聚合，不是代码版本。两点是我的责任：结果文件里没有记录 Python 版本和平台；把会随平台翻转符号的量原样写进了被哈希的内容。修正版从写盘起去掉负零，并把 Python 版本、平台、命令写进每个结果文件。旧文件和旧校验值原样保留。

**还查出一处我自己的记录不实。** 实验 042 第 7 节说首次作废的启动“只留下空文件”。原始目录里九个文件有八个是空的，但负对照那一个在进程被终止前已经写完，内容与后来登记的结果逐字段相同。我当时没有读它，但那句话是错的，已在实验 042 第 16 节更正。

**没能做到的。** 运行机器连不上云端，所以原始文件随 PR 放在仓库里，没有放到云端审计目录；我也没有拿到验收方的原始 JSON，“本机换求和后的结果等于验收方的结果”是通过校验值相同来确认的。

## 二、数学正确性：似然滞后

`fit` 在最后一次 M 步之后返回新参数，却保留更新前那一步算出的对数似然，重启选择和 BIC 都用了它。这是实现缺陷。修正版多做一次 E 步，使似然和期望计数都属于返回的参数。

它有没有改变结论：在修正版复算里对每个（种子, N）同时用新旧两个似然做选择并计数。

| 选择 | 场合数 | 新旧不同 |
| --- | ---: | ---: |
| 5 状态时带不带转移 | 2640 | 0 |
| BIC 选出的状态数与结构 | 2640 | 0 |
| 两个随机初值取其一 | 26400 | 241（0.9%） |

换了初值的 241 次都没有改变最终选出的模型。所以这个缺陷没有影响 c4 的模型选择结论。第一版（40 轮）的滞后更大（验收报告给出的小例为 0.12），没有重算；第一版的结论本来就是负面的。

另一点要更正：停止条件在实际运行里几乎不触发，所谓“跑到收敛”实际是“固定跑 300 轮”。

## 三、决策理论：比较规则

**原规则的两个问题。**

- 依赖顺序。“完成率相差不到 δ 视为并列”不是传递的。验收报告的例子：三个动作（完成率, 费用）为 (1, 3)、(0.96, 2)、(0.92, 1)，δ=0.05，六种比较顺序可以选出三个不同的动作。逐节点基线和信念模型的求解器枚举顺序不同，所以“同样是 0.05”并不是同一条规则。
- 没有整体保证。每个节点让一点，沿着计划累加，整体可以让出不止一个 δ。

**替代规则。**

- 节点带：在完成率不低于本节点最高值减 δ 的动作里取最便宜的。只由集合决定，与顺序无关。保证是每个决策最多让 δ，$H$ 个决策的计划最多让 $H\delta$。
- 全局界：取 $c-\lambda f$ 最大的计划，$\lambda=\delta/F$，$F$ 是任何计划费用的上界。这是全序，没有顺序问题，并且
  $$c(\pi^\star)-c(\pi_\lambda)\le\lambda\big(f(\pi^\star)-f(\pi_\lambda)\big)\le\lambda F=\delta ,$$
  即整个计划让出的完成率不超过 δ。代价是它很保守：只有每让 1 个百分点能省下 $F/(100\delta)$ 的费用时才让。

两条保证都只在拟合出的模型之内成立。$\lambda$ 只在规划器内部使用，评分仍分别报告完成率与费用。

**换规则之后（N=3000，费用）。**

| 格（最优） | 旧 ACV 容差 0.05 | 旧并列带 0.01（c4） | 节点带 0.01 | 全局界 0.01 | 全局界 0.05 |
| --- | --- | --- | --- | --- | --- |
| M5（3.400） | 3.789 | 3.400 | 3.400 | 3.500 | 3.400 |
| M3（5.300） | 5.313 | 5.303 | 5.303 | 5.303 | 5.303 |
| S4b（3.600） | 3.670 | 3.648 | 3.673 | **3.827** | 3.686 |

节点带与旧并列带几乎相同（完成率最多差 0.1 个百分点，费用最多差 0.7%），说明 c4 的数值不是顺序依赖造成的假象。但在有整体保证的全局界 0.01 下，共享故障格上的费用从 3.67 回到 3.83，比旧基线的 3.67 还差。也就是说，那里的费用优势靠的是“每个节点都可以让一点”，而这恰恰是没有整体保证的那部分。

**性质判断：决策规则定义的缺陷，同时暴露出研究假设层面的问题。** “先比完成率、再比费用”在完成率是估计值时必须配一个让步规则，而让步多少是价值取舍。本轮能给的只是让它定义清楚、把保证写出来，不能替项目决定取舍。

## 四、建模边界

**宏步还是逐调用。** 模型按“决策步”转移：一次记录的动作及其反馈转移一次，成功后自动跟随的调用不转移。拟合、信念更新、规划三处一致。我没有改成逐调用，理由是本实验所有生成器的故障规律本身就按决策步定义（成功率按公开事件序列索引），按决策步是与生成器一致的写法，改了等于换实验机制。需要明确的边界是：

- 隐藏状态不变时两种写法完全相同。Gate 42A 的执行器是这种情形。
- 隐藏状态会变时两者不同（留在某状态的概率 0.8，一个带三次跟随调用的动作，逐调用是 $0.8^4\approx0.41$）。本 PR 没有把动态模型接到逐调用的执行器上，接之前必须重新定义并验证。代码和文档里的“每次调用之后转移”已改成“每个决策步之后转移”。

**标签表。** 原来默认从生成器对象汇总标签名。那是工具合同里的公开信息，不含隐藏状态或概率，但接口上确实是从生成器读的。修正版只从日志里读标签，不再碰生成器对象。验收报告查到的唯一差别（一个 30 条历史的前缀里少见一个信号名）在修正版里按日志实际出现的为准。

**性质判断：接口边界不清，不是信息泄漏。** 没有为此增加新的抽象层。

## 五、科研有效性：优势到底来自哪里

这是本轮最重要的部分，结论对上一份报告不利。修正版加了两个对照：只有一个状态的模型（跨节点共享统计，但没有隐藏状态），和“逐节点基线加上没试过的工具先于停止”（实验 041 已有的选项，c4 没用）。

**1. 小样本下完成率更高，不来自隐藏状态。**

| 格，N | 旧 ACV | ACV＋没试过的先试 | 一个状态的模型 | 修正版信念模型 |
| --- | --- | --- | --- | --- |
| M3，30 | 0.849 | 1.000 | 0.992 | 1.000 |
| M3，100 | 0.869 | 1.000 | 0.996 | 1.000 |
| M5，30 | 0.758 | 0.900 | 0.335 | 0.862 |
| M5，100 | 0.829 | 0.898 | 0.405 | 0.898 |
| B2R-mini，30 | 0.733 | 0.720 | 0.752 | 0.772 |

M3 和 M5 上，基线只要不在没有数据的节点停下，完成率就和信念模型一样，M5 上 30 条时还更高。c4 把这部分算作信念模型的优势，是因为当时的基线会停。只有 B2R-mini 上小样本的完成率优势还在（0.772 对 0.720–0.733）。我登记的判断 R5（M5 上信念模型完成率高出至少 3 个百分点）被否定。

**2. 剩下的是费用差别，它需要隐藏状态，但只在符合模型假设的格里出现。**

| 格，N | ACV＋没试过的先试 | 一个状态的模型 | 修正版，节点带 0.01 | 修正版，全局界 0.01 |
| --- | --- | --- | --- | --- |
| M5，100 | 0.898 / 3.719 | 0.405 / 3.810 | 0.898 / 3.529 | 0.899 / 3.531 |
| M5，3000 | 0.899 / 3.833 | 0.899 / 3.791 | 0.900 / 3.400 | 0.900 / 3.500 |
| M3，300 | 0.999 / 5.589 | 0.940 / 5.544 | 1.000 / 5.327 | 1.000 / 5.324 |
| S4b，3000 | 0.800 / 3.877 | 0.800 / 3.670 | 0.800 / 3.673 | 0.800 / 3.827 |
| B2R-mini，3000 | 0.775 / 4.347 | 0.774 / 4.286 | 0.775 / 4.360 | 0.775 / 4.391 |

- M5（互斥路径）：完成率相同时费用低 5%–11%，一个状态的模型做不到，换成全局界也还在（3.50 对 3.79–3.83）。这是唯一一处既需要隐藏状态、又不依赖带宽的优势。原因是互斥路径的完成率本来就相同，只有认出“哪条路被堵”才知道先试哪条便宜。
- M3：300 条时费用低约 5%，3000 条时差别不到 1%。
- S4b（共享故障）：与旧 ACV 容差 0.05 相比没有优势（3.673 对 3.670），在全局界下更差。上一份报告里“1000 条起明显更好”只对 1000 条成立，而且依赖节点带。
- B2R-mini（不符合模型假设）：没有优势，费用高 1.7%–2.4%。

**3. 逐项回答“优势来自哪里”。**

| 可能的来源 | 判断 |
| --- | --- |
| 隐藏状态共享统计 | 只解释 M5 上的费用差别，和 M3 上中等样本的费用差别 |
| 固定 5 个状态 | 只在小样本下有影响（BIC 选的状态少时 M5 上 30 条完成率 0.499 对 0.862）；1000 条起无差别 |
| 容差调优 | S4b 上的费用优势完全依赖它；M5 上部分依赖（3.40 对 3.50） |
| 生成器恰好符合模型假设 | 是。有优势的 M5、M3 都在模型类之内；唯一在模型类之外的格上没有优势 |
| 基线能力不足 | 是。小样本完成率的优势全部来自这里 |

**4. 负对照没有变。** 混杂日志下修正版 5.100，ACV 4.400；分布迁移下两者相同（4.4、4.8，最优 4.0）。预测性检查对这两种情况和结构失配都不报警。

| 类别 | 问题 | 处理 |
| --- | --- | --- |
| 实现缺陷 | 似然落后一步；结果里的负零；结果文件不记录环境；EM 初值依赖集合顺序（早先已修） | 已修，旧路径保留 |

| 研究假设本身 | “显式隐藏状态估计能改善恢复决策”只在生成器是小的有限状态模型、日志不混杂时成立，且收益限于费用 | 见下节建议 |

## 七、Go / No-Go 建议与剩余风险

**对方法线：No-Go。** 按任务给出的止损标准逐条对照：

- 只在生成器符合模型假设时有效：是。
- 在混杂或结构失配下明显更差：混杂下更差（5.1 对 4.4），结构失配下略差，迁移下相同。
- 优势依赖任意容差：共享故障格上完全依赖；互斥路径格上部分依赖。

三条都中。我不建议为信念模型本身投入真实 LLM 实验。

**还剩下的、范围明确且可以被否定的假设，只有两个，都不需要信念模型这套机制。**

1. “没有数据的地方不要停，先试没试过的工具。” 它在 M3、M5 上把完成率从 0.76–0.87 提到 0.90–1.00，代价是费用高几个百分点，在 B2R-mini 上没有帮助。这是一条基线规则，不是方法贡献，但它决定了以后任何方法该和什么比。
2. “几条路径因同一个隐藏原因而互斥时，一条路径的失败应当改变其余路径的尝试顺序。” CPU 上它在完成率相同的情况下省 5%–11% 的费用。它可以用很小的代价在真实 Agent 上被否定：只需要互斥路径的任务，比较“提示里给出跨路径的失败统计”与“只给逐路径统计”两种条件下的尝试顺序，不需要 EM 和规划器。是否值得做，取决于项目的任务里互斥路径占多大比重，这需要你们判断。

**对 PR：** 是否合并由独立验收决定。本次更新只补证据、修缺陷、加对照和更正记录。

**剩余风险。**

- 修正版仍用 c4 的那批历史，是修正与对照，不是独立的确认性检验；没有新的留出格。
- 两条规则的保证只在模型之内；模型错时（混杂下自估完成率仍是 1）保证没有意义。
- 跨 Python 版本的差别目前只观察到负零一种。修正版去掉了负零，但我不能保证在别的平台上所有数值逐位相同；差别若翻转了某个接近并列的决策，结果会真的不同。需要验收方在 3.10 上复算 d1 来确认。
- 一个状态的模型在样本多时全部被预测性检查否决并回退，所以大样本下它的数值就是回退用的 ACV，不是它自己的。
- 可识别性的两篇文献仍是凭记忆引用，没有核对原文，不应作为定理依据。
- 全部是 CPU 环境模型内的参照，没有任何 Agent 证据。
