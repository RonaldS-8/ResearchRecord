# 近邻对照：恢复时的备用路线自动发现

2026-11-16。用于判断 052 第四节“自动发现备用路线”方向是否存在缺口。只做文献核对，不新增实验，不改研究问题；立项需导师确认。

## 1. 要核对的候选缺口

工具失败后，自动生成一张“义务 → 备用路线 → 适用故障 → 安全性”表，替代 BTM 等工作里人工写的替代映射。我们认为已有工作缺三件事：

- **(a) 义务等价：** 哪些路线完成的是失败那一步的**同一项用户义务**，而不只是“输出能接上输入”或“经常一起用”。
- **(b) 按故障区分的有效性：** 每条路线在哪类故障下仍有效（例如共享后端故障会让备用路线一起失败），从合法历史估计。
- **(c) 副作用安全：** 写入是否幂等、能否查询是否已提交、能否补偿；特别是**写入可能已生效时切换到备用路线**是否安全。

## 4. 结论

1. **“自动建工具图”和“失败后改道”各自都很拥挤。** 建图有 GOAT、In-N-Out、HyperAgent、NaviAgent、ToolAtlas、SING；改道有 Self-Healing Router、KAIJU、NaviAgent。单说“自动发现路线”没有新意。
2. **(a) 义务等价：所有工作都是假定，没人估计或核验。** 备用关系来自人工图（Self-Healing Router、BTM）、Benchmark 聚类（ToolMaze）、或 LLM 临场提出（KAIJU）。In-N-Out 说明零样本 LLM 连“能否接上”都只有 47.7% 准确率，“是否完成同一义务”更难。
3. **(b) 按故障区分的有效性：没有工作做。** NaviAgent 最接近，但只按总体成功率加权。ToolMaze 的故障规则在同一备用组内排除了相关故障，共享后端这类情况在它的 Benchmark 里不会出现。
4. **(c) 副作用安全：重试同一动作已被占。** Verified Tool Calls、LIMBO、Atomix（未读）做了核实、幂等键或补偿。**写入可能已生效时改走备用路线**，没有工作讨论。050 正好是这个情况：去掉“至少重试一次”后 BTM 直接切换到备用写入，照样 10/10 重复发布。
5. **(a)(b)(c) 合在一起、在恢复时使用、按严格完成率和成本评估，目前看是空白。** 这是基于 15 篇的判断，上面列的未读论文读完前不能写成“首次”。

## 6. 风险

- **ToolMaze 的合同是我们自己扩写的，路线关系可能过于规整。** 需要在 In-N-Out 用的 AppWorld 或真实 MCP 工具说明上检验推导效果。
- **(b) 需要带故障标签的合法历史。** 051 只在 CPU 上验证了“估计故障机制”，真实轨迹上还没有。
- **(c) 与 Verified Tool Calls / LIMBO 的边界要说清：** 我们的贡献只能落在“切换路线时的安全性”，不能重复主张“先核实再重试”。
- 未读的 Atomix、RAC、Tool-Planner 可能覆盖部分 (a) 或 (c)。
