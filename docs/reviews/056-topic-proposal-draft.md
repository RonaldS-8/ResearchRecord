# 选题草案：工具故障后备用路线的自动发现与选择

2026-11-16。供与导师讨论选题。数字都来自已提交的实验记录（053、054、055），没有新实验。改 AGENTS.md 的研究目标需要导师确认。

## 一句话

工具出故障后，不依赖人工写的替代映射，从工具说明里自动找出能完成同一项任务的备用路线，再用历史估计每条路线在当前故障下的成功率和成本来选路。对照对象是 Bench2Robust 的 BTM。

## 1. 为什么做

- **BTM 的提升主要靠人工映射。** 论文自己的消融（表 5b）：无信念 23.2，只有统计 24.9，静态结构加均匀信念 33.7，完整 BTM 37.8。约七成提升来自人工写的“原工具 → 替代工具”映射和约束，统计部分只多约 4 个百分点。真实业务里没人会提前写好这张映射表。
- **Agent 失败主要在认不出备用路线。** 我们自己的检查点 M4（Gate45）：不给提示 0/5，告诉它“发布失败可改走准备 → 确认”后 5/5。ToolMaze 论文里，只加一句“子任务可以用不同工具组合完成”的提示，就能提升 1.5–20.8%。
- **近邻对照（报告 053，15 篇）：** 自动建工具图（GOAT、In-N-Out、HyperAgent 等）和失败后改道（Self-Healing Router、KAIJU、NaviAgent）各自都有人做，但所有工作都把“备用路线能否完成同一项任务”当作给定，没人去估计或核验；也没人按故障类型区分路线是否还有效。这两点合在一起、在恢复时使用，是本课题的切入点。

## 2. 已有证据：三个可行性检查

| 检查 | 问题 | 结果 | 结论 |
| --- | --- | --- | --- |
| A 环境 | ToolMaze 能否公平检验“自主发现备用路线” | 原生设定下，Agent 看到的工具恰好是两条有效路径的并集；规则“可见工具减去当前路线”在 C2、C3 的 400 次查询里全部找回备用路线。加入同领域干扰工具后（中位 92 个工具）才有难度 | 通过，但主设定必须加入干扰工具。原生设定泄漏答案这一点本身作为 Benchmark 审计发现写进论文 |
| B 自动发现 | 不读答案表、只看工具说明能找回多少 | 干扰设定、C3（多步对多步），开发集：规则“输入能接上”前 3 名找回 0.58；规则候选的上限（前 20）0.69 | 规则不够，有方法空间 |
| C 简单规则 | 简单规则是否已经够用 | 名称相似对多步路线为 0；集合差规则在干扰设定下为 0；人工映射按构造是全对 | 简单规则远未饱和 |

**两个已知局限：**
- 真值备用组每组只有两条路线，漏了一些合法路线（例如一步完成下单的 `checkout_best_recommendation`），所以分数偏低。
- 上述都是离线找路线的结果，还没有在真实 Agent 上验证。

## 3. 方法（两层）

1. **路线发现（只用工具说明，不用历史）**
   - 规则枚举能接上的候选链：按输入输出匹配，参数说明里点名了来源工具的也算能接上。
   - 本地 4B 模型判断候选是否完成同一部分任务并重排；同时测试让模型直接从工具目录里提出路线，用来补规则漏生成的部分。
   - 后续用工具插件试执行，过滤跑不通的候选。
2. **路线选择（ACV）**
   - 用合法历史估计每条候选路线在当前故障下的完成概率和成本，再决定重试、切换到哪条，或者停止。历史只在这一层使用。

## 4. 实验设计

- **环境：** ToolMaze C2、C3 任务，加入同领域干扰工具；另按服务抽取或随机抽取干扰工具，做稳健性检查。
- **故障类型：**
  - P1 暂态：重试就能成功，重试和切换的成本不同。
  - P2 持续：只能切换。
  - 共享后端故障（我们扩展）：备用路线和原路线一起坏。
  
  只用 P2 的话备用路线永远是好的，正确动作永远是切换，ACV 没有可选的东西，所以必须包含另外两类。
- **对照组：**
  - ReAct，不给提示；
  - ToolMaze 自带的“可换组合”提示；
  - 规则推出的路线表；
  - BTM 加人工映射，作为知情参照，用和我们一样多的历史拟合它的信念；
  - 我们的方法：自动路线表加 ACV。
- **指标：** 严格完成率；恢复成本，包括工具费、诊断费、输入输出 Token。各项分开报告，不合成一个分数。
- **主张，按非劣写：**
  - 不用人工映射，完成率与 BTM 的差距在登记的非劣界以内（例如 5 个百分点）。
  - 在暂态和持续故障混合、共享后端故障的场景下，ACV 的成本或完成率优于 BTM。
- **补充证据：** 实验 050 显示，“回执丢失但已提交”的场景里，BTM 两组都重复发布（C 世界 0/10），人工知情提示 10/10。作为“切换路线时还要考虑写入安全”的讨论，不作为主实验。

- 仍不够再换 API 模型。

## 6. 风险

- **工具说明太规整。** ToolMaze 的说明和备用组由同一流程生成，比真实 API 规整。后续需要在真实 MCP 工具说明或 AppWorld 上检验。
- **路线全对也不等于 Agent 能用好。** 路线表给全了，Agent 也可能执行不好；这需要真实 Agent 实验来回答。
- **BTM 没有开源代码。** 对比依赖我们按论文附录 B.1 的复现，论文里要说明复现差异。
- **文献还没读完。** 053 里还有 6 篇近邻没读（Atomix、RAC、Tool-Planner 等），读完之前不能说“首次”。
