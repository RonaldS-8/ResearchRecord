## 4. 六项质疑判定及原报告修订

1. **M4工具关系解释：部分支持、原因未唯一识别。** 多条明确排除alternate为非当前任务；工具说明非对称是待检验竞争解释，不能把所有失败说成注意缺失。
2. **统计信息只是传回正确路径：足以构成主要未排除解释。** 可确认关系/建议引导下的可执行续程；不能确认Beta/ACV数值独立有用。固定检查点、4条建议诱导成功训练使泄漏设计者路径知识的复现偏差必须前置说明；这不是从私有生成器泄漏，但也不是自主发现/跨任务估值证据。
3. **k1不能判HMM方法无用：接受修正。** 每格只有固定构造故障、极小且受建议选择的日志，且R4无恢复规划，数据不足以检验多状态必要性。也不能反向宣称固定外部故障使任何HMM数学上必选k1：隐状态可能拟合阶段/其他混合，BIC选择是本次拟合事实，不是这样的定理。
4. **重复及首区块异常：接受边界，运行原因仍U。** 完整哈希、顺序、不同进程见上，未证明冷启动因果。
5. **主读信息功能：接受增列候选，主动动机未证实。** 原实耗费与strict失败不改，补充执行性信息获取可能及明确凭据替换解释，不能以事后失败证明VOI为零。
6. **M4悬空archive引用：确认。** 冻结M4 validate描述提到backup or archive，但可用工具中没有read_archive_record；publish描述只提示与read_primary共享provider，prepare描述强调independent writer、one-publication limit。这些原文均可在M4冻结tools逐字检查。本轮没有证据证明悬空archive影响行为，记录为合同文案问题，不修冻结文件。M3 validate明确提archive与M4 publish未指prepare的非对称值得另行合同消融。
