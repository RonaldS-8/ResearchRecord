# 外部审查 · 历史经验注入的有效性与适用边界

2026-11-12，独立科研外审（Claude）。只读本地仓库 main `86a42e1` 的实验记录与代码；没有访问云端归档，没有运行模型或 CPU 实验。文中数字均引自原记录，标注出处；我自己的推断单独注明。Bench2Robust 论文报告的数字按用户 2026-11-11 的决定不作对照，只引用其方法结构。

## 结论

待审判断“过去的方法没有超过强简单规则，不代表历史经验无法被 Agent 有效利用”**基本成立，但应改写为三句分开的话**：

1. **历史经验本身有用。** Gate 18–23 里表现最好的强规则，大多就是用同一份历史拟合或在验证集上选出来的（三节点规则、完整历史费用阈值、最佳固定顺序）。过去的比较实际上是“代码读历史”对“LLM 在上下文里读历史”，不是“规则”对“历史”。
2. **LLM 在上下文里读历史，相对不给历史的 LLM 只有小而不稳定的收益。** 动作条件记忆在 Gate 19、23 相对无历史组降费 8.4%、7.5%；任务级 BTM 统计在 Gate 19 多完成 2 例，在 Gate 23 反而少完成 1 例、多花 6.7%。
3. **模型有没有“用统计做决策”，从未被直接测量。** 没有任何一轮报告建议采纳率。可观察到的差异大多来自参数绑定（Gate 18）、停不停（Gate 19、23）或控制器代为决策（混合组）。

在当前 A/B/E 中，BTM 的任务级统计几乎不含决策信息（第二节第 4 点），历史能起作用的合法形式只有按公开上下文或诊断信号分层的动作结果统计。这能否被 4B Agent 用上，可以用两次小实验直接回答（第四节）。

### 2. Agent 怎样使用这些经验（问题 2）

提示结构（均已对照代码）：

- **BTM 原始提示**（[gate18.py:35–44](../../extensions/action_conditioned_recovery/gate18.py)、:191–213）。指导语写“恢复信念高则再试，低且备用更强则切换”，另有“失败后至少先重试一次”和“穷尽后才上报”。后验的目标是训练策略下的**最终回合成功**，不是单个动作的成功。
- **共同规则 BTM 与记忆**（[gate19.py:39–50](../../extensions/action_conditioned_recovery/gate19.py)、:125–147、:151–180）。所有组共用系统提示，统计放在用户消息的 `history` 字段并注明统计目标；模型只调用 `select_recovery_action` 选一个动作名，参数由执行器从真实回执绑定。所以 Gate 19、23 的差异只来自决策与停止，不来自绑参。

可观察到的用法，按类型分：

| 用法 | 证据 | 强度 |
| --- | --- | --- |
| 依据统计选动作 | Gate 19 动态预约 1821：记忆按估值（B 3.00 < A 3.17）继续用 B，BTM 回切 A，实付 4.00 对 5.20（022:16）；但固定切换走同一路径，估值首选与默认动作重合。Gate 23 标准预约 2321：记忆先选 B、BTM 先选 C，少付 2.00（025:74）。Gate 19 记忆与 BTM 的首步分歧只有 1/20 | 个案一致，**采纳率从未统计** |
| 遵循静态指令 | 先重试条款使首步重试从 0/20 到 6/20（Gate 19）、0/16 到 7/16（Gate 23）；完整论文提示 4/16 | 部分遵循，约三到四成 |
| 改变执行或输出格式 | Gate 18 实参拒绝：ReAct 7、完整 BTM 2、记忆 4、去先重试 6、均匀先验 5，均为保留期限 `" 90d "` 未去空格（021:7） | Gate 18 的组间差异主要在这里 |
| 改变停不停 | Gate 19 无历史过早停止 3 次、BTM 1 次；Gate 23 BTM 与记忆在 A 仍合法时停止，正确停止 0/4（025:48） | 任务级“能救回”的信号可能减少过早停止，但不改首动作 |
| 控制器代为决策 | 混合组与确定性解析在 Gate 19 的 28 组、Gate 23 的 16 例逐步同选（021:82、025:74） | LLM 只做抽取，收益属于决策规则 |

## 二、解释

### 3. 为什么简单规则曾经更强（问题 3）

| 解释 | 证据 | 判断 |
| --- | --- | --- |
| 备用可靠、续程相同 | Gate 19 五格中四格备用每节点必成，固定切换与记忆在这 16 个起点只走 B；此时只剩一个阈值 $p_A>c_A/c_B=0.60$（[022](../experiments/022-recovery-mechanism-audit.md):47） | 成立，是首要原因 |
| 回执信息充分 | 结构化回执让确定性解析与混合组逐步同选；“结构化合同已将许多语义判断变成字段读取”（[026](../experiments/026-agent-recovery-benchmark-audit.md):56） | 成立 |
| 规则利用了相同经验 | 三节点规则、确定性解析用同源动作条件校准（020:9）；固定信念、最近反馈、完整历史三种阈值规则用同一份训练拟合运行（023:37）；固定顺序在验证集上选 | 成立；“规则胜过历史”的说法不成立 |
| 历史估计不准 | 保持率拟合 9/10 而生成律 1/2，导致排序反转（022:43）；局部缺样本导致 43 处误排（023:77）、8 处与迁移 30 处（024:81）；A 分支费用平均低估 1.19（022:26） | 成立，但多在 CPU 代理上；对 LLM 组实得结果的贡献未分离 |
| 提示未被采纳 | 静态条款遵循三到四成；统计的采纳未测 | 静态部分成立，统计部分未知 |
| 参数绑定或执行链失败 | Gate 18 共 24 次首步实参拒绝；Gate 19 起执行器代绑后消失；A/B/E 中重新出现（038 的 S03 工具调用写成文本、P05 漏句点） | Gate 18 成立；Gate 19–23 已排除；当前环境中重新相关 |
| 停止错误 | 见问题 2 | 成立，是 LLM 组相对规则的主要完成损失 |
| 采样噪声 | Gate 19、23 温度 1（025:10），Gate 18 沿用项目采样配置（020:25），每格单样本；Gate 19 的 20 个主起点只有 4 组基础事件键（022:7） | 未知，无法排除 |

### 4. 能否迁移到 A/B/E（问题 4）

环境事实（[gate34a.py:72–77](../../extensions/toolmaze_recovery/gate34a.py)、[037](../experiments/037-decision-tradeoff-lineage-design.md) Gate 34-A 节）：所有回合首错都是同一句主读超时；隐藏状态只有快暂态（第二次主读成功）与持续；备用总能完成；预算 7 足够。B 的 X1/X2 以无语义标签写在用户消息里（[gate34b.py:68](../../extensions/toolmaze_recovery/gate34b.py)）。

- **BTM 的动态统计在 A/B/E 中几乎不含信息。** 它的键（主读工具，超时）在所有格、所有上下文下相同；只要训练续程能完成（备用可靠时总能），恢复后验与切换后验都趋近 $(n+1)/(n+2)\approx1$。所以 BTM 在 A、B-X1、B-X2、E 收到的数字基本一样，行为差异只能来自静态文字。再加上指导语把“恢复信念高”读作“该再试”、外加先重试条款，**我预测完整 BTM 在 A/B/E 中近似固定先重试**：A 3.2（优于 ReAct 的 4.0）、B 平均 4.0（X2 为 4.6，劣于切换）、E 4.0。若观察到 BTM 在 A 胜过 ReAct，那是静态先重试偏好碰巧与 A 的最优动作一致，不是统计起作用。这正是 Gate 9 反例在本夹具中的实例：高恢复率来自切换救回，却被读成重试证据。
- **能携带信息的合法历史只有分层的动作结果。** 首错后立即重试的成败只由隐藏状态决定，所以按公开上下文 X 统计的重试成功计数就是 $P(T\mid X)$ 的合法估计（A 约 0.9、X1 约 0.8、X2 约 0.2、E 约 0.5）；按诊断信号统计的重试成功计数就是信号可靠度的合法估计，不需要也不能写出 γ。两者都必须来自分配了重试或诊断的训练回合（037 §6），以“k/n 次”的计数加样本数呈现，不能写生成概率。按 037 §6 的量级，每个分层约需 28–43 个独立回合才能把区间半宽压到 0.15。
- **自然轨迹给不出这些计数。** 038 中原生 ReAct 从未重试主读（038:107），所以用该模型的自然轨迹建历史池，与重试相关的分层支持数为 0。分配首动作是必要条件，不是可选项。
- **能迁移的旧经验：** 静态指令只被部分遵循；LLM 组容易过早停止；动作条件记忆能减少冗余调用。**不能直接迁移的：** Gate 19–23 由执行器绑参、回执结构化，而 A/B/E 由模型自己绑参、首错不含状态信息。前者让执行失败重新进入比较，后者正是本题需要的条件。
- **诊断：** BTM 没有诊断相关的键，给不出“买不买”的依据；038 的 S08 收到暂态信号仍切备用，说明原生模型目前不读信号。

### 5. 与动作条件价值的差异（问题 5）

| 收益来源 | 需要什么 | 在 A/B/E 中 |
| --- | --- | --- |
| 静态知识：备用映射、核验约束 | 经验本身即可 | 有，但原生 ReAct 在 8 个自然回合都走通了备用链，余量小 |
| “能救回”的鼓励，减少过早停止 | 任务级统计即可 | Gate 19 有；A/B/E 中原生 ReAct 未见过早停止 |
| 重试倾向 | 静态条款 | A 有利、X2 不利，平均等于固定先重试 |
| 按上下文选首动作 | 同起点动作条件统计（分配的重试） | B 的核心；BTM 键不含 X 且后验约为 1，提供不了 |
| 续程完成率，含路径特有的执行失败 | 真实 Agent 续程下的分支统计，即 $Q^{\pi_{\mathrm{Agent}}}$ | P05 的失败发生在备用链的写入；任务级统计把它混进“恢复率” |
| 诊断买不买、听不听信号 | 信号条件的动作统计加净价值计算 | E 格；BTM 无对应项 |
| 信念更新 | 多步反馈 | 一次重试失败即揭示持续状态，A/B/E 中 M2 没有空间（只有 F 格有） |

所以在 A/B/E 中，“经验本身”能带来的只有静态知识和停止行为；B 的上下文选择和 E 的诊断利用必须依靠同起点的动作条件统计；信念更新在这三格中无法检验。

## 三、局限

**证据本身。** Gate 18–23 样本小、基础事件复用（Gate 19 的 20 个起点来自 4 组基础键，Gate 23 的 16 个条件来自 4 个基础事件，025:78），每格单样本；Gate 21、22 是确定性代理，没有 LLM；这些合同与 A/B/E 不同。BTM 未开源，各轮使用的都是我们按论文复现的提示。

**对现有设计的意见。**

1. **A/B/E 中 BTM 的比较实际上是“静态文字对 ReAct”。** 建议在预登记中写明上面的行为预测，避免把 A 格里 BTM 的优势读成统计的作用。
2. **037 §5 计划的“等量自然轨迹池”敏感性分析，对这个模型基本无信息**：自然轨迹里没有重试。
3. **温度 0 下，独立单位是不同的提示，不是种子。** 同一格同一上下文的首个请求逐字相同，首动作只是一次贪心解码。038 的 8 个自然 ReAct 回合因此只构成 3 个首决策情形（A、B-X2、E 且 $d=1/10$）；X1 下的自然行为从未观察过。039 提议的 12 回合探针中，自然组 4 个种子只是 1 个情形；γ 不进提示，所以强制诊断后的提示在 γ=0.9 与 γ=0.5 两组之间相同，行为层面只有“暂态信号后”“持续信号后”两次决策，种子只是在重复执行链。建议按不同提示计数，并通过独立历史池或登记的采样温度引入变化。（038 已确认配对首请求相同；跨种子相同是我按 [gate34b.py:61–78](../../extensions/toolmaze_recovery/gate34b.py) 的提示组装推断的，未在归档中核对。）
4. **建议采纳率应列为建议侧实验的主要观测**，Gate 18–23 都缺这一项。
5. **结论的措辞**应区分“历史有用”“LLM 能在上下文里用上历史”“超过强规则”，三者的证据要求不同。

**本审查。** 未访问云端归档，没有复算任何数字；Gate 19、23 中模型是否采纳建议，需要云端只读统计后才能回答（见建议 0）。

## 四、建议

**0. 先做零模型成本的归档统计（不是实验）。** 在 `results/021-gate19-controlled-02/` 与 `results/025-gate23-agent-01/` 上只读计算：记忆组每个检查点所选动作是否等于其建议的字典序首选；同一检查点无历史组选了什么；只看“建议首选与无历史选择不同”的检查点时的采纳率。Gate 19 的检查点已保存 `values`（gate19.py `replay`），Gate 23 的请求里保存了建议。混合组不计入。这能直接回答问题 2 的“用统计做决策”部分。

以下两个候选都只复用已验收的 A/B/E 夹具、038 的原生 Agent 与原始提示，不改合同、评分或报价，需另行预登记和批准。历史可以完全在 CPU 上采集：重试与诊断的结果只由环境决定，用登记的分配规则作行为策略即可，不需要模型请求。代价是它只提供动作结果统计，不提供真实 Agent 续程下的完成率。

### 候选一 · B 格：按上下文分层的动作结果历史能否被用上

- **假设。** 给出按 X 分层的“首错后立即重试的实际成败计数”，原生 Agent 在 X1 重试、在 X2 切换。
- **最强竞争解释。** 任何历史块都会普遍提高重试（提示推动），或模型对 X1/X2 标签本身有偏好。
- **合法历史。** 训练种子上按登记概率分配首动作，按 X 记录重试的成败计数与 $n$，以及两条路径按当前报价的费用；不写 $P(T\mid X)$、Z 或生成律。用 3 个互不重叠的训练池生成 3 份历史，作为真实的估计差异。
- **组。** 无历史 ReAct；BTM 论文格式（同一历史池算出的任务级后验、映射、约束及先重试条款）；分层计数（同一位置、同一映射与核验约束，不含先重试条款）；不分层的汇总计数（控制提示推动）。X1、X2 各一，温度沿用 038 的 0。约 20 个首决策情形，每个情形跑一个完整回合。
- **主要观测。** 按 X 的首动作；建议采纳；严格完成与业务义务；后缀费用；绑参与协议失败分列。
- **为什么简单规则解释不了。** 固定顺序与 BTM 任务级统计在 X1、X2 上相同，产生不了随 X 变化的首动作。按 X 的上下文规则可以，但它要从同一份分层历史里选出来。理论上限与验证过的上下文规则相同（3.7），所以本实验检验的是 Agent 能否用上历史，不是能否胜过规则。
- **止损。** 只有分层组在至少 2 个历史池中出现“X1 重试、X2 切换”，而汇总组没有出现，才算支持假设。否则判定这个 4B Agent 不能从上下文利用动作条件历史，建议侧方法线停止，只保留由控制器落实的方式；那条路还要面对强制调用下的执行失败（038 的两次失败都发生在强制调用的回合）。若出现分化但完成率因绑参下降，按完成率优先报告，不称收益。

### 候选二 · E 格：信号条件历史能否让 Agent 听诊断

这是 039 提议探针的补充版：加入历史组，并按第三节第 3 点计数。

- **假设。** 原生 Agent 不按二元信号改动作，是因为它不知道信号有多可靠；给出“收到某信号后重试的实际成败计数”后，在 γ=0.9 训练池的历史下会听信号，在 γ=0.5 的历史下不会分化。
- **最强竞争解释。** 信号的字面（transient_hint）本身推动重试，或多一轮交互改变了行为。无历史组与 γ=0.5 历史组控制前者；各组都强制首动作为诊断，交互轮数相同，控制后者。
- **合法历史。** 训练种子上分配“诊断后重试”，按信号记录重试成败计数与 $n$；γ 不出现。3 个独立历史池。
- **组。** 首动作强制诊断（复用 038 的首动作强制），之后原生续程：无历史、γ=0.9 池的信号条件计数、γ=0.5 池的信号条件计数。两种信号各取一个，按公开信号预选环境种子、不看 Z（先例见实验 025），诊断费 $d=1/10$。
- **主要观测。** 按信号区分的下一动作；建议采纳；严格完成与业务义务；含诊断费的后缀费用；失败分类。
- **为什么简单规则解释不了，以及它不能证明什么。** 冻结的 simple_feedback 规则写死了“持续信号切备用、暂态信号重试一次”，在 γ≥0.8 时已达公开最优；γ=0.5 时跟随信号在期望上与不跟随持平。所以在已登记的 E 组合里，本实验不能显示优于规则。它检验的是 Agent 能否从历史判断信号的可靠度并据此行动，这是 M1 能在建议侧落实的前提。
- **止损。** 只有在 γ=0.9 历史下、至少 2 个历史池中两种信号后的动作不同，而 γ=0.5 历史下不分化，才算支持假设。否则停止“在上下文里给诊断经验”的路线，M1 的购买与跟随决策只能由控制器执行。

两个候选若都得到负结果，合起来的结论是：在这类故障上，4B Agent 不能在上下文中把历史统计转化为动作，历史的价值只能通过规则或控制器兑现。这时方法的贡献应定位在“从有偏历史中估计动作条件价值并交给控制器”，而不是“把历史写进提示”。
