# Agent 效率方向：在已有方法上改进的候选（调研）

2026-11-14，分支 `efficiency-tailoring`。用户确定的思路：硕士论文以在公认强方法上做可测量的改进为主，不追求问题本身前所未有。这与 AGENTS.md 科研原则 1 一致（“允许在已有工作上改进方法、效果或数学解释”）；公平比较、预登记和保留负结果等规则不变。

本文只是调研，没有新代码，也没有运行实验。文献多数核对到摘要或代码仓库主页，标注处读了正文；检索不保证穷尽。

## 选基座的标准

1. 公开发表、有代码或我们已有复现，有标准 Benchmark 可比。
2. 改动只有一个明确的“旋钮”，改进可用同一口径测量。
3. 一张 RTX 4090、4B 模型做得动，优先只需推理的方案。
4. 能复用现有资产：ToolMaze 恢复夹具、Gate45 的 BTM 实现、费用账本、严格验收、cp01 的 38 个全流程单元格。

## 1. 首选：省成本的 BTM

**基座自己暴露了缺口。** Bench2Robust 正文附录表 14（Qwen3-4B，402 个留出任务，单次运行，seed 42）：

| 配置 | 无故障 | 故障且无备用 | 故障且有备用 |
| :--- | :--- | :--- | :--- |
| Base | 88K Token / 11.9 步 | 70K / 10.3 | 67K / 9.9 |
| Base + BTM | 103K / 12.2 | 110K / 12.8 | 123K / 12.5 |

BTM 换来稳健性，代价是 Token 增加 17%、57%、84%。原文承认恢复上下文“增加推理成本”，但没有给出 BTM 段落的长度，也没说明是每轮注入还是只在故障后注入。

**我们自己的数据也能看到同样的开销。** Gate45 首个请求的 Token 数（M3/M4）：R0 原生 ReAct 为 1551/1911，R2 完整 BTM 为 2159/2456，即每个请求多约 550–600 Token（+29% 到 +39%），而且后续每个请求都会重复携带。

**旋钮（一次只改一个）：**

- **门控：** 只在观察到工具错误之后才注入 BTM。
- **裁剪：** 只注入与当前失败工具相关的统计行和切换关系，去掉无关工具。
- **组合：** 门控加裁剪。

**故事线：** 稳健性与完整 BTM 持平，Token 与时延显著下降。这属于典型的“在已有方法上改进”。

**竞争解释和风险：**

- Gate45 的解释候选是：BTM 起作用靠的是“具体工具关系”的提示。裁剪若保留这部分，可能无损；若门控让模型在故障前看不到恢复约束，可能影响第一次故障时的选择。这是需要测的，不是预设结论。
- “只在出错后给提示”本身已是常见工程做法（2606.25819 等），新颖度来自在 BTM 上的系统测量与改进，不来自门控这个想法本身，论文里要如实写明。

**实验落点：**

- Gate45 的 M3/M4 是故障后的检查点，门控在那里与完整注入相同，测不出差别。必须用**有无故障全流程**的任务：cp01 已有的 38 个单元格正好覆盖 clean 与各类故障，可以直接复用。
- 外部 Benchmark 优先 BFCL 多轮：200 个任务，无需用户模拟器，官方包支持本地 vLLM。但 Bench2Robust 的故障注入框架尚未开源，在 BFCL 上注入故障要自己实现，并说明与原文不同。τ²-bench 需要用户模拟器，原文用 GPT-4o，放在第二优先。
- 对照组：原生 ReAct、完整 BTM、门控 BTM、裁剪 BTM、门控加裁剪；外加“只在故障后给一句通用提醒”的简单规则，用来区分 BTM 内容与提醒本身。
- 指标分项报告，与 AGENTS.md 一致：严格完成、Token（输入/输出）、请求数、时延、工具与诊断费；不合成单一分数。可另报成本效率指标 cost-of-pass（Efficient Agents，2508.02694 使用）作为辅助。

## 2. 备选：故障感知的推理强度

- **基座：** ARES 用一个 1.7B 路由器逐步选推理强度（低/中/高）。代码以 MIT 协议公开，含评测、监督微调与强化学习流程。据二手摘要，在 TAU-Bench 上推理 Token 减少约一半，结果未与原文表格核对。
- **旋钮：** 故障前后的推理需求不同。最小实验是免训练规则：平时低强度，只在故障检查点切到高强度。
- **障碍：** Qwen3-4B-Thinking-2507 没有强度档位，只能换 Qwen3-4B 混合模式（思考开/关两档）或 gpt-oss-20b，基线要重跑；原文监督微调用 8 卡。

## 3. 备选：按成本挑轨迹微调

- **基座：** 只保留成功轨迹中最短或最省的，再做微调，已有多篇工作支撑（SlimSearcher、HyperEyes）。
- **旋钮：** 用我们精确的费用账本挑选，包括诊断费和故障后的恢复费，而不只按轮数挑。
- **障碍：** 需要大量采样轨迹；挑选偏短会让工具调用萎缩，需要混入较长的成功轨迹；工具调用格式可能被训坏。

## 建议的第一步

先做候选 1 的最小验证，只用推理：

1. 在 cp01 的 38 格上测完整 BTM 的 Token 开销，确认 Bench2Robust 报告的增量在我们的夹具上是否复现。
2. 若开销显著（例如 ≥15%），再比较门控与裁剪两种改法。

步骤 1 本身就是论文需要的基线复现。这一步需要 GPU，须另行预登记并经用户批准；本文不自动推进。

BTM 已在 Gate45 实现，第 1 步主要是把它接到 cp01 的全流程单元格上。
