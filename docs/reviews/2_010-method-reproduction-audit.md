# 2_010 · 历史瓶颈复核与成熟方法复现

2026-11-18，基于 `research/route-recovery@c0e582d`。旧 M4 确实存在恢复瓶颈。其关键是识别同一次发布的备用协议，在仅余三次调用的情况下选择正确首步。2_009 大多数任务能为通用归档更换数据来源。两个实验的行为差异与任务结构相符。

## 续跑后的验收结论

在一个已见 M4 故障前缀上，原生 Agent 停止，迁移 In-N-Out 后 Agent 合法完成备用发布并读回。确定性同名字段规则产生了逐字相同的提示，也严格通过。这个结果支持自动获得的依赖知识可以在本例替代人工指路，尚未识别模型判边相对强规则的增益。

### 原作者公开链路

固定 NESTful 前八任务、20 个目标参数。原版 MiniLM 排名，Qwen3-4B 替代作者选择模型。独立 CPU 重放逐条验证无图组全部 20 个请求的消息一致，空正文按弃选计入分母。原判边器以本地模型得 5/12。检索读取作者发布的自动图，两项实验之间没有将这 12 个预测用于重建整图。

**研究判断。** 旧短板限于同一发布义务、紧预算和备用协议识别；2_009 的取数替换和通用归档通常更容易。2_009 的候选质量、绑定器和表示型误拒各有实证。本轮证明同一已见点上自动知识能传递给 Agent 并完成执行，强规则已能提供全部观察到的收益。优先保留成熟基线；后续如获批准，预先选取合同能支持依赖推断但字段名存在歧义的独立任务族，同时保留简单任务，比较强规则和自动图的完整恢复与成本。当前无证据支持新增路径记忆或微调。

## 2_009 给出的证据

2_009 用共同策展的 28 工具池及公开 MCP 输出字段，只阻断每类任务的指定取数入口，并保留共同通用归档。模型与 045 的本地运行使用同名 4B 系列，Harness、工具卡、错误注入、预算和任务框架均不同。2_009 通常为读取加一次复合归档，M4 是同一非幂等写义务的备用三阶段协议。005 和 011 四组都从未受扰动的接口取数并通过，002 四组都尝试可用路线。原生整体路径尝试 3/4，严格局部完成 2/4。

- **生成和采用。** `gate_2_009.candidates` 用字段匹配束搜索和词元余弦排序，提示仅有至多五条工具名序列。026 的首条包含正确来源 Visual Crossing，但顺接两个归档动作，违反一次归档的义务。其余四条混入航班工具或重复归档。独立覆盖检查只验证起点输出字段与唯一末端归档，对合法实参的证明仍不足。两个提示组均选中该天气来源，自行改接一次通用归档。路径提示的两条 +25 点简单效应都来自这一任务，严格完成的平均增量为零。D 在全排序上搜索并于写前验证，4/4 共 21 次调用，不能据此推断前五链可执行或给模型的提示足够。
- **绑定与表示。** `audit_2_009.grade` 对实际保存载荷执行 JSON 解码，再以固定别名比较来源。002-R00 的有标签纯文本包含真实账本引用、类型、28785 和 USD，故有明确表示门槛。R10/R11 也使用纯文本，但把主体 `user_01` 写为账户标识，仍有账户和主体含义的歧义。026-R11 的 London、12、Rain、normal 均能在读回执中核对，`conditions` 未收录于冻结别名。保持原分。026-R00 实际缺提醒等级，R01 未调用任何工具，属于实质问题。
- **执行。** 发起归档的 15 个回合都报告模拟回执。天气两个提示组实际完成取数与保存，未观察到合法绑定后被执行器拒绝的同类故障。无公开读回归档工具，外部持久性与送达未知。旧 M4 的 STOP 与重试耗尽有独立的工具行为证据，跟归档表达差异无关。

### 逐条执行冻结前五

用原 D 绑定器在独立重置上下文中执行每条候选，原评分照用。静态覆盖判据命中 8/20，其中账户 1/5、设备 2/5、航班 5/5、天气 0/5。在该绑定器和预算下严格通过 0/20。所有 20 条均在取得最终业务回执前结束。账户和航班的若干链能执行读，却不能把实际数据绑定到专用归档合同。天气排名第一的链调用正确来源后，在第一个非末尾写处被规则拒绝。前五候选的静态覆盖对可执行性偏乐观，同时确定性绑定器的限制意味着 0/20 不能证明其他合法绑定一概无解。冻结 D 曾跨路线重用读取缓存和探查全表，与固定强制前五是两个条件。具体路线、调用与分数见[派生审计](../evidence/2_010/historical-audit.json)，实际调用事件在云端 `2_010-candidate-replay-01/cases.jsonl`。2_009 原 78 个文件的 SHA-256 已重新核对一致。历史请求索引含 78 个按回合归档的日志，记录的是模型提议，执行边界仍以原结果为准。

### 第 02 批结束时的 M4 准备状态

已写参数级迁移适配，用历史检查点和评分器通过了 CPU 接线烟雾测试。固定假边标签时，脚本从公开合同抽出两条字段依赖，并在重置副本执行准备、确认和实际读回。也验证了全负标签足以阻止产生路线以及重置隔离。CPU 结果只证明接线与环境可行。公开自动图检索尚未运行，M4 启动门槛未满足，真实 Agent 对照为 0 回合。该检查点的规则臂用确定性同名字段和同一提示，能要求图方法与强规则比较。若两者给同一路线，即使均救回，也只支持自动结构提示可用；成熟方法的独立增量仍未知。

先补齐公开自动图选择，再用登记的五组在原 M4 做一次探索。用原生失败和自动臂的合法三步、严格通过构成最小恢复证据。M4 只有一个已见检查点，在进入独立任务阶段前，优先完成基线和逐实参审计。当前证据不足以开始改进论文方法。接续、预算与暂停状态见[研究交接](../HANDOFF.md)。
