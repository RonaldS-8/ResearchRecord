## 预登记

- **问题与假设。** 两类不同语义的任务可复用同一原生 Agent 协议、状态与评分框架，在相同公开首错后通过重试或切换完成不同的后续义务。合法服务查询可提供有限的恢复证据。竞争解释为评分仅识别参考顺序、复合成功文本掩盖写入、诊断泄露后续结果、提示预设恢复路径或 Agent 跳过故障。
- **开发样例。** `case-handoff` 归档工单摘要并发送可定位归档的通知。 `case-archive` 在同一合同下只归档另一工单，通知属于额外副作用。 `stock-reservation` 读取库存，预留指定数量，再核实该笔预留处于有效状态。每族有两个不同回执形状的合法读入口。三项永久标记为开发样例。
- **故障配对。** 每个任务有正常、首个主入口暂态、主入口持续、共享依赖关联故障和双端证实阻断。相关故障前两次合计目标读取失败，诊断不推进尝试次数。暂态和持续使用相同首错，连接状态可相同，后续重试不同。诊断有可观察共享异常、正常但对持续性无判别力和诊断接口失败三种可见情况。
- **CPU 验收。** 两条正常路径、暂态重试、持续切换、关联故障及阻断的见证使用预设调用序列。错对象、错参数、伪造／跨会话回执、缺后续义务、重复写入、错误终止、非法调用均需拒绝。验证费用、实际状态、会话隔离、SDK 可见字段与未发生动作不可观测。失败保留。脚本见证不作为 Agent 或方法效果。
- **方法对照接口。** 原生 ReAct、共同无历史、BTM、原完整 BTM 提示、Action-Conditioned Memory、LLM 加动作选择器及既有强规则共用环境、价格、公开工具与评分。干预组只控制恢复首工具及后续恢复决策点，模型仍负责实参及续程。Gate 26 历史不迁入，当前无合规训练历史，动作估值为空并标记零支持。
- **真实接口验收。** CPU 全部通过后，用原生 Qwen3-4B-Thinking-2507，温度 0，种子 2701，最多 12 次 SDK 请求／回合、每次 6144 输出 Token、执行预算 16。固定两回合 `case-handoff/persistent` 与 `stock-reservation/transient`。从自然语言请求启动，首工具由模型选。至少一个回合须有实际首错、成功恢复读取和严格终态，直接绕开故障只计普通执行。原始请求、响应、计费、版本、时延、完整轨迹和失败在云端归档。本轮不做模型策略比较。

## 实现和运行

扩展位于 `extensions/toolmaze_recovery/`。三个开发样例及公开工具合同在 `tasks.py`，执行、模拟状态和独立评分在 `environment.py`，原生 Agent 协议接入与原始 SDK 归档在 `run.py`。工具使用原生定义格式和 `ToolExecutor`，账本复用 Gate 25。写入与真实调用对照，回执引用由会话签发，跨会话引用无效。工具费和诊断费分别记账，二者暂均为每次已公布接口调用 1 工程单位，失败调用照计。模型 Token 和时延分报。

工单家族消费实时记录或当前版本的授权归档。工单交接要求准确的内部笔记和送达正确收件人的笔记链接，单纯归档任务禁止通知。库存家族可消费库存视图或授权盘点，用实际凭据预留指定 SKU 和数量，再查询这笔预留是否有效。严格评分看笔记、通知和预留状态的内容及次数，核对实得回执、读取来源和库存余量。

显式诊断接口 `read_service_status` 只读当前共享连接状态。它能看到模拟共享故障的影响，无法区分共享连接正常时的端点暂态与持续故障，也可能自身超时。关联故障按有效读取次数推进，属于可重复的工程夹具，尚无真实时长或服务相关性的外部校准。当前读／准备层以外没有注入故障。

仅在 LabServer 运行。先切到含 Gate 27 提交的独立工作树。MVP 自身无需下载原生 ToolMaze 数据，Gate 25/26 回归需链接已有数据目录。

"$agent_root/.venv/bin/python" -B -m unittest discover -s tests -p 'test_no_leakage.py' -v

真实冒烟使用 `scripts/serve_gate5_vllm.sh` 的现有云端服务配置。以下命令展示单回合入口，父目录需已创建，回合输出目录需为新目录。运行前登记授权范围和归档路径。
