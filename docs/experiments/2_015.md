# 2_015 · 剩余义务驱动的真实 Agent 恢复

已见开发，基准 88415ef。固定会议开始/结束、原/推荐商品和 Gate050 的 C/T/P 共七例，每组三组一次。会议及商品沿用合法前缀，仅为绑定诊断；发布有真实模拟超时。直接 Agent 与方法使用同一 Qwen3-4B-Thinking-2507、本地服务、温度零、种子 201501；规则是无模型的强业务对照。所有组使用相同用户请求、公开历史、候选和工具，绑定场景只提供续程工具。前两族共享 2_013 的已生成 In-N-Out 强/弱候选，发布合同无类型输出 Schema，使用公共工具菜单和原生合同，不能将其计为新自动构图成功。策略只收公共视图。

方法在每次决策中显式产生剩余义务、当前状态判断及单步动作；确定性执行层核对来源引用、拒绝在自报提交状态未知时的写入，执行实际查询后用新增回执重新决策。直接组使用原生函数调用；规则按对象角色和公开回执运行。每回合至多 7 次模型决策、5 次后续工具调用，规则同等上限。每请求 4096 输出 Token、120 秒。总模型上限 98 请求、GPU 服务 60 分钟，无外部 API。单例失败保留，不调提示补测。输出保存实际参数、回执、状态/读回、请求原文、Token、时延。绑定场景只报回执值，持久写入未知；发布沿用冻结评分。按任务逐对分析，不合并为泛化率。若方法未超过规则或直接组，如实报告。CPU 先测配对前缀隔离、引用解析、未知提交约束和实际规则执行。
