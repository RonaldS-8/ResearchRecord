# 001：C2 × P1/P2 可观测性审计

状态：用户已批准审计方向；先登记计划，不运行策略比较。

## 问题与判据

- 不确定性：同一 C2 任务的 P1/P2 在首次故障时，策略已有观测是否足以识别真实故障状态？
- 假设：现有观测不足以直接区分状态，诊断可能带来额外决策信息；本审计不验证诊断收益。
- 竞争解释：任务、提示、工具描述或错误已暴露状态；一次重试即可提供足够信息。
- 可证伪标准：发现可从合法观测直接识别状态的可靠规则，即报告相关样本及覆盖范围，暂停后续比较并评估 Benchmark 适用性。观测相同仅支持该检查点不可区分，不证明诊断有价值。

## 最小执行范围

1. 只读追踪现有 Agent 请求构造、工具结果传递及 C2 扰动激活逻辑，区分环境内部字段、日志元数据与实际模型输入。
2. 云端枚举 C2 P1/P2 成对任务，报告缺对和差异；复用现有加载与接口，不修改数据、模拟器、扰动引擎或评测代码，不新增依赖。
3. 对相同路径和相同工具调用前缀，记录实际任务、系统提示、工具定义、首次故障响应及此前历史，比较完整可见输入；不同前缀不得直接视为成对证据。参考 execution_trace 仅用于审计定位，不能冒充实际模型轨迹。
4. 检查 P 标签、perturbation profile、真实持续性、ground-truth 路径是否流入策略。保留正常错误信息。审计者读取真值与策略获得真值必须明确区分。
5. 报告首次故障能否区分状态，以及重试可能提供的信息；不将故障检测准确率当作诊断决策价值。
