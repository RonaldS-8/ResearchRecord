# 实验 051 · 从有限历史估计场景的恢复方法能拿到多少余量（CPU）

2026-11-15 登记，运行前提交。探索性，CPU-only；模型与网格沿用实验 048（`extensions/toolmaze_recovery/completion_headroom.py`，GRID2）。

## 1. 问题

048 第三轮显示：只用公开信息、在一部分场景选好后冻结的规则表，换到隐藏参数不同的场景后，与公共最优（按真实参数求解）差距明显（迁移合并 20.8% 的格 ≥10 个百分点）。但公共最优知道真实参数，是上界。本实验回答：**一个只看该场景少量合法历史、先估计场景再规划的方法，能拿到这个余量的多少？** 以及这部分收益来自“用了本场景的历史”还是来自“按中途结果自适应规划”。

定位（与 BTM 的关系）：BTM 同样不解决“认出备用路线”，备用映射由人工给出。本实验沿用这一前提：所有组都知道全部合法动作（重写、切换到备用、回读），比较的只是**如何用历史与反馈选动作**。BTM 本身是给 LLM 的提示，CPU 上不构造“BTM 代理”（AGENTS.md：只用工具-错误计数的代理不能称为完整 BTM），与 BTM 的比较留给真实 Agent。

## 2. 历史与行为策略

- 每个测试场景（GRID2 的一格）有 N 条历史回合，由行为策略 B 产生：首次模糊失败后，首动作在 {重写, 切换, 回读} 中均匀随机；之后按固定顺序“回读、重写、切换”循环，放不进预算的跳过；收到回执或回读 found 即结束并宣告完成，预算用尽则停止。
- 每条历史只记录合法可见内容：首次失败细节标签、动作序列、每步观测（回执 / 失败 / found / missing / 回读报错）以及回合结束后的严格成功标记（与 BTM 用的回合结局同类）。不记录隐藏状态。
- N ∈ {10, 50, 200}；每格每个 N 用 3 个独立历史种子（种子由格序号、重复序号、N 决定）。

## 3. 比较组（共享同一份历史、同一组动作和价格）

| 组 | 用什么选动作 | 类别 |
| --- | --- | --- |
| FR 冻结规则 | 048 第三轮：在验证场景选好、冻结的规则表；不看本场景历史 | 简单规则（设计者调好） |
| EMP 经验首动作 | 本场景历史中按首动作统计严格成功率，取最高者（平局取平均费用低），之后沿用 B 的固定顺序 | 简单规则（只用日志计数，同 Gate45 R3 口径） |
| HR 历史选规则 | 用估计出的场景（见 M）在 048 的全部候选规则里选最优固定规则 | **混合**：规则族 + 方法的估计器，单列，用于拆分收益来源 |
| M 估计后规划（方法） | 在与本格公开键相同的假设集合（GRID2 中 1152 格）上按历史似然取最大后验（均匀先验），再在该假设上求公共最优策略，按观测自适应执行 | 方法 |
| OPT | 按真实参数的公共最优 | 上界参照 |

所有组的成绩都在**真实场景**下计算（严格完成率与期望费用）。

## 4. 假设、竞争解释与判据

- **H1**：M 能从适量历史（N=50）中收回冻结规则的大部分余量。
- **H0**：历史太少或行为策略信息量不足，M 估错场景，与 FR 持平或更差。
- 竞争解释：① 收益全部来自“用了本场景历史”，任何同历史的简单规则（EMP、HR）也能拿到——则方法的自适应规划没有独立贡献；② 假设集合包含真实场景，对 M 有利——用“去掉真实格的假设集合”作敏感性分析。
- **主判据**（N=50，20 个迁移分割的测试格合并，三种子平均）：
  - **Go**：M − FR 平均严格完成率 ≥5 个百分点，且 ≥10 个百分点的测试格占比 ≥10%。
  - **No-Go**：M − FR 平均 <2 个百分点。
  - 其余为不确定，报告分布与区域。
- **次要**（不改变主判定）：M − EMP、M − HR（方法相对同历史简单规则的增量，按 AGENTS.md 5% 实质差异线判断是否有独立贡献）；收回比例 (M − FR)/(OPT − FR)；N=10 与 N=200；去掉真实格的敏感性；完成率持平时的费用差。
- 结果写回本文件；若 Go 且 M − EMP、M − HR 均 ≥5，下一步在真实 Agent 上与完整 BTM 比较（另行登记）；若 M 与 HR 持平，说明价值在“历史估计”而非规划，方法应写成“估计场景后选规则”。

## 5. 验证

- 每个假设下行为策略的轨迹概率之和为 1；用真实格的历史时，真实格的似然不低于期望水平（抽样检查）。
- 计划格等于真实格时，M 的值必须等于 OPT。
- 变异检查：似然里漏掉严格成功标记、M 用真实参数而非估计、EMP 用了 OPT 信息、去掉真实格时仍可选到真实格，均应被测试抓到。

## 6. 结果

> 编号说明：本实验登记时编号为 050（`bbaac54`），与 `lost-receipt` 分支同日登记的“实验 050 丢回执 BTM 检查”冲突，改为 051。证据 JSON 内的 `experiment`、运行目录 `results/050-history-estimation-01/` 与历史种子字符串（`050:格:重复:N`）保持运行时的原值，以便复现。

代码 `df6a4dc`；测试 8 项通过（另 048 测试 24 项）；四种变异（日志丢掉严格成功标记、方法改用真实参数规划、去掉真实格时仍可选中真实格、经验规则忽略成功回合）均被抓到。“EMP 用了 OPT 信息”的变异未单独构造，改为检查经验规则只读计数。Python 3.10 语法检查通过，云端未复跑。本地 Python 3.14，4608 格 × 3 个历史种子 × 3 种 N。摘要见 [summary.json](../evidence/051/summary.json)。

20 个迁移分割的测试格合并（50688 格），严格完成率差，单位百分点：

| 比较 | N=10 均值 | ≥10 占比 | N=50 均值（主） | ≥10 占比 | N=200 均值 | ≥10 占比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| OPT − FR（余量上界） | 6.2 | 20.8% | 6.2 | 20.8% | 6.2 | 20.8% |
| **M − FR（主比较）** | 1.4 | 9.4% | **5.6** | **18.9%** | 6.2 | 20.7% |
| M − FR，假设集合去掉真实格 | 1.4 | 9.3% | 5.4 | 18.4% | 6.0 | 19.8% |
| HR − FR（混合：估计器 + 固定规则） | 2.1 | 9.6% | 4.9 | 16.0% | 5.4 | 17.0% |
| EMP − FR（只用日志计数） | −12.0 | 1.5% | −5.2 | 3.3% | −2.5 | 5.4% |
| M − HR | −0.6 | 0.1% | 0.6 | 0 | 0.8 | 0 |
| M − EMP | 13.4 | 57.2% | 10.7 | 45.7% | 8.7 | 30.4% |
| OPT − M | 4.8 | 13.1% | 0.7 | 0 | 0.05 | 0 |

- **主判定（N=50）：Go。** M 比冻结规则平均多完成 5.6 个百分点，18.9% 的测试格 ≥10，收回余量上界的 90%（N=200 为 99%）。假设集合去掉真实格后几乎不变（5.4）。M 比 FR 差 ≥5 的格只有 0.1%。
- **N=10：No-Go。** 历史太少时最大后验常选错场景（命中真实格 5%），平均只多 1.4，12% 的格反而差 ≥5。约 50 条历史是门槛。
- **竞争解释①部分成立：收益主要来自“用本场景历史估计场景”，不是自适应规划。** 用同一估计器挑固定规则（HR）已拿到 4.9，M 只再多 0.6（N=50），低于 5% 实质差异线。按登记，方法应表述为“从历史估计场景，再据此选策略”，自适应规划只是小幅加成。
- **只用日志计数的经验首动作（EMP，Gate45 R3/ACV 口径）比冻结规则还差**：N=50 平均 −5.2，47.5% 的格差 ≥5。行为策略首动作随机、后续固定，按回合成功率挑首动作会被后续顺序和小样本混淆。这说明“按首动作或（工具，错误）统计回合成功率”这类统计本身不可靠，需要能区分故障机制的估计。
- **边界**：宏观 CPU 模型；假设集合是有限网格（去掉真实格只检验了网格内失配）；行为策略固定；LLM 是否遵从估计出的策略未测；BTM 未在 CPU 上构造代理，与它的比较须在真实 Agent 上做。
