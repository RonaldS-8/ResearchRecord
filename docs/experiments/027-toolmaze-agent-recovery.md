# 实验 027 · Gate 25 ToolMaze Agent 恢复工程验收

2026-11-10。探索性 CPU 工程验收。依据[ADR-0025](../adr/0025-toolmaze-agent-recovery.md)和[Gate 24 资产审计](026-agent-recovery-benchmark-audit.md)。云端基线 `e386eff`。本轮验证执行与评分，模型效果留待独立试验。

## 预登记

- **问题与假设。** 在相同公开首错下，原生工具调用和已观察回执可以驱动合法重试或切换，独立验收能识别真实完成。竞争解释包括插件成功或原生评分误报、私有参考路径补参、同值但没有合法生产者、账本漏掉复合工具的内部写入，以及故障标签进入模型请求。
- **样本与条件。** 固定 C3-001、C3-002。正常、原读工具首次暂态失败、同工具持续失败、两个注册读取入口均返回明确不可用四种工程夹具。仅拦截选定读取工具。暂态和持续条件的首错文字相同。请求费用按每次已公开工具调用 1 工程单位检查账本，含失败调用。无显式诊断、无模型计费。预算 16 次调用或回答轮次。回放使用确定性调用序列，非模型评估或方法比较。
- **预期通过。** C3-002 两条原生替代路径分别可经合法重试和切换完成。错回执、缺步骤、重复效果、未完成即停止及私有工具调用均不得计成功。可公开证实全部候选入口阻断时正确停止。C3-001 可执行前缀和归档，但错误票据与预约请求不得计完成。配对请求无故障模式、真值、未来结果、参考路径或测试标签。收费与实际调用一致，历史隔离测试通过。
- **独立性审计。** 只读清点现有 C2–C4 任务、替代入口工具族与 P1/P2 文件覆盖，六个设计样例成组排除。报告库存、代理分组和已通过验收的独立样本三种数字。样本审计不按策略收益筛选。
- **证据。** 在 LabServer 隔离工作树使用既有 `.venv` 运行 CPU 验收。保存运行提交、配置、Python/SDK 版本、输入摘要、完整验收轨迹和结果。保留失败批次。测试客户端只回放本地构造的结构化消息。

## 云端工程结果

预登记与首轮提交 `c02e47c`，归档 `results/027-gate25-cpu-01/`。跨层清点及输入类型防御的复核提交 `788a721`，归档 `results/027-gate25-cpu-02/`。两批各通过 9 项 Gate 25 测试和 5 项原有 `test_no_leakage.py` 测试。两批均保存 `config.json`、`status.json`、测试日志、案例轨迹及库存清点。复核批次有 12 个案例文件，Python 3.10.12，OpenAI SDK 3.42.0。脚本响应通过原生 vLLM Agent 的 SDK 请求构造与解析，外部模型请求数为 0。

| 验收 | 观察 |
| --- | --- |
| C3-002 暂态重试、持续故障切换 | 两个受控正例均严格完成。每例 8 次工具调用，含 1 次故障，费用 8 个工程单位。归档文档、通知、邮件和会议各产生一次模拟写入。切换正例经原生 Agent 协议完成，保存 9 次本地脚本请求。 |
| 合法来源、终态和计费 | 验收依据实际返回的归档输入、归档状态／标题和邮件收件人，逐步核对后续绑定。错对象、没有前序生产者、缺会议和重复写入均未通过。账本分列执行费、诊断费、失败／非法调用、重复读取和额外成功调用。Token 和耗时字段已接通，脚本结果不用于估计模型成本。 |
| 停止与隔离 | 单入口失败后的停止未记正确。两个注册入口均返回明确的会话阻断且没有写入时，正确停止，计 5 个工程单位。暂态和持续组直至首错反馈的 SDK 请求完全相同，未带真值、参考路径、任务标签或刻意置入的私有字段。 |
| C3-001 契约冲突 | 两条归档分支均执行并记录其内部模拟提交。原生票据入参是 `slot_id` 与 `duration`，发布插件读取 `slot_ticket_id` 并在缺字段时回退到默认时段。末步只返回预约请求。两条路径均被拒绝认证。最小补充是在独立合同中核实合法票据来源、可见字段和实际预约工具，并分别验收发布和预约；原生任务保留作为回归样例。 |

效果在四个已核对的原生写入叶调用处独立记录，固定模拟 ID 无法抵消重复写入。评分侧使用原生模板的两条合法续程检查绑定，运行时只接收模型给出的工具名和实参。参数来源表示与实际较早回执相容，同值轨迹无法证明模型内部的因果来源。工程片覆盖已登记的依赖和复合调用链。新增复合工具若没有可观察的叶提交，需要独立验收后才能纳入。当前评分覆盖工具执行与效果，尚未单独判定最终自然语言答复是否准确转述全部结果。

## 诊断契约审计

- C3-001 的 `query_availability_outlook_calendar` 查询人员日历，提供必做任务信息。它不报告航班工具的健康状态。航班详情读取若提供归档材料，属于执行性信息获取。
- C3-002 的 `get_account_balance_bank_api` 是必做余额读取，且被银行报表插件在内部调用。返回的账户 `status` 描述账户，代码可从先前结果复用余额。这个字段不能作为报表端点可重试的证据。两项样例中已核实的合法显式诊断接口为 **0**，诊断费用在本批不适用。
- **最小扩展路径。** 库存中有 24 个含 `get_iot_device_status` 和控制工具的既有任务。抽查 C2-046 和 C3-085，其原生状态读取都属于用户要求，计执行。可优先筛选其中已有公开设备 ID、独立状态读取和写入义务的任务，保留同一原生插件接口。仅当额外查询主要为判断下一步是否合法或有用、且其状态字段对该决策有独立证据时，登记为付费诊断。例如只读当前设备状态，核实原回执是否仍足以安全继续。须先验收字段来自模拟设备状态或合法查询回执，能保持过期、失败和无新增信息的情况，并分离状态证据与未来调用结果。若找不到有效关系，继续标记诊断缺口。这个候选只经源码和模板核查，尚未运行或接入。

## 对照与放行

Gate 19–23 的冻结实现与历史归档保留。新执行入口复用原生 ReAct 的工具循环。完整 BTM 的提示条款和后验格式、Action-Conditioned Memory 的续程估值格式，以及固定顺序、上下文规则、最近反馈、历史阈值、简单诊断和确定性解析，均沿用 Gate 19–23 的设计作为后续对照。原 A/B/C 合同的统计键、策略状态和已拟合历史还没有迁移到新的 ToolMaze 工具契约。迁移时所有组共享工具、可见证据、静态契约、预算和评分。诊断对照以合法查询验收为前提。简单规则稳定适用是有效结果。

**最小工程切片通过，完整 Agent 实验暂不放行。** 已验证一个完整原生任务的替代恢复和一个原生任务的严格拒绝。独立留出仍需认证，合法诊断仍待接入并验收。没有提交完整实验设计或运行 LLM。现有 ToolMaze 与 Gate 19–23 冻结代码保持原状。
