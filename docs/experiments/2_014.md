## 结果与判断

运行 3dbe680，云端 results/2_014-cpu-01/pairs.json。会议七种绑定均返回 active，只有 start_time 满足开始提醒、end_time 满足结束提醒。原规则选 title 两者均错，图保留两个时间；明示开始/结束角色的规则可以分别挑中。严格的持久提醒状态不可查。商品六种绑定中三个 ID 被接受；原 ID 指黑色，product_id 和 recommended_product_id 均指银色，两种后者都符合推荐商品要求。图保留这三个 ID，规则只选 product_id，满足推荐但不满足原商品。按对象角色匹配可覆盖两种显式义务，但该角色映射为知情参照。本例仅看新结账回执，先前预留的释放和实际扣款未知。

Gate050 的十二个确定性组合中，先查询再据结果读回或切换在 C/T/P 均严格通过，每次诊断费一单位。直接切换在 T/P 成功，在 C 重复发布两次。P 中先查再重试策略执行两次查询，虽发布一次但预算耗尽未读回，严格失败。该部分为旧机制复核。源文件与逐项回执见[运行器](../../extensions/route_recovery/obligation_pairs.py)和[派生证据](../evidence/2_014/pairs.json)。

预设机制门槛达到；单次确定性案例不能估计成功率、证明图优于规则或证明模型能识别义务。建议下一步仅在相同可见信息和同一候选列表上比较直接模型选择与角色匹配规则；成熟图负责候选，再评估模型自主取证和执行。保留能以多个值来源等价通过的验收条件。
