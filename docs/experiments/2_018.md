# 2_018 同一 M4 的路线信息阶梯

冻结 2_017 M4 中性指导、模型、种子、输出与三次后续调用预算。在故障回执后统一追加消息，三组分别给同一批无序名称、有序链、有序链加公开参数来源，不给实际值或成功保证。人工信息是知情机制参照。每组一次、至多12请求和30 GPU分钟，无外部API。按首次备用动作、合法回执、三步完成及严格评分比较，记录 Token 和时延。无动作不证明不会执行。

后续固定链长和预算，分别增加同型竞争工具、近似业务用途和组合分支数。按结构预选，保留简单任务，控制菜单长度和输入 Token。4B 失败只描述该模型与协议。冻结任务后再用较强 API 和可部署的 7B/9B 级模型复测；Q4 与参数量存在混杂，考虑同权重量化对照。只有跨任务复现同类缺口、有不重叠训练族时才考虑 LoRA。报告训练、构图和推理成本。API、下载权重和训练另行预算。

## 验收

源提交 95c4c95，云端 results/2_018-gpu-01。剔除末条干预后，三组首请求逐字段一致。各自重置 M4，重放全部后续调用，逐回执、原严格通过标志和问题列表均相符。无序名称组零次新调用、无发布；有序链和有序链加来源组均准备、确认、读回，全部实参相同，严格通过。输入/输出 Token、时延及哈希见[独立复算](../evidence/2_018/replay.json)。

该模型在此已见点能够执行三步及自行绑定；本轮最小成功干预是明确给出有序续程。无序与有序组同时改变排列及“Candidate tools / Candidate continuation in order”措辞，不能单独归因给排序，也不能据此证明自动发现。建议下一步以规则与作者拓扑采样生成候选，检验能否从公开菜单中自动选出适用于当前任务的有序链；预先区分生成漏召回、排错、模型拒用和执行失败。与同预算直接 Agent 比较，并在成本评估中单列失败即停。
