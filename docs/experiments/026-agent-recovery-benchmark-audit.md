## 四类机制如何进入同一个恢复循环

选用已有的多步任务。Agent 先按用户要求取得数据或回执，再用它完成后续义务。已发现的故障发生在某个依赖环节。统一设计的关键是**恢复动作既推进任务，也改变 Agent 随后能获得的证据和必须完成的工作**。

1. **已有反馈与隐藏故障。** 早先的成功、失败、回执和当前错误共同提供证据。例如，来自同一后端的更早失败可能降低再次尝试同域工具的可信度。具体故障范围和持续性留在环境。故障会随时间及合法调用进展，状态更新与信息可见时点均以契约为依据。
2. **动作与下游执行。** 重试可能保留已有合法输入和依赖，切换可能产出可直接使用的等价回执，也可能需要额外验证、刷新或转换。回执是否满足后续要求取决于任务和实际返回，成功调用本身并不证明任务完成。涉及写入时，重放保证和副作用约束同样适用于所有策略。
3. **显式诊断的信息价值。** 当合法查询可区分会改变选路或续程的状态，Agent 可在执行前付费查询，也可先做一次能推进任务的合法调用，用执行反馈决定是否还需查。相同诊断证据可能对不同任务产生不同收益。若可行续程始终相同，或一次低费执行已经给出足够证据，付费诊断可能只有开销。
4. **历史估值的不确定性。** 跨回合历史给出先验或条件估值，采集策略可能很少在当前证据和任务下尝试某个合法动作，工具契约或故障条件变化也会让旧统计失准。这是对估值可靠性的限制。它与环境的隐藏状态分开记录，可能促使 Agent 参考当前证据、采用契约规则或在值得时查证。

例如，旧回执和新错误都指向共享服务异常时，Agent 可能考虑独立工具。若独立工具给出的数据可直接用于当前任务，一次切换同时推进执行并产生反馈。若同一返回在另一任务里还需校验，切换的剩余成本及诊断价值都可能改变。此时若历史只有“该切换后的回合大多完成”，还须区分它是否覆盖本任务所需的续程。这个例子说明机制怎样相连，具体任务与注入频率仍由现有资产和公开契约约束。

## 为什么简单规则经常有效

- **备用可靠且续程近似相同。** Gate 19 的可靠备用能完成各节点，宽预算也允许再试原工具。若备用必成，两条路径后续费用相同，先试原工具的期望费用为 $c_A+(1-p_A)c_B$。与直接切换相比，只需判断 $p_A>c_A/c_B$。增加同质节点或替代工具仍可能留下同一阈值或固定顺序。[Gate 20 分支审计](022-recovery-mechanism-audit.md)
- **重复的公开证据与相同续程压缩了有效差异。** Gate 17 的闭式局部规则覆盖有限规划。Gate 21 的单点反转成立，但完整机制格的固定顺序仍逐步同选。Gate 22 的单次探针规则与完整规划具有相同执行序列，规划主要节省八次探针。较早证据若常与最近反馈同向，或只影响同一分支的一个阈值，保留整段历史的收益就很小。Gate 23 中确定性解析替代混合组后同选，说明当时的结构化合同已将许多语义判断变成字段读取。[Gate 17](019-stochastic-dynamic-recovery.md) · [Gate 21](023-multipath-recovery.md) · [Gate 22](024-contextual-recovery.md) · [Gate 23](025-agent-efficiency.md)

新设计用契约导出的任务义务和证据可用性定义样本，在比较策略前确定抽样与分层。保留固定顺序足够的情况，也保留实际续程因任务或回执变化的情况。手工见证用于检查环境机制，留出样本的准入按契约、合法可执行性和证据完整性判定。

**首批准入样例。** C3-001 的两条分支分别取得 gate board 或 trip timeline，再交给对应归档工具。C3-002 的两种余额对象分别进入对应归档工具，后续邮件还依赖归档状态和标题。两者提供可追溯的下游数据依赖，可用于工程验收。C3-003 复用 C3-002 的银行／券商工具族，契约留出时须同组。C2-055 的复合／分解分支可作独立评分与计费边界验收，复合插件直接调用内部插件，外层拦截看不到每次内部调用。C2-001 的天气结果未绑定到后续文档，适合作为续程相同的对照。C2-018 可复用旧回放作回归，分解分支的 `send_email.recipients` 来自用户输入，不能据此认定联系人查询结果已进入邮件。此前审计过的样例用于设计或验收，从确认性留出排除。见[原生 C3 证据](008-c3-c4-recovery-audit.md)和[C2 验收草案](../c2-independent-completion-spec.md)。

**两个缺口。** 抽查的 `create_document` 与 `push_alert` 返回固定模拟 ID，代码没有持久化业务记录。严格验收需要独立记录模拟动作实际生效的对象、参数与次数，不能靠成功字符串或 ID 唯一性推断；复合步骤的内部效果看不到时，该实例只作回归。现有样例也尚未核实有能区分恢复状态的合法查询。仅在任务具有可调用的状态或详情接口、且查询标识来自公开证据时纳入显式诊断。若缺该接口，先保留重试／切换／停止子集，联合诊断试点暂不放行。

| --- | --- |
| 任务与生成 | 从现有 ToolMaze 多路径任务及 Gate 19–23 合同筛选可复用样本。每个任务至少有一项依赖真实回执的下游义务，任务要求、授权和成功条件可核验。替代工具按已文档化的输出能力、语义等价条件和额外义务纳入。保留正常与合法受阻对照，允许部分任务只有一条合法路径。按契约筛选或生成实例，避免以步数、工具数或预期策略胜负决定纳入。 |
| 故障与动态反馈 | 首版只在读／准备工具上加入一层隔离包装，提供正常、暂态、持续和有公开证据的阻断条件。原生错误保留作对照；受控组仅在接口契约允许时用相同超时反馈配对不同持续性。按任务实例、工具与重试次数对齐外生事件，时间变化按登记的环境时钟处理。共享故障和写入结果未明待具备契约及状态验收后再纳入。诊断只读合法状态或详情接口，保留明确错误或无新增信息的对照。注入频率和持续性属于受控假设。 |
| 观察与动作 | Agent 可读任务、工具文档、合法历史、报价和原始工具反馈。当前故障真值、生成参数、参考路径及未来结果留在环境。允许通过实际工具接口自主诊断、在契约允许时重试或切换、停止并说明依据，再执行所需续程。只有主要用于取证的独立调用计显式诊断；推进任务并带回证据的调用计执行。硬性契约对所有策略一致。 |
| 语义与验收 | Agent 判断用户条件、错误文本和回执之间的关系，识别部分成功、替代差异、仍待验证的义务，并用实际回执绑定后续实参。执行器可做通用校验和无损字段传递。独立验收依据真实调用、参数来源、依赖、终态与副作用账本。允许语义等价的合法路径。区分正确停止、未决安全退出、过早停止与预算耗尽。 |
| 历史与留出 | 按任务家族、工具契约、故障条件分别留出，另列同分布对照。任务留出切分语义目标及依赖结构；契约留出提供新工具公开文档和实时回执，隔离该契约的训练轨迹；故障留出改变已知机制的持续性或共享范围，单列跨机制外推。基础任务、共享事件与其派生条件成组切分。历史来自冻结的自然行为策略；需补充时可在训练检查点均衡分配合法首动作，历史对照共用记录。固定回合数也要报告各任务条件、动作和续程的直接支持。 |
| 分叉与报告 | 同一起点成对运行完整 Agent，包含正常前缀、故障和恢复。另从共享的合法首错检查点评估恢复表现，避免用各策略自行遇错的子集比较。首次合法分歧可用同快照、同外生事件、同续程核验。主要报告全回合严格完成、正确停止和副作用，分列工具费、诊断费、输入／输出 Token、延迟与冗余。共同完成子集用于解释费用。按独立基础事件和三类留出分层报告；正确停止无适用样本时标记不适用。 |

**最小落地顺序。** 先按任务依赖及公开工具合同建立样本清单。任务留出要有不同目标或依赖的同契约实例，契约留出要排除训练中相同或等价的接口和共享故障域，故障留出要在可比较的任务与契约上隔离一类变化。每个轴需要多个独立基础实例，不能用同一任务的模式、价格或种子补足。检查过的六个样例只支撑设计与验收，未证明三类留出均已有足够覆盖。历史池保持各方法同源，未见键明确标记零支持。

首个工程切片复用现有 Agent 和插件，只拟增加一层回合包装、少量任务契约数据及独立验收。包装只拦截调用、返回合法可见字段并记录账本。复合工具按一次外层调用记录，内部提交可观测时分别验收副作用，价格另行确认。先用已知合法路径、错回执、缺步骤、重复写和可证阻断作为验收夹具。核对重建前缀、正常／受扰提示一致及账本，并检查实际模型请求是否夹带参考路径、环境模式或用户文本与工具回执中从未提供的结构化参数。验收后另行登记试点规模和费用口径。

## 方法对照与阶段判断

- **强基线。** 保留原生 ReAct、完整 BTM 提示复现、最强固定顺序、任务上下文规则、最近反馈、完整历史费用阈值、简单诊断规则和确定性解析加同一恢复规则。顺序、阈值和诊断条件在验证集确定。所有组共用任务、契约、反馈、可用历史、价格和执行预算，规则也能遵守合法重放及退避约束。完整 BTM 保留回合后验、替代粒度、合法先重试、核验及升级约束。训练历史固定；若试跨回合在线 BTM，按统一顺序与同等可得反馈单列。共同提示对照分别比较无历史、BTM 统计和动作条件估值。[ReAct](https://arxiv.org/abs/2210.03629) · [Bench2Robust 附录 B.1](https://arxiv.org/html/2608.11977v2#A2.SS1)
- **最小方法。** 用同一原始工具证据比较现有提示与规则。可用少量预登记的消融估计任务证据、最近反馈、较早历史和合法诊断各自的增量。动作估值组可提供规定续程下的严格完成率和分项剩余费用，附直接支持数、外推及验证误差，由 Agent 自主决定。核查低支持或排序不稳时，规则回退、支持度提示或付费查询哪种更可靠。查询收益按实际改善的结局和剩余成本衡量，计入查询自身开销。
- **判别与放行。** 分别记录语义理解、合法选路和续程失败。跨留出持平或胜出的简单规则是有效结论，按预登记的契约与证据条件报告适用边界。新增复杂方法的理由是有可复现的增量效果。单次换序、协议绑定或同一事件的多个派生行只提供机制证据。当前结果是源码与样本审计及最小设计，完整留出覆盖、独立验收和合法诊断能力仍待验证。
