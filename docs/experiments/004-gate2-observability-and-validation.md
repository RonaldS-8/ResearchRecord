# 004：Gate 2——P3/P4 可观测性与独立完成验证设计

用户批准任务 A 的完整配对审计、任务 B 的独立规范及测试设计。只在云端 CPU 运行审计，无模型推理，不设计诊断算法，不改原始数据、模拟器或 Judge，不将验证规范直接作为新评分实现。指标成本草案仍待批准。

## 问题、假设与可证伪标准

- 不确定性：异常已知后，首次合法观测是否能区分 P3/P4 持续性；尤其前轮相同的 12 个输出对，其完整输入是否也相同。
- 假设：部分配对输入相同，但其他输出的结构或内容可能带有持续性线索。
- 竞争解释：输出差异只是随机扰动，没有可泛化的状态信息；规则失效只是过于简单；异常检测困难被误当成持续性难判断。
- 判据：完整可见输入相同的配对支持该检查点无法由当前观测确定状态；输出不同仅说明有差异，不等于可可靠分类。规则成功/失败按预登记指标报告，不据留出结果改规则。

## 冻结流程

1. 复用此前任务划分：已见任务 001–013 为规则建立集，其余 87 个任务全部留出。全部路径和模式按任务分组，检查模板不交叉。Gate 1 已处理过全量静态相同性统计，故这不是全新外部数据集；本轮留出内容不参与规则建立。
2. 冻结两种简单对应规则：A 为规范化完整异常输出的精确匹配；B 为输出结构签名匹配（递归 JSON 类型、字典键、数组结构和预定异常标记，普通数值/字符串内容不进入 B）。建立集同一键出现两种标签或留出键未见时，均返回“无法判断”。不使用任务 ID、路径 ID、模式字段、真实输出或扰动配置作为输入。
3. 先获取 13 个建立集的首次真实注入响应并保存规则及哈希，再读取其余 87 个任务。原始模型输入由现有 Agent 构造；只调用故障返回接口，不调用正常工具、重试或模型。历史用参考前缀重建，不能冒充模型轨迹。
4. 持续性分类以“异常已知”为条件，评价全部首次异常输出，不按异常规则检测成功与否筛选。报告准确率（无法判断计失败）、覆盖率、已判断准确率、混淆计数及任务全部路径正确比例。可靠标准沿用：任务比例≥95%、Wilson 95% 下界≥90%、覆盖率≥95%。
5. 独立记录可见异常线索：输出非对象、顶层 error、非有限数值，或递归出现精确标记 CORRUPTED、[CORRUPTED]、INVALID（忽略大小写/空白）。用 P0 同工具参考输出计算规则误报；参考输出差异另列为审计者真值对照，不叫异常检测成功。该规则不是完整业务语义检测器，也不评价模型检测能力。不使用仅 MCP 可见的 output_schema 来声称函数调用模式已知约束。
6. 全部 100 对、200 个路径比较查询、系统提示、工具定义/顺序、故障前历史、调用参数和首次响应；将首次响应统一替换后再次比较完整输入。单列原先 12 对相同输出的任务/入口、完整输入是否相同、规则预测、异常线索与参考差异。

### A3. 异常识别与持续性分类分开解释

200 个 P0 对照输出、P3 的 200 个输出、P4 的 200 个输出，预定的窄异常标记规则均未触发。它只检查明确 error、特殊标记、非对象和非有限数值，没有覆盖完整类型和业务语义，所以不能把 0 次触发写成模型无法识别异常。
