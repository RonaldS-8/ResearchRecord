# 2_009 · 真实 Agent 路径发现与剩余义务解耦

2026-11-18。设计基线 `research/route-recovery@4ed394b`。**探索性预登记，待审核批准。** 无新增模型请求或实验结果。复用 ToolMaze 的 `ExecutionEngine`、`ToolExecutor`、`VLLMAgent` 和 Qwen3-4B-Thinking-2507。新增代码如有必要，限于 `extensions/route_recovery/` 下的薄适配、记录和独立验收。001–060 冻结，Gate 060 不重跑。

## 问题、假设与证据边界

Gate 060 有 7/8 局部业务通过和 1/8 严格通过，7 个严格失败均缺写后查询。候选对照没有把路径信息与义务提醒分开，且一项任务给出了替代商品。原登记和独立复核位于 `gate059-dynamic-evidence@b3a226c` 的 `docs/experiments/060-agent-route-smoke.md` 和 `docs/reviews/060-agent-route-smoke-review.md`。

- **H1 路径知识。** 合同生成的候选增加实际尝试正确多步路线的回合，并可能提高局部义务完成。竞争解释包括候选未覆盖、排序误导、工具菜单已经足够、模型知道路线但绑定失败。
- **H2 义务执行。** 把同一用户请求重排成义务清单，提高正确交付、回执核对或报告；即便选择了路线，模型仍可能提前停止、填错字段或遗漏核对。竞争解释是清单仅改变提示显著性，或者执行已经接近上限。
- **H3 可分离性。** 两因素的作用可能互补、重叠或抵消。这里估计的是分配两类提示的效果。候选提示也可能提高执行稳定性，清单也可能帮助选路线，故不会把组间差额解释为对模型内部机制的直接测量。

- 设备（4）`get_light_mesh_snapshot_native`、`get_light_bridge_payload_native`、`get_iot_device_status`、`get_light_status`。
- 航班（5）`get_aviationstack_gate_board_native`、`get_flightaware_trip_timeline_native`、`get_flight_info`、`get_flight_info_aviationstack`、`get_flight_info_flightaware`。
- 天气（5）`get_weatherapi_alert_card_native`、`get_visualcrossing_forecast_chip_native`、`get_weather_openweather`、`get_weather_weatherapi`、`get_weather_visualcrossing`。
- 归档（8）对应四个业务类各自的两种公开 `archive_*_native` 接口，只包含名称主体为 `bank_balance_sheet`、`broker_balance_ledger`、`light_mesh_snapshot`、`light_bridge_payload`、`aviationstack_gate_board`、`flightaware_trip_timeline`、`weatherapi_alert_card`、`visualcrossing_forecast_chip` 的八个工具。

各组共享原生 Agent 系统提示、同一局部用户正文、失败回执和工具卡。P 块只列按规则产生的最多五个工具名序列，标为待验证，允许跳过。O 块只将共同正文改排为“对象与内容／归档与通知条件／回执核对与报告”，逐字保留要求和取值，不出现工具名、链、参数绑定示例、评分条件或额外义务。两块存在时固定 P 在前、O 在后；各区组的 R10/R11 使用完全相同的 P，R01/R11 使用完全相同的 O。两种提示的额外 Token 分别记录，比较的是提示策略整体效果。

P 使用现有 [Deriver](../../extensions/toolmaze_recovery/route_discovery.py) 的公开合同字段匹配和束搜索，beam=200，保留长度 2–4、以具有归档及通知公开回执字段的工具结尾的链，去掉包括实际失败工具的链。输入限于共同任务已给的参数键及实际已见回执。用既有 `Deriver.cos` 按链说明与失败工具及共同任务正文的词元相似度降序，短链优先，同分按工具名序列排序。以明确的固定字典序枚举和固定 `PYTHONHASHSEED=0` 消除集合迭代差异。运行搜索前锁定规则与工具池，空候选或覆盖不足照录，禁止据验收标签或实际模型表现补候选。搜索所用完整合同与模型卡同源同字段，候选不得附带推荐路由、正确性标识或预填参数。

另做四个 **D 确定性执行回合**，每任务一个，单列且不计入 2×2。D 使用相同公开合同、用户正文、已见错误、候选排序和 12 顶层调用上限，不调用模型。D 依序尝试搜索保留的链，可扫描全部排序链而不限提示前五。执行参数优先用正文的同名已知值，其次用合法先前回执的同名字段。若唯一来源是前序回复且公开参数要求业务对象，传完整对应对象。多义或缺值即拒绝该绑定，不猜枚举事实。D 在写前核对对象、正文要求的业务字段、接收方、标题、渠道和优先级，缺证据则只能换下一条读取路线。写后核对实际回执的标题及两个 ID、正常报告或标为未知。只要发起可能生效的写入，就不再次尝试写入。规则阈值、字段投影及同分顺序随运行提交冻结，禁止按任务 ID 指定工具或路径。D 成功只说明公开信息和确定性执行足以完成该回合；D 失败不能推出任务无解或模型一定缺路径知识。

## 验收与逐回合归因

评测进程独立于搜索、D 和模型。先保存原始 SDK 请求/响应、工具实参、公开回执及实际嵌套调用事件，再以同一模拟器在新 context 中独立重放实际调用，核对状态与实参。内层保存和通知插件的实际内容、收件人、渠道、优先级和回执按调用时序关联，记录器只观察，不向策略返还内层信息。固定 ID 可重复出现，凭实际事件计数与关联，不能单凭 ID 判定执行。禁止把原路径精确匹配当作正确性，任何等价路线都按下列规则验收。

1. **路径发现。** 轨迹中实际尝试连接正确业务的数据来源和归档动作，工具能在公开语义上形成可行多步链。若因参数错误未运行完，已提交的工具序列仍可证明发现。仅在最终文本提议且未尝试的正确链单列；其余只记未观察到发现，不推断模型内心。独立评测另给 P 候选是否覆盖可行链，区分搜索漏召回与模型未采用。
2. **合法绑定与执行。** 分别记录对象、作用域、参数合法性，必需数据是否来自此前成功取数，及执行回执是否成功。业务值按本轮回执复核而非预期常量。序列化允许字段重排与公开等价字段名，要求归档保留表内所有字段的值及目标对象；伪造、遗漏或把不相关对象传给宽松插件均失败。字段等价表和回放比较规则在模型请求前随运行提交冻结。
3. **局部业务完成。** 需要恰好一次实际保存和一次实际通知、完整合法来源与表内配置、通知正文对应归档标题。记录来自同一模拟器的执行证据。外部持久性、邮件送达和原 C3 整体任务均不评，记为 N/A；不能用回执宣称外部状态。
4. **主动核对与严格局部完成。** 独立地记录 Agent 是否根据本轮对应回执核对并在最终答案准确报告两个 ID、以及是否观察到对标题或状态的显式核对。核对证据来自最终答复前的可见推理、工具行为或最终答案明确引用对应回执，沉默的内部检查记未知。区分仅复述 ID 与有可见核对证据。严格局部成功要求业务完成、从真实回执正确报告两个 ID、正常结束，并且恢复期无非法调用、错误工具回执或用户未授权副作用。主动核对可见性单列，隐藏推理不作为严格评分门槛。没有可公开读回归档状态的工具时，写后状态查询记 N/A。首次注入错误不计为恢复期非法调用。
5. **首个可证实阻断。** 按“系统异常／预算或代理响应中断、可行路径未见、路径已见但绑定失败、绑定合法但执行失败、执行成功但对象/内容/通知未满足、业务已成但回执核对或报告遗漏”记录主要阻断及所有并发缺项。无法区分时保留未知。明显可见的计划后未执行与未找到路径分别记录。

主要终点为实际路径发现和严格局部完成。每个终点给四组绝对分子/分母及四个区组原值。按区组分别计算 P 的两条简单效应 `R10−R00`、`R11−R01`，O 的 `R01−R00`、`R11−R10`，再报告各自两条效应等权均值和交互 `R11−R10−R01+R00`。同法报告业务完成、合法绑定及报告/核对作为解释指标；不用“仅在发现成功者中”的差额作因果估计。展示百分点、净改善/退化的配对计数，不做显著性宣称。

若对应提示在至少两个任务区组改善其预期环节、且没有区组的两条简单效应均值为负，并有可复核的轨迹机制，记为值得进一步验证的探索信号。P 优先看实际路径发现；O 优先看严格局部完成，并要求轨迹支持出现义务或报告改善。失败的 R00 若有同任务 D 完成、且观察到至少两个任务的同类阻断，则列为可复核的 Agent 瓶颈。候选覆盖不足、D 执行偏弱、各组均接近上限或不同任务方向冲突时，按具体原因报告不确定。单个区组成功只报告个案。不因结果改评分或新增样本。

## 预算、停止和测试

- 固定 16 个模型回合、4 个 D 回合，各一次。按任务表顺序运行，模型四组在四个区组中分别用 `00,10,01,11`、`10,01,11,00`、`01,11,00,10`、`11,00,10,01` 的顺序，D 每区组最后。各区组共享模型种子 200901–200904，temperature=0，沿用 Qwen3-4B-Thinking-2507 revision `768f209d` 对应全长已校验权重，具体版本与 SHA 随冻结清单记录。
- 同组预算为每回合至多 8 个 SDK 请求、12 次顶层工具尝试，首错准备和独立验收另计。单串行，单请求最多一个实际工具调用，因此模型组的实际调用还受 8 请求上限约束。禁止自动重试、替换样本和强制指定工具。每请求最多 6144 输出 Token、180 秒，真实模型请求全批最多 128 个（输出上限 786,432 Token），批次墙钟上限 8 小时。使用经 Function Calling 工具卡对照验证的服务端计数，逐请求请求前检查上下文 32768；服务计数若无法核验，停止并报告。任务停止、截断、空答、超限、参数失败均留原轨迹，进入固定下一回合；泄漏、状态隔离失败、评分器故障、记录缺失或服务不可用即停整批并归档，未运行格单列。禁止靠重试或扩样补齐。
