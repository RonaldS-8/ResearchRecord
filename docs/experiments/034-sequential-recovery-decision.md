**问题与假设。** H1：原恢复接入只检查读取失败，成功库存读取后的写入超时及查询反馈会丢失检查点；序贯接口应在新合法反馈后继续识别剩余恢复义务。H2：强一致请求查询后，简单反馈规则可能解决提前停止，无须动作价值预测。竞争解释是工具理解、绑参或续程能力失败；规则足够；规则额外提示产生收益。结果只能支持机制与真实续程可行性，不能识别估值的独立收益。

**范围。** 复用已多次使用的 `stock-write-recovery`，两个隐藏条件 `write_not_committed` / `write_response_lost`；同属 stock-reservation 基础任务、depot-physical-stock-v1 实现、ambiguous-write 事件谱系。全部为开发数据，不能作为独立样本或确认性测试。查询失败仅 CPU 检验，不追加真实场景。无 BTM/动作记忆比较，无显著性结论。

**CPU 先行。** 核对两个隐藏条件首次诊断前的任务、工具、历史、上下文与原生请求相同；查询后 not_found/found/失败的公开历史、证据允许动作和 unknown 估值；真实 ID 绑定、真实写入与复核；首次查询后检查点保留；查询失败无安全写入证据；没有额外计费或隐藏真值。脚本证人明确单列。运行序贯专项、原有 ToolMaze Agent/接入/MVP/写入/家族及 `test_no_leakage.py`。所有执行仅云端 .venv，归档每次失败，不覆盖日志。CPU 不通过不启动模型。

**真实 Agent 冻结方案。** CPU 通过后，使用现有 Qwen3-4B-Thinking-2507（修订 `768f209d9ea81521153ed38c47d515654e938aea`），vLLM 现有服务配置，temperature=0、seed=3201、每请求最多 6144 输出 Token、12 次实际 SDK 请求、总工具预算 16（含前缀）。每组/隐藏条件各一次，共 4 回合，上限 48 次 SDK 请求。固定顺序 ReAct not-committed、ReAct response-lost、Simple Feedback Rule not-committed、Simple Feedback Rule response-lost。无按结果补跑、改提示或改任务。

两组均从既有真实库存读取→写入超时的相同前缀恢复；首次真实模型请求单独用 SDK tool_choice 限定 `lookup_reservations_by_request`，模型仍绑定 request_ref 并消费回执。此前缀和首诊断限制不称自主选路。诊断后的 ReAct 完全原生选路；规则只限制下一工具并给既有控制格式的选中工具提示，参数、实际效果和最终答复均来自模型。记录实际第一次诊断参数是否合法；若不合法不伪造诊断后配对。两个组都保留原工具定义、公开回执、预算、评分和价格，规则施加的工具限制/提示作为干预差异公开。对相同隐藏条件核对诊断前首请求一致，以及诊断后实际公开证据一致（ID 为各次会话真实签发，不替换回执）。

**归档与分析。** `results/034-gate32-cpu-01/`、`results/034-gate32-agent-01/` 保存配置、提交、版本、种子、SDK 请求响应、所有公开检查点、支持度、续程标签、外部约束、模型实际动作、完整事件、账本、评价及失败。每个检查点记录已付执行/诊断费和各实际后缀费用；后缀包括当前动作，不重复计沉没费用。工具/显式诊断费分列，普通状态验证为执行费；输入/输出 Token、延迟、重复效果和非法调用分列。自托管无已确认模型货币报价，Token/秒如实列出、货币费不臆估。四例均可恢复，正确停止率不适用。

按合法公开证据检查动作选择（停止/无证据写入/选错工具）、参数绑定（已有校验回执及模型是否用真实 ID）、续程执行（合法动作后未完成必要复核或答复）分别描述；不修改评分或新增历史非法调用审计。首诊断及规则选路的外部来源与模型自主选择分列。不以这些样本估计 Q。所有动作成功率/预测成本均 unknown、支持 0，续程明确为原生 ReAct 或 Simple Feedback Rule + 同一 LLM；未来比较动作必须固定续程。

**可证伪及 Go/No-Go。** H1 若查询后检查点丢失或未随证据改变则工程失败；H2 若规则组任一后续实际义务失败，则本批不能声称解决全部开发条件。信息隔离和回归正确，且至少一条真实诊断后续程严格完成为 Go。需要隐藏真值、执行器代办义务、回执不足以支撑合法动作、旧评分或防泄漏回退则 No-Go。简单规则全完成如实报告，停止扩张方法，交由下一阶段采样设计决定。不调整故障制造优势。

## 归因与阶段判断

**观察。** 新接口在查询后产生 `confirmed_absent` 或 `verify_existing` 决策点。not_found 的 CPU 证人可以合法再预留并复核；真实模型两组却都提前停止。规则已选对 reserve_stock，模型未提交该调用。found 两组均正确绑定实际 ID、完成真实状态回读与最终答复，没有重复副作用。

**错误区分。** not_found 的可观察错误是模型选择停止／不执行外部所选工具，不是已经发生的重试参数错误；模型未尝试重试，故其重试绑参与重试后续程能力尚未验证。found 的参数绑定与续程执行均通过。没有观察到“合法重试后执行失败”，也不能仅凭结果将停止归因于动作估值不足。原生 ReAct 本来已有消费反馈的完整循环；新增接口使恢复义务和规则干预可连续记录，未证明本批任务必须依靠新接口才能成功。

**判断。** H1 的接入缺口和序贯工程可行性得到 CPU 与轨迹支持；不构成完成率收益证据。H2 在本批未满足“解决全部开发条件”：规则未修复 not_found 的提前停止，两组完成数相同。**机制 Go**：信息隔离、账本与回归通过，且两条真实 found 诊断后续程严格完成。没有证明规则或估值的性能优势，不推进复杂估值或大规模方法比较，不改条件追求正结果。
