# 2_026 独立任务上的依赖判别与顺序增量（运行前登记）
选择流程先于方法输出。由评测侧按基础任务、工具实现和故障谱系隔离开发/验证任务，登记既往使用与作者样本重合、公开工具池、故障前缀、可观察业务状态，以及屏蔽主入口后的合法替代执行证明。无法证明或存在重合的条目保留原因，不计独立样本。包含简单替换、共享标识符、需要新凭据或重新验证的情况，不依据模型是否失败入选。与合作者的 Benchmark ADR 共用一份任务清单，未确认的新环境只作可行性审计。
 
比较冻结公开规则、规则加有效依赖判断、2_025 GOAT 迁移、迁移加同一判断。边按具体输入参数判定；其他必需参数允许由公开前缀或其他工具补齐。已有且有效的值不强制排序，回执失败仅否定其明确涉及的绑定，不笼统屏蔽工具。证据不足保留 unknown。固定排序器及候选池，记录每层漏边、误边、实际入口及构建成本。M3/M4 仅作回归，不作独立验证。
 
在线隔离顺序：同一自动入口和后继工具，比较仅首步、相同两名字无顺序说明（平衡展示顺序）、两名字带推导方向。错误边照常计入。相同任务、模型、工具、历史、请求设置、实际消息及种子均一致才复用。分别记录第二动作、参数来源、写入/读回、严格业务完成与模型/工具成本；失败分为选路、参数绑定、执行器误导性回执及验收差异。完整 BTM 历史来源与成本需独立登记。独立任务清单、实际组数、预算及停止条件需在在线执行前冻结。当前尚无已验收独立任务，不启动正式 GPU 对照。

### 已见任务的开发批次（独立比较另行登记）
正式提交开发队列。M3/M4 全部纳入，直接从冻结 build.json 读取两方法产生的前两个工具，不足两项记缺失，相同二元组合只运行一次。M3 规则无第二步；M4 两方法相同。每种子同时交叉两种名称展示方向和两种顺序说明（有向关系/未指定）；前者明确复述名称，故估计的是提供显式顺序说明的整体效果。两任务×16种子×4=128 条，最多 704 请求，8 小时45分上限。对同种子同展示顺序配对；两种展示不视作独立任务。历史首步作辅助参照。记录实际首两动作、绑定、回执、业务成功及成本。错误建议照常执行；目前不运行尚未冻结的改进方法，独立样本与方法排名单独验收。
