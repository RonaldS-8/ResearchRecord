# 005：Gate 3 部分可观测诊断 MVP

用户授权的独立扩展，工程决策见 ADR-0003。先提交设计及参数，再实现。原始 Benchmark 保留，无模型、训练、RL、P3/P4 或 GPU 推理。

## 假设与固定任务

问题：在故障持续性不能从首次反馈直接判断、恢复动作存在代价差异时，可选诊断是否仅在其收益覆盖价格时值得购买？竞争解释：一次重试已经提供足够信息；总是切换已足够；诊断并未改变动作。

根据 Gate 1/2 既有记录，按任务号排序选择前 10 个：依赖无未解析引用、存在短入口状态依赖权衡、正常输出没有已知参考冲突。固定 source 为 path_0，故障前动作与历史固定，不允许策略改变先前入口。不会因本轮结果换任务。

## 成本和理论判据

每次顶层工具尝试 1 请求单位，包括失败；P2 一次无效重试 F=1。低/高诊断价格固定为 0.25/0.75，每次调用收费，重复诊断也收费。起点之前及首次故障是公共沉没项，计入总账但恢复成本另列。各策略同样最多 32 次底层调用、8 个决策动作，同样诊断接口，种子 0，无模型所以模型名/版本不适用。

两状态各一条成对轨迹，比较时权重各 1/2，不把这当作原 Benchmark 的自然先验。未诊断前公开 p=1/2 和动作报价 R/S/F；报价不依赖实际模式，不包含路径或参考值。

直接切换成本 S；重试失败后切换的期望成本为 (R+1+S)/2；理想知情参照为 (R+S)/2。因此最佳无诊断完整恢复策略与完美知情参照的差为 min((S-R)/2, 1/2)，所有选中任务为 0.5。总是诊断的预期净收益低价 +0.25、高价 -0.25；价格感知的固定规则应低价诊断、高价选择最佳无诊断动作。无诊断成本相等时选直接切换。

此收益是受控请求成本和准确诊断假设下的构造性预测，不是对真实工具费用或学习算法贡献的实证结论。若实际参数绑定、合法完成或成本导致该正收益不成立，保存失败并停止，不调价、不换任务。

## 实施与检查

1. 环境：原始引擎只在内存实例中运行；初始 P1/P2 公共视图逐字相同，私有审计保留模式和原错误。动作宏按已确认模板绑定展开，源数据取自任务用户字段及先前真实有效返回，不用参考输出替代实际工具。诊断信息只经付费结果进入公共视图。
2. 验证：原生 Judge 与独立子集验证分开报告。独立验证核对路径节点、参数来源、执行先后和返回重放；必须拒绝跳步、错值、伪造返回、跨实体参数及使用错误来源。`tests/test_no_leakage.py` 必须通过。验证测试是 MVP 的必要实现，不修改原 Judge。
3. 单任务端到端先用 018、低高两价及两状态，先确认成本、评分和隔离，再运行全 10 个任务。
4. 固定策略：仅重试一次后停止（P2 失败负对照）、直接切换、重试失败才切换、总是诊断、按价格选择诊断/最佳无诊断、独立理想知情参照。成功率及成本分别报告；失败负对照不能因花费少被当作优胜策略。
5. 主对照：10×2 模式×2 价格×6 策略=240 条确定性轨迹。原始错误对照额外运行 10×2×3 个无诊断策略，共 60 条，不应用统一错误；同一固定入口及合法展开，不能称为全量原始模型基准。
6. 每阶段配置、提交、种子、完整底层轨迹、全部公共策略输入、诊断调用、收费明细、原生及独立评价保存至全新 `results/<run_id>/`；所有失败保留。记录原始文件/工具源码哈希，确认未变。仅云端 .venv，使用标准库 unittest。

完成四项证据：首次观测不可区分；P1 重试/P2 切换的最佳动作不同；诊断可选且每次收费；正确轨迹通过而关键反例被独立评分拒绝。实验后仅报告观察与条件性解释，不自动升级为模型实验。
