# 实验 028 · Gate 26 ToolMaze 恢复环境与方法接入

2026-11-10。探索性工程验收，见[ADR-0026](../adr/0026-toolmaze-recovery-integration.md)和[实验 027](027-toolmaze-agent-recovery.md)。

## 预登记

- **假设。** 复用原生 Agent、工具调用和严格验收，可以在真实依赖链上接入只读诊断与多种恢复方法。竞争解释为模板偷渡、诊断泄露未来、写入遗漏、统计覆盖虚高或组间接口不一致。
- **样本与划分。** C3-002 为已知工程与训练回放样例。C3-055 为任务迁移候选，C3-005 为 IoT 契约和诊断工程候选。训练回放仅从 C3-002 正常、暂态、持续和明确阻断夹具生成。每一恢复首动作接同一公开续程策略。双次暂态和设备离线为未见故障机制验收，所有候选与派生文件保留基础任务身份。跨轴重叠只作机制验收，从正式独立样本排除。此前设计的六个任务从确认性测试排除。
- **对照。** ReAct、共同合同的无历史、BTM、动作条件记忆、混合决策器、固定顺序、任务上下文、最近反馈、历史阈值、简单诊断规则。完整 BTM 提示另列。规则仅接管已注册恢复决策，后续执行共用原生 Agent。CPU 用已知合法序列和假 SDK 验证接口，结果不作方法效果。
- **可证伪标准。** 合法替代完成，错回执、缺失续程、重复写入及提前停止失败。诊断费用单列、实际清单可核验、同一连接状态可对应不同后续读取结果。相同公开前缀的 SDK 请求无故障、路径、测试标记和未来结果。新契约无历史时不得填造估值。所有 Gate 25 与原防泄漏测试回归。
- **冒烟上限。** CPU 通过后，仅尝试 C3-002 持续故障一回合，原生 Agent、已知任务、Qwen3-4B-Thinking-2507，最多 12 个 SDK 请求，每请求最多 4096 输出 Token，温度 0，种子 2601。使用既有 LabServer vLLM 配置。保存完整请求与响应、模型版本及失败。只作接口验收，无策略效果推断。

## 历史证据与方法边界

`History` 分别保留 BTM 的回合成功后验和动作条件值。BTM 按实际遇到的工具／错误与观察到的切换计数，同一键在每回合最多计一次。零样本的 0.5 是 Beta(1,1) 先验。核心 BTM 使用共同静态契约与动态统计，完整 BTM 独立参考另接原先重试、核验及升级条款。

$Q^\pi(h,a)$ 使用公开任务、失败序列、诊断反馈和剩余调用数作为可复核上下文，以指定首动作后的实际严格完成及分项费用估计。续程在工程回放中固定，外推仅来自相同公开失败形状和同一动作的训练回放。任务未见时直接支持数为 0。无适用历史的工具族返回空估值。受控训练样本仍属于同一个基础任务，不能据此估计泛化。混合组和规则组只决定当前恢复工具，原生 Agent 提交实参并完成后续。普通 ReAct、无历史、BTM 和动作记忆的自主组选用完整工具列表。规则尚未在独立验证池选优。

## Gate 26 后续验收预登记

- **问题。** 原冒烟在首错后看到了两类读写工具及真实超时反馈。原生工具描述没有说明同账户券商账本是否可作为合法备用，也没有说明归档工具只接受配对的回执类型。只补这个共享静态契约。竞争解释是模型即使拿到契约仍不能完成，或仅绕过故障而未演示恢复。
- **模型工程验收。** 仅用已知 C3-002，使用共同契约的无历史原生 Agent，持续故障一回合。从用户请求自主执行。仅在该回合严格完成并确实经历故障、切换及实际后续写入时，追加同任务暂态一回合。每回合至多 12 次请求，输出上限 6144 Token，温度 0、种子 2601，沿用 Qwen3-4B-Thinking-2507。SDK 原始 usage 按所有请求累加。保留旧负结果，不作正式方法或提示效果比较。
- **留出冻结。** 从只读工具名和 DAG 清点选定 C3-007/011（任务轴，已审计航班读取契约），C3-016/050/066/068（恢复契约轴，天气、市场、住宿族），C3-089（故障轴，航班读取合同下保留两次超时事件）。天气两例同组。候选基础任务、共享读取实现与故障事件各自成组，保留所有拒绝，不换样。排除此前已查看过任务正文的工程和设计样例。冻结后只读验收，候选的轨迹和实参不得用于修改方法、合同、历史或提示。
- **认证。** 复用原生工具和独立评分。要求两条静态路径的模板实参可由任务正文、公开工具默认值或实际前序回执提供。每个必要写入均须通过独立对象、参数、内容和次数校验。执行原生正常两路径、同首错暂态重试及持续切换；故障轴增加留出的两次超时，验证训练池无同事件或同基础任务。验收后人工检查正文与工具语义；证据不足计未认证。仅工程认证和分组审核，无留出模型请求。

这七题没有证据表明某项失败仅由模拟器漏记写入引起，也没有穷尽所有合法执行而证明整题不可恢复。原生输入字段与插件读字段直接冲突已有 C3-001 的独立例证。写入模拟缺口则在库存中另见，例如原生 `book_flight` 返回固定成功标识，代码中没有独立预订状态可供验收。参数来源、回执形状和效果记录可按工具族通查。什么内容算交付、替代能否满足用户指定字面量，仍需按义务做语义复核。

### C3-002 的 Agent 合同

- **可公平共享的接口知识。** 同账户、同类型且内容满足要求的余额回执可互换，两种原生对象各自对应可消费该类型的归档工具。可以公开回执类型、适用条件和真实参数限制。用户确实同时要求普通余额和完整记录。超时只能证明本次调用失败，禁止伪造回执属于通用规则。
- **依赖具体任务或带有路径提示的说明。** 指定普通余额必须走哪个工具、必须先于完整记录，逐字段给出归档到邮件再到会议的模板绑定，以及在超时后要求检查特定备用接口，都降低了模型自行组织续程或选择恢复动作的难度。原任务要求发送归档状态及安排与 Alice 的会议，但没有写出邮件主题必须取自归档回执、会议参数必须从邮件回执取得。当前 `BALANCE_RECOVERY` 只在 002 注入，且明确标出两个恢复入口。一次已知样例成功只能验收接口，无法证明这套说明可迁移。

扩展中，义务写进用户任务，稳定的回执类型和兼容条件写进工具文档。共同组共享同一合同、价格与合法权限。凡业务本身要求具体依赖，就公开其含义。执行顺序、备用首选和逐步参考绑定保留在私有验收侧，除非它们本身就是公开义务。原始 ReAct 与完整 BTM 提示继续单列参照。

### A/B 路线与建议

| 维度 | A · 原生任务加通用校验 | B · 独立 ToolMaze-Recovery 扩展 |
| --- | --- | --- |
| 工程成本 | 起步可沿用 70 个优先复核对象的静态结构。通用参数检查与若干共享写入可复用，历史任务的语义歧义和复合效果仍需逐族核对。 | 前置成本是为少量新任务定义公开合同、模拟状态和私有完成谓词。复用原生 Agent、工具注册与调用协议、故障注入、账本和方法适配。优先复用有可验收状态的插件。 |
| 泛化与诊断 | 原生多样性有迁移价值，但共享实现会缩小独立契约池。已有查询有时只是必做读取，缺合适接口时无法测试付费诊断。 | 按基础任务、等价／共享恢复实现和基础故障事件分别留出。优先复用合法状态查询。只报告当前可观察证据，同一证据允许不同后续结果，显式诊断单独计费。 |
| Agent 职责与偏差 | 保留原生语义，也可能把文案缺失、插件默认值或隐藏模板惯例误记为恢复失败。 | LLM 根据自然语言、工具合同和在线回执自主选诊断、重试、切换或停止，并绑定实参、完成后续。统一合同可能过于规整，需用未见工具形状和不同义务控制模板捷径，不能按某个方法获胜筛任务。 |

**建议以 B 为主线，A 用于兼容性和外部复核。** ToolMaze 提供执行基础设施和真实依赖的参考。扩展任务独立标识，围绕剩余义务设计，按对象、内容、来源、次数和实际模拟状态验收，允许所有满足义务的合法续程。执行器只校验、记账和评分。保留 BTM、Action-Conditioned Memory、强规则、混合对照及现有诊断机制。训练历史只来自训练侧，留出按三轴独立核验，固定规则表现好也保留。

本轮结论是工程方向 Go，正式方法比较仍暂缓。后续准入证据包括三类严格认证的独立留出、可证阻断、合法诊断和已知工程样例之外的自主完整执行；确认性留出与验收样例分开。C3-089 仍是既有唯一认证留出。路线 B 尚未实现，本轮不冻结新实验或分配正式样本。
