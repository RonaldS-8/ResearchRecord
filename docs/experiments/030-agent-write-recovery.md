## 运行预登记

**假设与竞争解释。** 原生 ReAct 能在相同写入超时后理解非幂等合同，主动取得授权状态证据，并据实际查询结果完成不同续程。竞争解释为盲重试造成重复、查错状态或参数绑定失误、无证据停止、参考前缀暗示恢复路径或完整启动未实际遇错。成功和失败均作行为观察，未预设查询必然发生。

**固定样本。** 复用 `stock-write-recovery`，与 Gate 27 库存样例同一开发谱系。两种故障各运行一次固定检查点恢复和一次自然语言完整回合，共 4 回合。顺序为检查点未提交、检查点已提交、完整未提交、完整已提交。无按结果追加回合。

检查点前缀固定为真实 `get_depot_inventory(sku=P-140)`，再用其实际凭据调用 `reserve_stock`，预留 3 单位、请求号 HOLD-2702。前缀使用相同的公开读取引用 ID。已提交一侧的实际预留 ID 不公开。两次写入均返回同一超时文本。保存当前状态和原生 SDK 首请求，逐字段及哈希核验公开前缀相同。脚本只产生前缀，不生成诊断或参考续程。完整启动从相同用户请求开始，选择入口、写入与后续均由模型决定，分别记录有无实际触发写入超时。

**模型与预算。** Qwen3-4B-Thinking-2507，下载修订 `768f209d9ea81521153ed38c47d515654e938aea`，原生 ReAct，温度 0、种子 2801。沿用既有 vLLM 服务配置，每回合最多 12 次 SDK 请求、每次 6144 输出 Token，工具总预算 16，固定前缀占 2 次工具调用。核心上限 48 次 SDK 请求。保留 SDK 自动空响应重试的实际请求与 usage。服务、版本、配置、完整轨迹、失败和效果均在云端归档。

**验收与分析。** CPU 先核对检查点消息构建、无隐藏字段、两状态首请求相同、模型选择的实际调用才推进状态。原生 39 项测试回归。随后运行四回合，记录首个恢复动作、事务诊断和连接诊断、查询后的实际动作、未获得有效事务查询证据前的写入重试、重复效果、非法实参、缺后续复核、严格完成、终止以及工具费／诊断费、Token 和时延。检查点沉没执行费 2 单列，后续费用含恢复首动作。固定回放的行为不是模型选路证据。本组均可恢复，正确停止率标不适用，无证据停止作为失败。诊断之后的分支变化只能支持观察性解释，不能用这 1 个事件估计诊断的因果收益或泛化。

## 独立家族与接口审查

当前 `Task` 固定工单／库存字段，`completion_issues` 按这两族验收，尚非通用任务生成器。原生注册、调用、账本和诊断计费可复用。新增家族只增加必要的业务字段、插件与家族终态谓词，验收实际状态及回执图，不引入参考序列规划器。历史仍为空，四个开发任务及改写／派生事件均禁止进入确认性测试。

先登记基础义务、工具实现的传递依赖和故障事件父子谱系。按三轴分别建隔离清单，禁止基础任务或事件派生跨集合。任务轴共用已登记合同；工具轴隔离等价接口、共享后端与刷新链；故障轴隔离持续性、关联范围和反馈生成规则。同源仅可作为明确登记的非目标控制因素。两候选均只作开发方案，本轮不认证独立样本或生成测试集。

任务轴优先比较同一发布接口下不同的交付／审批义务。工具轴须为相同业务目标另写独立契约与后端实现，不能仅把发布家族与授权家族相互留出便声称单独检验工具变化。故障轴使用独立基础任务与事件，在已见合同下留出新的故障规律，并披露无法完全匹配的任务因素。当前四个开发任务及两个新家族方案尚不足以分配三类独立测试池。

## 下一阶段余量分析登记草案

在独立探索池冻结上述覆盖及各层抽样数量后，比较原生 ReAct、独立验证侧选定的最强规则和知情参照。规则候选保留固定顺序、最近反馈、上下文阈值与简单诊断，使用相同完整 LLM 续程，记录规则选择和模型实际执行分别是否正确。知情参照仅额外知道当前提交／可恢复状态，仍受合法工具、实际效果和预算约束，额外信息单列。对可复核小例只称知情可行参照，未经穷尽不得称最优上界。

写入规则池应包含先查询请求状态再按证据重试／复核的简单规则，以及按合同限制的安全重试。当前 Gate 26 干预接口只覆盖读故障，需先接通写入检查点并验证权限对等，才可进行这一比较。规则选择、模型绑参与完整续程分别评分。

按家族及故障分别报告检查点首动作、实参合法性、后续义务、严格完成和全部回合成本。配对同一事件与公共检查点，失败成本不删，共同成功子集另报；规则续程的 $Q^{\pi_{\mathrm{rule}}}$ 与模型续程的 $Q^{\pi_{\mathrm{Agent}}}$ 各自记录。用验证侧不一致率与成本差方差规划独立事件数及配对区间后再报预算。该草案不授权本轮方法或余量对比。强规则持平保留，Gate 21–23 的负结果继续约束方法扩张。

四次均实际触发写入超时。事务诊断和连接诊断均为 0，盲重试、重复预留、非法调用和成功后的重复读取也均为 0。每回合执行费为 2、诊断费为 0。固定检查点的执行费 2 全属脚本前缀，模型恢复费用为 0；完整回合的两次执行均由模型选择。未提交条件的实际预留数为 0，丢回执条件为 1，两种条件的实际预留复核数均为 0。四例均可恢复，正确停止率不适用，提前停止未计完成。没有共同成功子集可分析。

固定检查点两侧首请求哈希均为 `3d38a5ea5e70879fc2736388b8f16965243e83cc98e95b1d7a27bbd2a55b292f`，六个公开工具均包含授权请求查询。原始工具消息与实得回执逐条相符，未带隐藏提交状态或参考续程。两个完全相同的首请求在相同种子下仍产生不同措辞，不将措辞差异解释为识别了隐藏状态。全部响应正常结束，没有接口异常或长度截断。只用了 8 次模型请求，未补跑回合，服务已停止。

**诊断与错误归因。** 模型没有主动查询，因此尚无模型层面“查询后改变动作”的证据。可观察失败发生在合法写入超时后，模型跳过了公开诊断并停止。其故障前实参合法、实际写入状态与回执隔离通过 CPU 和请求复核，支持把本例定位为未探索合法恢复选项。模型没有尝试后续查询绑参或实际复核，故无法分辨工具理解、诊断选择和续程执行各自的能力上限，也不能单独归因于动作估值。四回合只覆盖一个开发事件谱系，查询、重试或切换的 Agent 动作价值均无直接样本。

**下一轮判断。** 执行、诊断接口、独立验收和失败归档工程通过；真实 Agent 自主写入恢复本批未通过。可继续按已冻结覆盖设计开发两候选家族的最小合同与 CPU 状态验收。开展探索性余量对比前，还需独立探索／验证分组、写入检查点规则接口与预算审核。优先验证简单的按请求查询规则能否帮助同一 LLM 完成实际续程，保留原生 ReAct 作为对照。正式 BTM 或动作价值方法比较继续暂缓。
