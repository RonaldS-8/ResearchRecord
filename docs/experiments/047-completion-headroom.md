# 实验 047 · 阶段 0：完成率维度的恢复余量（CPU）

2026-11-14，探索性、仅 CPU，分支 `completion-headroom`。用户授权直接开始阶段 0，与阶段 1（GPU，真实 Agent 失误性质）并行，两者共同作为决策点 D1 的输入。不运行 LLM/GPU，不改冻结实验、执行器与评分。Q2 科学问题不变。

**读数须知。** 本文的“公共最优”“Oracle”“固定顺序”都是 CPU 宏观模型内的参照值，不是 Agent 表现。

## 1. 问题

实验 040/041 已证明成本维度的余量有上界：相对较好固定规则最多省 25%，现实参数下为个位数；多路径上下文余量中位数 2.1%，M4 为 1.5%。这些模型里失败只多花一次调用，不会让任务变得不可完成。

本实验问：**当错误动作有不可逆后果时（写入已生效但回执丢失，盲目重写导致重复发布），读取合法信息的最优策略相对最强简单规则，在严格完成率上的差距有多大？**

## 2. 模型

代码 `extensions/toolmaze_recovery/completion_headroom.py`。第一次写入以模糊失败结束（超时等），之后剩 L 次调用。

- 隐藏状态：已生效次数 n∈{0,1,2}，写入器状态 w∈{T 暂态, P 主写入器持续故障, S 共享后端故障}。初始以概率 q_C 为“已生效、回执丢失”（n=1, w=T），否则 n=0，w 按 (T,P,S) 比例抽取。
- 动作：
  - 重写（主写入器，费 1，占 1 次调用）：w=T 时以 p_t 生效并返回回执；否则以 c_lost 生效但回执丢失，其余不生效，均返回 fail。w∈{P,S} 时不生效、返回 fail。
  - 切换（备用写入器，费 2，占 1 次调用）：w=S 时不生效、返回 fail，否则生效并返回回执。
  - 回读（显式诊断，费 d，占 1 次调用）：n≥1 时以概率 a 返回 found，n=0 时以概率 1−a 返回 found。
  - 完成（宣告完成，免费）；停止（上报，免费）。
- 收到回执后自动宣告完成。严格完成当且仅当以“完成”结束且 n=1。已生效后再写入使 n=2，不可挽回。
- 首次失败附带公开细节 timeout/error，P(timeout | 类别) 的信息量分三档：无（均 0.5）、弱（C 0.7、T 0.5、P/S 0.4）、强（C 0.95、T 0.5、P/S 0.2）。业务含义：服务端明确报错时通常未写入，超时才可能写入后丢回执。

## 3. 比较对象

- **Oracle**：知道初始隐藏状态，不知道后续随机结果。仅作参照，不可由合法方法达到。
- **公共最优（OPT）**：只读公开细节和所有回执，按字典序（先严格完成率，再期望费用）精确求解。
- **逐上下文最强固定顺序（FIX-X，主比较对象）**：对每个首次细节分别选一条固定动作序列（重写/切换/回读，长度不超过 L，末尾为完成或停止）；收到回执或回读 found 即宣告完成。在真实模型上选最好的一条，对规则有利。
- **最强固定顺序（FIX）**：同上但不读细节。
- **命名规则**：不回读的“重写后切换”；“先回读，not found 再重写后切换”。

比较值为 OPT − FIX-X 的严格完成率差（百分点），同时报告 Oracle − OPT 和费用差。

## 4. 网格（事先固定，不按结果调整）

L∈{3,4,6}；q_C∈{0.1,0.3,0.5}；(T,P,S)∈{(0.6,0.3,0.1),(0.3,0.5,0.2),(0.2,0.4,0.4)}；p_t∈{0.5,0.8}；c_lost∈{0,0.3}；a∈{1,0.9,0.7}；d∈{0.1,0.5,1}；细节信息量∈{无,弱,强}。共 2916 格。

## 5. 假设、竞争解释与判据

- **H0（预期）**：与 040/041 相同，逐上下文固定顺序在几乎所有格上达到公共最优；完成率差距主要存在于“不回读”的天真规则与最优之间，一条“先回读”的简单规则即可补上。
- **H1**：回读有噪声且预算紧张时，最优策略需根据回读与写入结果自适应，固定顺序在严格完成率上明显落后。
- **竞争解释**：①差距只来自 Oracle 掌握而合法信息拿不到的部分（看 Oracle − OPT）；②差距集中在单一极端参数（看各参数边际分布）；③稍复杂的反应式规则即可补上（仅在出现差距时作为后续检查，另行记录）。

| 结论 | 条件 |
| --- | --- |
| 有余量 | OPT − FIX-X ≥ 10 个百分点的格占比 ≥ 10% |
| 无余量 | 全网格 OPT − FIX-X 最大值 < 5 个百分点 |
| 局部余量 | 介于两者之间，报告所在参数区域 |

完成率差小于 1e-9 视为相等。另报告每格 Oracle − OPT 与 OPT − 不回读规则，用于说明余量来源。

## 6. 验证

测试 `tests/test_completion_headroom.py`：①闭式手算格（a=1、单状态等）与精确值一致；②OPT ≥ FIX-X ≥ FIX、Oracle ≥ OPT 在全网格成立；③策略只读公开视图；④变异检查（例如让回读泄漏真实状态、让重复写入不计失败）必须被测试抓到。

## 7. 结果

登记 `4256439`；模型与运行 `819ba87`（2916 格，本地 Python 3.14，约 97 秒）；后续检查 `ba89594`。测试 11 项通过；两种变异（回读泄漏真实状态、重复写入计为成功）均被抓到。逐格结果留本地 `results/047-completion-headroom-01/`，摘要见 [summary.json](../evidence/047/summary.json) 与 [followup-vote.json](../evidence/047/followup-vote.json)。

### 7.1 登记比较：局部余量

| 差值（严格完成率，百分点） | 中位数 | 90% 分位 | 最大 | ≥5 的格 | ≥10 的格 |
| --- | ---: | ---: | ---: | ---: | ---: |
| OPT − FIX-X（主比较） | 1.7 | 6.8 | 12.7 | 23.5% | 2.9% |
| Oracle − OPT | 2.2 | 15.6 | 27.5 | 38.3% | 20.6% |
| OPT − 不回读“重写后切换” | 28.1 | 50.0 | 54.5 | 92.0% | 78.9% |
| OPT − “先回读” | 6.5 | 16.1 | 27.0 | 60.0% | 28.3% |
| OPT − 禁止回读的最优 | 12.6 | 30.0 | 45.0 | 86.0% | 61.7% |

按第 5 节判据为**局部余量**（≥10 个百分点的格占 2.9% < 10%，最大值 12.7 ≥ 5）。完成率持平的 1140 格里，OPT 与 FIX-X 的费用差最大为 2e-16，即为零。

余量来源（参数边际）：
- **只出现在回读有噪声时**：accuracy=1 时全部为 0；0.9 时最大 8.5；0.7 时最大 12.7。
- **随预算增加**：L=3、4、6 的最大值分别为 6.9、7.8、12.7，≥10 的格全部在 L=6。
- **首次细节越有信息量越小**：无/弱/强 的最大值为 12.7、10.6、6.8。
- **p_retry、c_lost、read_fee 对余量没有影响。** 原因是本模型的备用写入器除共享故障外必成，按先比完成率的字典序，切换总不劣于重试主写入器，重试从未被选中；回读费用只影响费用，不影响完成率比较。这是模型结构的后果，与实验 041 指出的“必成备用”结构相同，属于本实验的局限。

### 7.2 后续检查（竞争解释③，事后追加，非登记判据）

固定顺序规则第一次读到 found 就宣告完成，而噪声回读下最优策略会多读几次。追加一条同样简单的规则：每个上下文“回读 k 次，至少 m 次 found 则完成，否则按固定顺序写入”，与 FIX-X 逐上下文取较好者。

结果：**全部 2916 格 OPT − 最强简单规则 = 0**（最大 1e-14）。典型规则形如“回读两次，两次都 found 才完成，否则切换后完成”。

### 7.3 结论

- **观察**：不可逆副作用确实带来很大的完成率差距，但差距在“读不读”上，不在“怎么读”上：不回读的规则比最优低中位数 28 个百分点；只要会回读，固定顺序加投票的简单规则在全网格达到公共最优。
- **解释**：Oracle − OPT 最大 27.5 个百分点，说明剩余差距来自合法信息拿不到的部分（回读精度上限），不是策略能补的。
- **对 D1 的含义**：完成率维度与 040/041 的成本维度结论一致——在这类宏观模型里，读对一两个公开信号的简单规则等于公共最优。阶段 0 判为**方法余量不足**；有价值的是“避免不回读就重写”这一类失误，它由简单规则解决。
- **局限**：只覆盖单次模糊写入、必成备用、对称噪声回读；没有模型化多步依赖、回读本身可能失败或延迟、以及 LLM 不遵从规则。这些是 Agent 层面的问题，归阶段 1 回答。

## 8. 第二轮登记：去掉第一轮的结构局限

2026-11-14，运行前登记。用户要求处理第一轮局限。第一轮结果与判据不改；本轮是独立的第二轮网格。

### 8.1 模型扩展（默认值与第一轮完全相同）

- **备用不必成**：备用写入器在 w≠S 时以 p_switch 成功；失败时同样以 c_lost 静默生效（回执丢失）。
- **多步依赖**：备用路线需要 backup_calls 次调用（2 表示 prepare→confirm，与 M4 相同），在最后一步才生效，费用 2 不变；预算不足以走完时不可选。
- **回读本身可能失败**：每次回读以 read_fail 返回 error，不含状态信息，照常收费并占用调用。
- **非对称噪声（复制延迟）**：read_noise=lag 时，已生效的写入以 a 被读到，未生效的写入永远不会被读成 found；symmetric 同第一轮。
- **规则对回读 error 的处理**：固定顺序与投票规则都把 error 当作未读到，继续下一步；最优策略可分别处理 error 与 missing。

### 8.2 比较对象

主比较对象改为第一轮已确立的**最强简单规则类**：逐上下文取“固定顺序”与“回读 k 次投票”中较好者（FIX-V）。比较值为 OPT − FIX-V。另报告 OPT − FIX-X、Oracle − OPT 与 OPT − 禁止回读的最优。

### 8.3 网格
