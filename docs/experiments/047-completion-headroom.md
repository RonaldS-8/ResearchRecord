# 实验 047 · 阶段 0：完成率维度的恢复余量（CPU）

2026-11-14，探索性、仅 CPU，分支 `completion-headroom`。用户授权直接开始阶段 0，与阶段 1（GPU，真实 Agent 失误性质）并行，两者共同作为决策点 D1 的输入。不运行 LLM/GPU，不改冻结实验、执行器与评分。Q2 科学问题不变。

**读数须知。** 本文的“公共最优”“Oracle”“固定顺序”都是 CPU 宏观模型内的参照值，不是 Agent 表现。

## 1. 问题

实验 040/041 已证明成本维度的余量有上界：相对较好固定规则最多省 25%，现实参数下为个位数；多路径上下文余量中位数 2.1%，M4 为 1.5%。这些模型里失败只多花一次调用，不会让任务变得不可完成。

本实验问：**当错误动作有不可逆后果时（写入已生效但回执丢失，盲目重写导致重复发布），读取合法信息的最优策略相对最强简单规则，在严格完成率上的差距有多大？**

## 2. 模型

代码 `extensions/toolmaze_recovery/completion_headroom.py`。第一次写入以模糊失败结束（超时等），之后剩 L 次调用。

- 隐藏状态：已生效次数 n∈{0,1,2}，写入器状态 w∈{T 暂态, P 主写入器持续故障, S 共享后端故障}。初始以概率 q_C 为“已生效、回执丢失”（n=1, w=T），否则 n=0，w 按 (T,P,S) 比例抽取。
- 动作：
  - 重写（主写入器，费 1，占 1 次调用）：w=T 时以 p_t 生效并返回回执；否则以 c_lost 生效但回执丢失，其余不生效，均返回 fail。w∈{P,S} 时不生效、返回 fail。
  - 切换（备用写入器，费 2，占 1 次调用）：w=S 时不生效、返回 fail，否则生效并返回回执。
  - 回读（显式诊断，费 d，占 1 次调用）：n≥1 时以概率 a 返回 found，n=0 时以概率 1−a 返回 found。
  - 完成（宣告完成，免费）；停止（上报，免费）。
- 收到回执后自动宣告完成。严格完成当且仅当以“完成”结束且 n=1。已生效后再写入使 n=2，不可挽回。
- 首次失败附带公开细节 timeout/error，P(timeout | 类别) 的信息量分三档：无（均 0.5）、弱（C 0.7、T 0.5、P/S 0.4）、强（C 0.95、T 0.5、P/S 0.2）。业务含义：服务端明确报错时通常未写入，超时才可能写入后丢回执。

## 3. 比较对象

- **Oracle**：知道初始隐藏状态，不知道后续随机结果。仅作参照，不可由合法方法达到。
- **公共最优（OPT）**：只读公开细节和所有回执，按字典序（先严格完成率，再期望费用）精确求解。
- **逐上下文最强固定顺序（FIX-X，主比较对象）**：对每个首次细节分别选一条固定动作序列（重写/切换/回读，长度不超过 L，末尾为完成或停止）；收到回执或回读 found 即宣告完成。在真实模型上选最好的一条，对规则有利。
- **最强固定顺序（FIX）**：同上但不读细节。
- **命名规则**：不回读的“重写后切换”；“先回读，not found 再重写后切换”。

比较值为 OPT − FIX-X 的严格完成率差（百分点），同时报告 Oracle − OPT 和费用差。

## 4. 网格（事先固定，不按结果调整）

L∈{3,4,6}；q_C∈{0.1,0.3,0.5}；(T,P,S)∈{(0.6,0.3,0.1),(0.3,0.5,0.2),(0.2,0.4,0.4)}；p_t∈{0.5,0.8}；c_lost∈{0,0.3}；a∈{1,0.9,0.7}；d∈{0.1,0.5,1}；细节信息量∈{无,弱,强}。共 2916 格。

## 5. 假设、竞争解释与判据

- **H0（预期）**：与 040/041 相同，逐上下文固定顺序在几乎所有格上达到公共最优；完成率差距主要存在于“不回读”的天真规则与最优之间，一条“先回读”的简单规则即可补上。
- **H1**：回读有噪声且预算紧张时，最优策略需根据回读与写入结果自适应，固定顺序在严格完成率上明显落后。
- **竞争解释**：①差距只来自 Oracle 掌握而合法信息拿不到的部分（看 Oracle − OPT）；②差距集中在单一极端参数（看各参数边际分布）；③稍复杂的反应式规则即可补上（仅在出现差距时作为后续检查，另行记录）。

| 结论 | 条件 |
| --- | --- |
| 有余量 | OPT − FIX-X ≥ 10 个百分点的格占比 ≥ 10% |
| 无余量 | 全网格 OPT − FIX-X 最大值 < 5 个百分点 |
| 局部余量 | 介于两者之间，报告所在参数区域 |

完成率差小于 1e-9 视为相等。另报告每格 Oracle − OPT 与 OPT − 不回读规则，用于说明余量来源。

## 6. 验证

测试 `tests/test_completion_headroom.py`：①闭式手算格（a=1、单状态等）与精确值一致；②OPT ≥ FIX-X ≥ FIX、Oracle ≥ OPT 在全网格成立；③策略只读公开视图；④变异检查（例如让回读泄漏真实状态、让重复写入不计失败）必须被测试抓到。
