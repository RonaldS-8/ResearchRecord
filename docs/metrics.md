# 指标与计价草案——待用户确认

本文件为用户要求的草案，尚未批准，不是当前生效计价规则。Gate 1 使用的是逐工具调用记录和符号表达式，没有据此设置价格、重算或优化实验结果。正式比较前须确认以下定义及参数。

## 分开报告的四项指标

| 指标 | 建议定义 | 尚需确认 |
| --- | --- | --- |
| 任务成功率 | 沿用对应 Benchmark 的原生判定，分别报告模式及分母；保存判定明细。 | C2 当前主要检查成功工具覆盖，是否另需语义正确验证；不能把两者混为一谈。 |
| 正确停止率 | 在真值明确不可恢复的任务中，合理主动终止的比例；单列误停止可恢复任务。 | 不可恢复真值和合理停止的具体判定规范。分母为 0 时记“不适用”，不记 0 或 100%。 |
| 实际成本 | 逐项报告工具、诊断、模型资源消耗；价格未定时保存次数与 token，不合成价格。 | 每种调用的价格、失败是否收费、诊断价格、模型资源如何换算。 |
| 恢复冗余 | 对已完成恢复的轨迹，建议报告实际恢复调用数减去同一故障状态下合法最少恢复调用数。失败恢复单列，不强行赋值。 | 是否采用调用次数差作为正式定义；合法最少路径及参数可得性的约束。 |

四项指标不合成单一分数。审计中的“规则分类准确率”和“按调用数比较动作”不替代上述研究指标。

## 成本的符号记法

- `n_t`：工具 t 的调用次数；`c_t`：其单次价格。建议成功和失败调用都计入，但收费方式须确认。
- `n_d`、`c_d`：诊断次数及单次价格。当前没有诊断工具，不指定价格。
- `C_model`：模型调用成本；在价格未确定时，输入/输出 token 和调用次数单列记录，不臆测金额。
- 待确认的表达式：`C_actual = Σ_t n_t c_t + n_d c_d + C_model`。延迟和实际运行时间单列，不自动与货币成本相加。
- 不默认所有工具等价，也不因为某条路径更利于诊断就设置差异价格。
- 复合工具内部会调用多个插件；须确认 `c_t` 是否已经包括这些内部工作，避免仅因顶层调用被合并就把同样工作视为更便宜。本轮保存的是 Benchmark 顶层调用数。

## 恢复区间与理想知情参照

建议统一保存三个计数：首次失败之后的调用数、包含首次失败的恢复调用数、任务总调用数。Benchmark 现有恢复计数包含首次故障；Gate 1 的主要动作比较从首次失败之后开始，首次失败及此前调用是公共沉没项。两种口径均保留，不混用。

建议恢复冗余采用包含首次故障的区间：`R_calls = N_actual_recovery - N_min_recovery`。参照允许知道真实故障状态，独立标记为理想知情参照，不能将这些信息传给被评估策略。若出现负差值，应审计最少路径定义，不截断或静默改为 0；失败轨迹不伪装成有效的最少路径比较。

Gate 1 的符号比较：令 S 为直接切换的后续工具成本，R 为 P1 重试成功并完成任务的成本，F 为 P2 一次无效重试的成本。则直接切换为 `(S_P1, S_P2)`；重试失败才切换为 `(R, F+S_P2)`；理想知情参照为 `(min(R,S_P1), S_P2)`。只在两模式下切换实际调用相同且计价相同时，才能进一步写成同一个 S。

## 确认后才能运行的事项

确认指标定义、收费范围与具体参数，再提交并登记实验。当前草案不授权新增诊断接口、修改评测代码、扩大研究范围或开展策略实验；恢复冗余与正确停止仍须实现并验证后才能报告为正式指标。
