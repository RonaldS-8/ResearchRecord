# Gate 9 · Action-Conditioned Recovery Benchmark 设计

状态为已批准的最小 MVP 设计。科研问题固定为历史任务恢复统计是否足以支持具体恢复动作选择，以及动作条件经验与当前反馈能否改善成本敏感恢复。先验证可识别的最小情形，再判断是否存在超出简单规则的研究空间。

## 最小反例

从同一工具和同一原始错误后的合法检查点开始。公开上下文 x 是故障前已获得的业务属性，例如服务区域；它可预测恢复概率，但不直接显示当前故障状态。两个上下文等权。故障状态 Z 在起点抽取，x=A 时 P(Z=可恢复)=3/4，x=B 时为 1/4。首错对两种状态完全相同。预算允许一次重试和一次切换，两个动作均有合法参数和可验收的任务完成路径。

| 首动作与后续规则 | 状态转移及符号成本 | 严格完成概率 |
|---|---|---|
| 切换 S | 支付 s=2，进入合法完成 | 1 |
| 重试 R，失败后切换 | 支付 r=1；可恢复时完成，否则收到失败反馈，耗尽重试权限，再以 s=2 切换完成 | 1 |
| 重试 R，失败后停止 | 支付 r=1；可恢复时完成，否则终止未完成 | p(x) |
| 停止 | 终止未完成，无额外调用 | 0 |

数值为手算用的抽象费用，从首错之后计，失败调用照常收费。动作价值用二元组（完成概率、期望后续费用）表示；在同完成率时比较费用。固定失败后切换的后续规则下，Q(S)=(1,2)，Q(R)=(1,1+2(1−p))。A 的重试费用为 1.5，优于切换的 2；B 的重试费用为 2.5，切换优于重试。一般阈值为 p>r/s，等号保留并列。

若历史行为策略总是重试失败后切换，两个上下文最终恢复率均为 1，且聚合到同一工具／错误项仍为 1。历史中实际发生的切换也全部完成。对调 A/B 的 p，任务恢复率、聚合切换率乃至等权下切换频次都不变，但最优首动作对调。只使用这些汇总的策略无法识别两种机制。原分布下任何忽略 x、两处用同一随机首动作规则的全完成策略，期望成本为 2；条件阈值达到 1.75。历史轨迹里的单次重试结果若可按 x 提取，则已经提供动作条件经验。

## 当前反馈与强基线

经验主对照固定相同的公开成本与任务，比较只增加任务恢复率、再增加按上下文和首动作记录的结局与费用。反馈检查使用同一机制的独立校验格 p=1/2。若启用付费诊断 D，提供对称准确率 4/5 的二元信号，成本 d=0.1，状态不变。两种信号各半，后验为 0.8 或 0.2。高信号选重试再按失败反馈切换，低信号直接切换，总期望费用为 0.1+(1.4+2)/2=1.8，对照无诊断的 2。一般此格在 d<0.3 时节省成本；保留等价、过贵与无信息信号。诊断收费单列，失败重试的反馈归执行反馈。这里的数字只用于校验推导，不作为正式计价。

- 固定仅重试在失败状态丢失完成率。固定先重试、失败后切换和直接切换均能保证完成，在等权反例中均花费 2。
- 仅以失败重试位记忆的策略在首步两处同值。允许 One-bit Memory 同时使用公开上下文和价格，公平地提供其上下文版；它配合正确的首步规则可达到最优。
- 使用上下文经验的成本阈值可以解反例。若它还能用合法信号更新概率，也可以解反馈校验格。公开路径和费用有差异时，另允许简单规则直接从这些信息决策，避免将可直接推导的收益归给经验。
- 完整 BTM 提供工具／错误后验、切换后验、替代工具与粒度说明及恢复约束，由模型读提示决定动作。论文模板的至少重试一次约束在 B 中有成本；单独报告该约束的影响，保留完整提示基线，再用明确标记的去约束消融区分统计与提示效应。若模型严格遵守至少重试一次的约束，就无法在 B 实现直接切换；消融版若能从合法上下文或共有经验推得阈值，则可以达到最优。完整 BTM 使用独立历史集，分别记录冻结版与在线版；在线版只在回合结束后按冻结顺序更新。规则 MVP 只校验统计与输入，不能据此宣称完整 BTM 表现。作者实现仍待核验。[Bench2Robust §3.1 与附录 B.1](https://arxiv.org/html/2608.11977v2#S3.SS1)

## 数据、配对和完成验证

1. 复用 Gate 3 的 018/032 两路径结构、参数绑定和评分反例，复用 Gate 6 的故障前缀与可见消息核对。旧案例仅作开发与验收。生成器由版本化任务模板、公开上下文、故障转移与报价配置、种子产生实例。公开属性需来自任务或合法返回，名字和顺序不编码 Z。除反转格外，保留两侧同一最优、并列、无信息和诊断过贵的对照。原生样本与自建样本分列。
2. 先抽取任务、故障检查点和隐藏状态，再复制同一个起点给各首动作。固定后续规则和共同预算，随机数按实例及事件类型预分配，避免动作顺序改变共同随机量。每个分支单独重放并记录完成、实际账单及可见历史。评估器可见配对组与真值，策略只见任务、工具说明、价格、预算、实际历史及按该实验组授权的历史摘要。比较当前反馈时保持同一环境与可用动作，单独报告策略是否利用返回。Oracle 只作知情上界，不预见未来随机数。
3. 历史集用预先固定、各上下文均覆盖重试与切换的行为分配采集，存首动作与后续策略标识，记录分配概率。任务级恢复率与动作条件统计从同一批历史派生，便于公平对照。反例里的全恢复历史只用于证明信息不足。按任务模板家族划分开发、历史训练和测试，连同同一实例的配对、价格格和故障变体一起分组，隔离近重复。测试只继承预先定义的可见属性语义，不能使用测试结局反填训练统计。只有两个旧模板时仅做验收，不报告独立泛化。
4. 完成验证同时检查真实工具执行、参数来源与先后依赖、最终任务效果和账单。受信执行日志可用于核验，参考路径不可传入策略。复用 Gate 3 的独立验证和错参、跳步、伪造返回、非法复用反例，补充跨分支状态污染检查及新接口的隔离覆盖。原生 Judge 仅作为适用时的交叉检查。Gate 6 的参考路径回放仅作结构参照。[Gate 3 验证器](../extensions/toolmaze_diagnostic_mvp/verification.py) · [Gate 6 审计](experiments/008-c3-c4-recovery-audit.md) · [Gate 7 负结果](experiments/010-gate7-belief-ssp-pilot.md)

## MVP 和放行标准

**MVP 验收。** 一个旧任务结构、两种上下文、两种隐藏状态，穷举四个起点与每个起点的切换、重试失败后切换、仅重试和停止。先逐分支核对理论结局、费用及同一起点可见输入，再用一个等先验格核对付费反馈与无信息对照。全量分支须与手算一致，完成验证负例全部拒绝，隔离测试全部通过。阶段只需规则与枚举，可在现有云端环境中完成。无不可恢复样本时正确停止率记不适用。

**研究 Go。** 后续独立测试前冻结样本数、配置、划分、基线和配对判据。至少要求冻结测试中可复现动作反转，且合法经验或反馈在配对比较中不降低严格完成率，并降低预先指定的恢复费用。若工具费与诊断费使用同一获批计价单位，比较两者之和并同时分列；否则预登记分项取舍，避免把费用转移当作收益。分别给出差值与按模板分组的不确定性；工具费、诊断费、Token、延迟及冗余分开报告。要进入新方法开发，还需在同等公开信息下超过最强可执行简单基线。完整 BTM 缺席时明确限制结论。

**No-Go。** 无法通过隔离、配对或严格完成验证时停止并记录原因。若冻结测试没有合法反转，或上下文阈值、One-bit Memory 等已覆盖收益，则保留基准和负结果，停止该条件下的方法开发。参数由阈值两侧、边界和无差异对照确定，正式冻结前登记其来源；不根据模型结果删难例、换费用或缩小比较范围。探索修订保留旧版本，并用新留出集验证。

ToolMaze 提供路径拓扑与故障原型，Bench2Robust 提供可恢复性控制和 BTM 参照，Calibrate-Then-Act 提供付费信息获取参照。这里要验证的是共享历史统计项下，受控首动作、相同后续策略和严格完成证据能否识别决策差异。[ToolMaze](https://arxiv.org/abs/2606.05806) · [Bench2Robust](https://arxiv.org/abs/2608.11977) · [Calibrate-Then-Act](https://arxiv.org/abs/2602.16699)
