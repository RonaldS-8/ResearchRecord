# ADR-0034（提案）：复合预留的可观察库存投影

状态：**待用户审批，未实施**。2026-11-18。基础d916949。依据Gate058及用户Gate059A第4项“修复方案及其可能改变的 Benchmark 语义先提交审查，获批后实施”。

## 问题与源码证据

原生get_stock_level.py:62–75仅按顶层history里的hold_inventory/submit_order输出扣减库存；hold_best_recommendation.py:35–65直接调用推荐、选择、预留插件，其内部动作不经ToolExecutor.record。hold_inventory.py:106–115未实际修改模块库存或RESERVATIONS。058实测直接预留10→9，复合预留10→10；全部新context回10。原生预留重复返回同一reservation_id，且按初始静态stock验证quantity，而非当前剩余量。

本提案不是修复交易数据库，只统一**同一上下文中预留义务的get_stock_level可观察库存**。不声称所有270工具/复合动作/持久交易语义等价。

## 方案比较

| 方案 | 改变与风险 | 判断 |
|---|---|---|
| 给hold_best拆成3次公开工具调用 | 改变对Agent暴露的调用粒度、费用、历史及可能的故障时钟 | 不选 |
| monkeypatch所有内部插件调用、统一落库 | 并发/模块加载副作用；扩大交易语义和计费范围 | 不选 |
| 独立扩展执行器仅在get_stock_level时投影历史效果 | 只补齐指定宏预留的查询状态，不增公开动作或存储 | **建议批准此方案** |

## 精确实施边界（获批后）

新增extensions/execution_memory_059/adapter.py（计划路径），组合复用原生ToolExecutor及058公开schema加载逻辑；不编辑058代码或benchmarks/ToolMaze。

- 默认native模式完全委托原执行器；显式reservation_projection_v1模式仅拦截get_stock_level，其他工具原样执行。
- 查询时构造只供原生库存插件消费的临时history视图。保留原有直接预留/submit_order记录；每条成功的顶层hold_best_recommendation，以其实际返回的product_id、quantity和reservation_details映射成一条等效hold_inventory记录。原始context.history、工具调用trace、公开返回和调用数均不添改。临时记录是环境状态投影，不是Agent真的调用了该工具。
- 宏record被替换为等效记录，不能在同一投影视图同时保留两个可扣库存副本。真实重复顶层调用是不同事件，各扣一次；**不按固定reservation_id去重**。多次查询不写回history，故不会重复扣减。
- 使用实际返回的推荐商品，绝不使用原输入product_id冒充选中商品；quantity与回执嵌套字段须一致且为正整数。失败/缺字段/矛盾回执不能认证宏预留；未知或不支持的写入返回明确unsupported/unknown，不静默当作成功状态。
- 原生库存插件在临时视图算stock/status/low_stock_warning；不改推荐列表的静态stock、不改hold_inventory的成功条件、固定ID/时间、确认订单及付款行为。可观测库存降至0的截断规则保持原生行为。
- 每个候选用独立context；相同起点用深拷贝历史，禁止A/B间串状态。不修改插件模块全局变量；隔离保证仅限本轮使用的这些插件。
- 本版只认直接顶层hold_best；checkout_best_recommendation等更深宏含预留效果尚不支持。不能靠这版认证它们的状态。不添加取消、支付、过期、幂等键、服务数据库或新的故障注入。

### 将改变的Benchmark语义

相同顶层宏调用后，projection模式的库存查询将从原生不扣减变为按宏回执扣减；这是公开可观察行为变化，必须标ToolMaze扩展模式。原生模式、054–058和原Judge保留原状；只在059新增独立义务验收。

**仍存在的限制：** 原生hold会在剩余stock不足时返回success，get_stock_level再把负数截成0。这版不补库存拒绝规则、不伪造完整交易一致性。059B可以把它当作原有“成功回执不保证足量新增预留”的反例；不得称已修成生产库存系统。若审批认为这一限制使环境不可用，则本轮报告环境不足，停止扩大，不能自行再修一层追求正结果。

### 公平接口与计费

所有基线同一registry和projection开关、同工具公开合同。公开补充合同仅说明“本模式get_stock_level计入直接及指定复合预留，重复预留重复消耗，可通过合法查询获取当前量”；不暴露初始库存表、真值路径或故障状态。所有组同样能查询、更新普通缓存并使用公开返回。

查询仍计一次真实工具调用，投影计算单独记CPU耗时，虚拟效果记录不伪计工具调用。组合内部execute进入数与顶层调用数分列；展开与宏的调用成本不强行等同。环境初始状态及准备调用对每组对称，费用单列。原生/扩展同样本配对，不能只汇报扩展有利结果。
