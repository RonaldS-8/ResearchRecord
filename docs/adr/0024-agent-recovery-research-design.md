# ADR-0024 · 真实 Agent 工具故障恢复研究设计

- 日期：2026-11-10
- 状态：已批准可复用性审计与最小设计，实施待审
- 证据与基准设计：[实验 026](../experiments/026-agent-recovery-benchmark-audit.md)

## 研究问题与决策

**科学问题 Q2。** 工具故障已被发现、但原因或持续性等状态不完全可观测时，Agent 如何权衡信息获取价值、任务恢复收益与执行成本，选择显式诊断、重试、切换或停止，以兼顾任务完成质量与恢复效率？

**统一研究对象。** 在同一个可执行环境中评估固定权重 LLM Agent 从理解任务、调用工具、处理故障到验收结果的完整恢复行为。以同一任务的剩余执行义务连接四类机制。已有反馈影响对故障的判断，重试或切换改变可用回执、后续义务与执行成本，显式诊断只有在证据足以改善后续决策时才有价值，跨回合历史的支持度限制动作估值的可靠性。真实接口用来约束可观察反馈、替代语义和副作用。支付、预订与路线仅提供契约实例。

**职责边界。** Agent 从用户请求和工具文档判断哪些结果可替代，从结构化字段与自然语言回执解释当前状态，自主决定何时诊断、重试、切换或停止，并完成后续步骤。执行器共用契约验证、实参校验、权限和计费。语义解释、路径选择和续程由 Agent 自己完成。确定性解析与规划分别用于独立基线与离线分歧分析。

## 可证伪假设与最小方法

检验哪种恢复机制能在未见任务、工具契约或故障变化下稳定改善严格完成、正确停止或分项成本。候选解释包括任务上下文阈值或最近反馈已保留足够信息，诊断只改变信念或购买时机，以及历史估值在支持充分时有用、在局部缺样本时误排。按实验 026 的独立留出分别检验。简单规则若能稳定迁移，其适用条件同样是研究结果。

先用任务契约、可用回执和当前报价，比较 ReAct、完整 BTM 与强规则。需要估值时，先提供当前合法动作在规定续程下的严格完成概率、剩余工具费与诊断费，并标注直接支持数、外推和验证误差。BTM 保留其回合后验、切换映射和约束。用共同提示分离提示效果与统计目标的差异。若排序受估值误差影响，再比较有无支持度提示或预先验证的简单回退规则。信息价值用同起点的查询与执行分支核验，计入查询费用和延迟。贝叶斯更新、外挂决策器和多步规划均为开放选项。

## 最小工程范围与放行

- **环境准入。** 选 ToolMaze 的完整 Agent 循环、工具定义和插件作为执行底座，借用 Gate 19–23 的证据记录、分叉、分项账本和基线。首批只在读／准备环节注入故障，保留下游写入义务。另建独立终态验收与诊断证据边界。候选须证明合法替代、可重放前缀及错误绑定、缺失义务和重复副作用的可检出性。已有 `tests/test_no_leakage.py` 作为回归要求，新环境另验收其实际模型请求。保留 ToolMaze 原生参照。
- **评估准入。** 运行前冻结任务与契约版本、历史池、独立留出、强基线、费用口径和最小有意义差异。先看端到端表现，再以同起点、同外生事件、统一续程的合法分支定位差异。评估使用的终态、参考路径与未来事件均留在执行器和评分侧。
- **Go / No-Go。** 设计可进入工程可行性审议。联合诊断试点须先确认合法、付费且可能改变续程的取证接口；否则保留已覆盖的比较并标明诊断缺口。根据预登记的分项标准判断各方法能否跨留出迁移。固定规则、上下文阈值、完整 BTM 或确定性解析若已覆盖收益，研究可继续验证其适用边界。复杂方法升级须有独立留出的增量证据。开发与运行另行确认。
