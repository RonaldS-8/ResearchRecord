# ADR-0001：单仓库与单端修改后同步

- 日期：2026-11-02
- 状态：已接受

## 背景与问题

云端项目原有 ToolMaze、ToolMaze/git-data、CostBench 三个独立 Git 仓库，本地只有协作说明。用户要求删除旧 Git、新建整个项目的版本管理，同时禁止权重和数据下载到本地，并要求每次只修改一端，减少重复工作。

## 决策

1. 本地 `Master_thesis/` 对应云端 `/home/ubuntu/Song/Agent/`，内部相对路径一致。
2. 删除三处旧 `.git`，保留工作文件；根目录统一使用 `main` 分支，新历史从当前代码开始。
3. 根 `.gitignore` 排除权重、数据、虚拟环境、缓存、日志和结果。CostBench 的 `env/` 是源码，必须纳入版本管理。
4. 本地 `origin` 指向云端带工作目录的仓库，云端配置 `receive.denyCurrentBranch=updateInstead`，推送提交时更新工作文件。
5. 每次任务只选一端修改，提交后同步另一端；实验与运行验证仍在云端完成。切换修改端前，先确认双方提交和工作区状态。
6. 项目级脚本归入 `scripts/`；说明归入 `docs/`；后续重要工程取舍追加 ADR。

## 备选与取舍

保留嵌套仓库或使用 submodule 能独立跟踪上游，但不符合此次统一管理要求。持续双向 rsync 无法提供提交历史与冲突保护，因此只用于初次引入代码，日常以 Git 提交同步。

直接推送到云端工作仓库省去额外部署目录，但要求云端工作区无未提交修改，且推送不会自动重启进程。旧 Git 历史被明确舍弃；上游更新以后需作为显式维护任务处理。

## 验证与边界

验收标准：两端 `HEAD` 一致且工作区干净；版本文件内容一致；项目内仅根目录一个 Git；权重与数据未出现在本地或跟踪清单；云端数据和已有服务继续存在。

初始化已验证上述条件：共同基线为 `02b5f4f`，跟踪 425 个文件；排除规则检查通过，云端服务健康接口正常。具体操作见 [版本同步说明](../version-control.md)。

后续如需多人协作或正式部署，可新增中央远程仓库与独立部署流程，另写 ADR 替代本决策。
