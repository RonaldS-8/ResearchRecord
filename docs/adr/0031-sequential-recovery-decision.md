# ADR-0031 · Sequential Recovery Decision MVP

2026-11-11。用户批准 Gate 32：仅开发机制验证和少量真实 Agent 续程，不启动正式方法比较。

沿用 Q2 与动作条件价值定义。检查点是一次模型决策前、仍有未解决恢复义务的公开历史快照；每次实际工具反馈到达后重新构造。写入超时产生“提交结果未知”义务；成功请求查询产生 `not_found` 或携带真实 ID 的 `found` 子状态；查询失败不能证明未提交。`not_found` 允许基于实际库存凭据再写，`found` 允许复核实际 ID，禁止规则重复创建。成功创建仍保留复核义务，实际状态回读满足义务后才退出检查点。停止是可选终止动作，不保证正确停止或完成。

复用 `methods.py` 的公开上下文接口及 `toolmaze_recovery/run.py` 的原生循环。新增上下文只接受任务、公开工具合同及实际调用/回执，不接收 Session、故障条件、私有提交状态或参考路径。可用集合表示按当前证据可满足任务约束的工具选择；它不是执行器的全部可调用工具。原生 ReAct 的工具列表不受该集合限制，违规或重复效果仍由原评分判定。所有组存档相同定义的检查点。

序贯价值接口逐动作记录续程策略、直接支持度 0、成功率及剩余费用 unknown。无训练历史，不从脚本或隐藏状态补估。费用起点为当前检查点，当前动作及未来实得调用计入剩余费用，之前均为沉没成本。脚本 CPU 证人只验证接口和规则续程，不能估计真实 Agent 价值。

对照仅原生 ReAct 与 Simple Feedback Rule。规则只选工具或停止，模型自行绑定参数、消费真实回执、执行续程及生成答复。共同工具合同不增添选路指令。外部首次诊断限制单列，不称自主选路。无新增依赖，不改执行器、计价、评分、合同或历史非法调用审计。

实验及止损：[034](../experiments/034-sequential-recovery-decision.md)。本轮交付后按 Go/No-Go 报告；规则达到全部开发场景完成仍算机制 Go，不据结果调整环境或提示。
