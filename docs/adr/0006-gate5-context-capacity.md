# ADR-0006：Gate 5 上下文容量修订

- 日期：2026-11-05；状态：用户明确批准“稍微扩一点上下文”，允许显存再放宽约 10%。
- 原因：实验 007 第一次正式批量在第 3 对因输入 16769 + 输出预留 16000 > 上限 32768，被服务拒绝。原始失败保留，不当作完成对照。

仅将服务上下文上限设为 40960 Token、vLLM 显存使用比例设为 0.90（原启动参数 0.85）。检查时 GPU 实占 21402/24564 MiB，约 87%，与配置比例和用户估计的约 80% 不是同一测量；0.90 是容量配置而非实际峰值保证，不直接设置到 0.95。保留并发上限 2、实验请求串行、eager 模式和原解析器。新增项目脚本 `scripts/serve_gate5_vllm.sh`，不修改 Benchmark 内原启动脚本。

不改变模型、采样参数、max_tokens=16000、消息历史、Prompt、三种子、任务、价格、故障、预算或评分器。不根据模型行为压缩消息或修复输出。扩大容量不保证所有重复动作都能运行到 8 步，不自动继续扩容。

先提交本修订，再停止空闲的旧服务并按新配置启动；保存旧/新进程参数、GPU 状态、服务完整日志、模型列表及检查记录。服务就绪后使用原 Gate 5 启动器重新执行测试、单对自检、六请求检查和 120 对正式运行，独立目录 `results/007-gate5-20261105-02/`。全部从头采样，不拼接旧批次、不挑选旧结果。

新批次全部阶段共享同一新服务；分析以它作为修订后的正式批次，旧批次单列失败证据，不与 Gate 4 的运行时或确定性检查混合估计。仍只与冻结 Gate 3 的环境成本参照比较，Token/延迟分开报告。成功标准和停止条件不变；原始辅助汇总遗漏失败分母的问题须在停止审计中明确说明，不据此报告 100% 完成。

## 随后的用户授权：仅超限样本例外

用户明确批准“单个样本超限记录好编号和错误原因后其他可以继续跑，其他错误再停止”。新批次运行前采用：仅识别 OpenAI SDK BadRequestError、HTTP 400 且明确说明 maximum context length / input_tokens 的服务拒绝；该状态标为 `context_limit`，保留种子/Prompt/价格/任务/状态编号、全部原始错误与已执行费用，计入所有启动状态的未完成分母。继续配对的另一状态及后续样本，不重试超限请求、不截断或降低输出预算。共享首次请求若超限，两状态均记录未完成，不再各发同一请求。

其他 400、连接错误、输出截断、多动作/空输出、预算耗尽、泄漏及评分异常仍停止。六请求确定性检查若遇明确上下文超限，也单列失败请求并继续余下重复，不将缺失输出当一致。批次“遍历完计划”与“全部合法完成”分开记录，报告所有超限编号和失败率；不得只汇总成功轨迹或用未完成的低花费声称成本优势。实现增加错误分类及分支继续的必要测试，无新依赖。

## 用户批准继续现有计划

批次 02 在第 79 对因 8 次决策耗尽停止后，用户要求先跑完能取得的结果。仅续跑剩余 41 对，旧样本不重试；将决策预算耗尽归为单状态未完成，继续其他状态，其他协议/评分/泄漏错误仍停止。不增加预算、改提示或扩充任务。独立续跑器核对旧顺序前缀、来源哈希和条件一致性，新目录保留新日志，并输出引用两批原始证据的合并摘要。现有运行器默认停止行为保留，仅续跑显式启用预算耗尽继续。
