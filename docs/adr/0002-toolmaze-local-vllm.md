# ADR-0002：ToolMaze 使用云端本机 vLLM 服务

- 日期：2026-11-02
- 状态：已接受

## 背景与问题

用户希望跑通 `C1_task_001_P0/P1 --inference-only`。默认配置使用了与磁盘权重不匹配的模型名，接口地址和密钥为空。权重实际位于云端 `models/Qwen3-4B-Thinking-2507`，环境已安装 vLLM 0.31.0，GPU 为 RTX 4090。

## 决策

沿用 ToolMaze 现有 OpenAI 兼容 VLLMAgent，通过 `127.0.0.1:8000/v1` 访问独立 vLLM 服务；服务从云端磁盘加载权重。启动脚本使用 `hermes` 工具解析与 `qwen3` 推理解析，上下文上限 32768 token，最大并发 2，显存利用率 0.85，并以 eager 模式启动。

默认配置中的模型名称与服务 `served-model-name` 一致。启动脚本将虚拟环境加入 PATH，解决首次请求编译采样组件时找不到已安装 `ninja` 的问题。

将原先写死的 45 秒请求超时改为 Agent 参数，保持默认 45 秒；当前 vLLM 配置设为 300 秒，以容纳 Thinking 模型生成。未配置 Judge，保留 `--inference-only`。

## 备选与取舍

直接在评测进程内加载模型需要改变现有架构，当前无必要。独立服务可沿用既有接口，但需要先启动且占用 GPU。eager 模式减少初始编译流程，吞吐量未做优化或对比。本配置服务于功能跑通，不构成性能最优声明。

## 验证与边界

实际加载权重并请求成功；P0 完成四次工具调用并输出最终回答。P1 收到模拟服务故障后结束，没有重试，这是已观察到的模型行为，不能解释为 P1 通过。未运行 Judge，未验证完整数据集，也未进行性能基准测试。

操作与修改文件见 [配置说明](../toolmaze-local-vllm.md)。换模型家族时需重新核实聊天模板和解析器；重启服务后配置才生效。
