# ADR-0026 · ToolMaze 恢复环境与 Agent 方法接入

2026-11-10。获准工程实现、CPU 与必要接口验收。见[实验 028](../experiments/028-toolmaze-recovery-integration.md)。

**Q2 原文。** 工具故障已被发现、但原因或持续性等状态不完全可观测时，Agent 如何权衡信息获取价值、任务恢复收益与执行成本，选择显式诊断、重试、切换或停止，以兼顾任务完成质量与恢复效率？

保留原生工具调用循环与 Gate 25 严格评分。扩展 C3-055 原生余额发布与核验任务。C3-005 采用隔离的工程合同，明确接受同设备的 mesh 或 bridge 回执，并按用户原文分析指定文本。保留后续状态核验、备份、归档和通知义务。C3-001、C3-037/041/060 的契约冲突隔离。冻结的原生文件和既有运行结果保留。

显式诊断沿用 `query_connected_devices` 的区域清单接口，限指定区域。执行器独立维护模拟设备连接状态，诊断报告当前清单。连接状态与读取端点故障分开，在线不能证明重试成功。诊断不提供归档回执，不替代必做状态读取。CPU 费用沿用每次已公布调用 1 工程单位，按执行与诊断分账。

BTM 复用工具／错误与切换后验及完整约束。动作条件记忆从同一训练档案计算指定续程下的实得完成概率和分项剩余成本，直接支持与外推分列。混合组在恢复检查点由决策器选工具，实参和后续工具调用仍由原生 Agent 提交。核心方法与规则共用公开工具契约。正式运行前还须冻结独立任务、共享实现分组、故障族、统计和预算。

后续工程阶段 Go，正式方法比较待审。共同静态合同公开已存在的替代能力与回执绑定。留出按冻结清单只做独立认证，确认性候选的轨迹不回流开发或估值。
