# ADR-0020 · 恢复机制审计与复杂 Benchmark 预研

日期为 2026-11-09。Gate 20 交付已有结果的只读机制审计和下一轮草案。保持 Q2、诊断定义与 $Q^\pi(h,a)$ 不变。证据见[实验 022](../experiments/022-recovery-mechanism-audit.md)。

## 研究边界

Q2 研究工具已报错且故障状态部分可观测时，Agent 如何权衡信息获取、恢复收益和执行成本。已有错误与历史、单独计费的显式诊断、执行动作产生的反馈分别记录。显式诊断的价值取决于它能否改变后续决策及完成或费用。

BTM 估计训练策略遇到工具错误或发生切换后回合最终成功的频率，结合替代工具和提示约束供 LLM 选动作。$Q^\pi(h,a)$ 比较从同一合法检查点 $h$ 先采取动作 $a$，再用同一续程 $\pi$ 时的严格完成概率、期望后续工具费与诊断费。历史观察提供估计依据，受控动作效果由同起点回放检验。Gate 18 的完整 BTM 是论文提示复现，Gate 19 的 BTM 是共同规则下的任务级统计对照，两者各自保留。论文数值未作为本项目证据。[Bench2Robust 附录 B.1](https://arxiv.org/html/2608.11977v2)

现有证据支持在同一检查点显式提供后续费用，可避免一些回切尝试。固定切换在 Gate 19 已完成全部可恢复起点，混合组与三节点规则逐步一致。下一轮只优先检验**备用路径是否共享故障域，以及成功回执是否改变后续义务**。ToolMaze 已覆盖动态路径和显式／隐式扰动，Calibrate-Then-Act 已研究先验与成本敏感的信息获取。此处要验证的是控制历史来源后，何时动作排序真的需要更新信念或考虑续程。共享依赖和凭据兼容性可用跨供应商执行模拟，备用路径应接受与主路径相同的终态审计。[ToolMaze](https://arxiv.org/abs/2606.05806) · [Calibrate-Then-Act](https://arxiv.org/abs/2602.16699) · [AWS Builders’ Library](https://aws.amazon.com/builders-library/avoiding-fallback-in-distributed-systems/)

## 下一轮最小版本

- **任务与动作。** 复用准备、取得凭据、登记及按需验证的流程。以预约确认和凭证归档为例，收到 A 的通用故障后，可重试 A、切换到同网关的 B、切换到独立供应商 C、购买一次网关诊断或停止。B 可返回短作用域凭据，公开合同说明其可能需要额外验证，实际义务只随成功回执揭示。统一执行器按合法回执绑定实参。严格完成要求完成所有已揭示义务并提交。
- **观察与隐藏状态。** 公开任务、故障域与接口能力、当前报价、可用动作、预算、通用错误和已揭示回执。真实网关状态、调用结果、诊断噪声和未来验证义务留在环境。A、B 共享一个短程隐状态，C 有独立失败风险。显式诊断只提供噪声信号。每接口在对应恢复节点最多执行一次；至少留足正常格验证或耗尽路线的预算。所有可用路线经合法反馈证实不可用才计正确停止，预算耗尽另列。仅在单独见证中收紧预算。
- **最小对照。** 共用任务、执行器和预算。以不可靠 B/C、共享故障、相同后续义务、无信息探针为中心格，分别单因素切换到可靠 B、同边际成功率但无共享故障、回执改变验证义务、同价有信息探针。另保留共同阻断夹具作评分验收。只增加必做步骤且不改变选路的长度对照，可复用 Gate 17 的检查机制。按语义动作和节点分配随机键，未来抽样不进入公开视图。
- **同源历史。** 新供应商与回执合同需要新训练观测。按家族和种子分离训练、验证和留出。保留基准策略的自然回合历史计算 BTM，另在训练检查点平衡分配合法首动作、执行统一续程，估计动作条件值和覆盖。核心组先在同一观察历史上比较。若加入受控记录，再用一份共用训练池分别计算两种统计，分层报告采集方式及分母。已知生成参数和隐藏状态只供独立评估参照。
- **强基线。** 比较验证集冻结的最佳固定顺序、考虑当前报价和回执的静态阈值、最近反馈规则、无历史、共同规则 BTM、相同信念下的局部规则与固定续程，以及用相同拟合的有限步规划。复用 Gate 19 的绑定与证据协议、Gate 17 的随机键与双账本。新合同单独版本化。先用 CPU 做精确见证和留出回放，固定权重模型小试点待证据放行。

### 实施判据草案

1. **先验证动作反转。** 在一个登记前只剩一次取得凭据机会的检查点，取得凭据后可完成共同登记。令共享网关好／坏等权，A 成功率为 0.6／0.05，B 为 0.9／0.1，C 恒为 0.7。无探针选 C，成功率 0.70。准确率 0.8 的探针使正信号下 B 达到 0.74，负信号下仍选 C，平均完成率 0.72，探针费单列。准确率 0.5 时应保持选 C。另用 B/C 都能取得凭据、预算可覆盖验证的费用见证，B 费 1.20、C 费 2.00，后续共同费用相消。B 成功后有一半概率需额外验证、费 2.00，B 的期望费从 1.20 到 2.20，首选由 B 改为 C。这些数值用于核验合同和评分。
2. **区分为何需要规划。** 固定报价、可用工具、最后一次错误和剩余预算，查找较早的合法证据能否改变最优动作。再保持信念相同，查找未来验证义务能否使局部规则和前瞻规则选不同动作。两类分歧须分别由同起点的严格结局与账单支持。多一个工具或多一个节点本身不足以放行。
3. **保留简单规则胜出的可能。** 后续在冻结前另登记样本规模和效应阈值。若最佳固定顺序、阈值或最近反馈在两个留出家族的完成、正确停止和费用已持平，保留机制见证与负结果，收缩到能解释差距的最小策略。工程验收须覆盖防泄漏、凭据绑定、动态义务、可认证停止及独立费用账本。
