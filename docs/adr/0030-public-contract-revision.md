# ADR-0030 · 公开工具合同修订

- 日期：2026-11-11
- 状态：已批准修订与 CPU 验收（用户 2026-11-11 确认全部六项）

Gate 30，在 `Dependence` 分支完成后提 PR。Q2、诊断定义与 $Q^\pi(h,a)$ 沿用 AGENTS.md。审计清单与验收见 [实验 032](../experiments/032-public-contract-audit.md)。

## 背景与问题

Benchmark 要测的是故障后的恢复决策。$Q^\pi(h,a)$ 的完成概率和剩余成本应当由恢复动作及其续程决定，诊断返回的观察应当是可信的状态证据。Gate 29 的设施正常回合里，模型把 `employee-204` 填成 `204` 被拒，整回合按严格规则记为失败（[实验 031](../experiments/031-benchmark-family-expansion.md)）。审计全部公开合同后，发现六处参数说明、任务文字或工具行为与执行器的实际要求不一致。它们会制造与恢复决策无关的失败，其中两处还会污染状态证据或让终态无法挽回。

## 决策

只澄清“这个参数该填什么”，不提示遇到故障该做什么。

1. `read_hr_clearance` 的 `employee_number`：说明写明填任务中的完整人员标识。
2. `set_facility_access` 的 `expires_at`：说明写明固定的 UTC 格式；其他写法在参数校验阶段报错拒绝，不再建立授权。
3. `inspect_project_release` 的 `version`：与 `project` 一样校验必须和任务一致，不再对写法不同的版本号返回空列表。
4. 标识不符的报错文本：点明是哪个参数与任务授权的值不符，要求与任务中的写法一致，不透露正确值。
5. 备用读取接口的 `ticket`、`item_code`、`artifact_key`：说明写明与任务中的标识相同。
6. 两个工单任务的文字：把“包含摘要原文”改为“正文即为摘要原文”，与评分一致。

涉及 `extensions/toolmaze_recovery/tasks.py` 与 `environment.py`。评分规则、故障注入、计费和任务目标不变。

## 备选与取舍

- **只改说明文字。** 放弃。第 2、3 项的隐患在工具行为：等价写法被悄悄接受后无法纠正，写法不同的查询得到“无记录”这一错误证据。只改说明不能消除。
- **放宽评分去接受等价写法。** 放弃。那是修改评分口径，且会掩盖真实的越界参数。评分解耦另行登记。
- **保留歧义作为难度。** 放弃。这类难度与 Q2 无关，会盖住恢复方法之间的差别。
- 代价：第 3、4 项改变了模型看到的反馈，新运行与 Gate 27–29 的旧回合不再逐字可比。

## 验证与边界

- Gate 27–29 的已有结果和评分不改，不重跑、不回溯。修订后的合同记为新版本，之后的模型回合注明使用修订版。
- 被拒绝的调用仍计费并计入非法调用，当前严格规则仍会否决该回合。是否拆分“任务目标完成”与“执行合规”属于评分口径，本 ADR 不涉及。
- CPU 验收见实验 032。本轮不运行模型。
- 撤回方式：还原 `tasks.py` 与 `environment.py` 的本次提交。
