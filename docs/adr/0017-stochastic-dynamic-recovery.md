# ADR-0017 · 随机动态工作流的信念恢复

- 日期：2026-11-08
- 状态：已批准，限精确反例与小批 CPU 配对

## 问题与设计

沿用 Q2 和现有诊断定义。以同一合法恢复起点比较重试、切换、诊断、停止的条件完成概率和续程成本。BTM 的回合恢复后验、切换统计及恢复约束仍单列。Gate 16 中，合法历史和未来路由概率都能改变首动作，但显式计入路由概率的强简单规则逐轨迹达到有限规划结果。Gate 17 因此先找需要第三个恢复机会的最小反例，再检查它在随机留出中的作用。信念更新和有限规划使用已有方法，科研判断取决于对照中的决策差异。[实验 018](../experiments/018-dynamic-belief-recovery.md) · [Bench2Robust §3.1](https://arxiv.org/html/2608.11977v2#S3.SS1) · [部分可观测决策的经典框架](https://cs.brown.edu/courses/csci2951-k/papers/kaelbling98.pdf)

复用 Gate 16 的准备回执、凭据依赖、动态路由和双账本。在扩展里设置两个必需恢复节点与一个由成功回执揭示的可选节点。共享服务的隐藏状态随成功推进转移。失败调用可提供证据并触发备用，诊断仅提供有噪证据并独立收费。主格使用可靠备用以隔离费用反转，压力格再开放备用失败和预算耗尽。严格完成要求全部已激活节点合法完成、凭据来源可追溯且终态只写入一次。

策略使用训练摘要和合法观测。已知机制参照额外知道生成参数；Oracle 另见当前隐藏状态与当前路线可用性，仍通过实际调用取得未来分支和转移。评估器拥有独立账本和可达性检查，公开可认证的正确停止、预算耗尽及过早停止分别记录。

## 工程边界

审核后在 `extensions/action_conditioned_recovery/` 新增 `gate17.json`、小型图适配与随机结果表、拟合／配对入口及专项测试。复用 Gate 16 的公开回调、执行／验证及按观测分组的有限枚举。原生 ToolMaze 和已冻结 Gate 15–16 保持原样。先用云端 CPU 完成手算反例的精确验收，再执行冻结种子的小批配对。若同权限强简单规则已覆盖收益，保留负结果并停止该条件下的方法开发。采样规划、LLM 和完整 BTM 运行均留待另行审核。[实验 019](../experiments/019-stochastic-dynamic-recovery.md)
