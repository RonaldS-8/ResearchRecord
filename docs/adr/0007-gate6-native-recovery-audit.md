# ADR-0007 · Gate 6 原生恢复回放

- 日期 2026-11-06
- 状态：C3/C4 × P1/P2 原生回放范围已获批准，具体设计待审核

## 背景

Gate 1–5 的 C2 审计与规则对照提供参照。Gate 6 检查 C3/C4 是否存在可由任务内反馈改善的恢复决策。关键竞争解释是直接切换或有限次重试已达到可比较的最优水平。配对、反证标准与阶段判断见[实验 008](../experiments/008-c3-c4-recovery-audit.md)。

## 决策

- 在 `scripts/` 添加独立审计入口，优先复用现有调用记录、轨迹序列化和原生评分接口。每个分支新建原生执行器并回放前缀。C4 切换后保留各替代工具组的首次触发逻辑，记录后续故障。原始 Benchmark、工具模拟器、扰动引擎、评分器和 `docs/metrics.md` 保持原样。
- 审计器可读取扰动标签、参考路径及真值，用于构造覆盖范围和评分。策略只接收任务、工具说明及实际可见调用历史，使用跨 P1/P2 一致的策略配置。参考轨迹只能用于审计枚举和知情参照，不能替策略补齐未知工具、参数或路径。
- 工具调用次数仅作结构审计代理，保存逐工具计数并区分成功和失败。正式计价及 API 费用另行处理。复用既有云端环境，无新依赖和模型推理。

## 验证与放行

先审核并提交设计。执行阶段从实验 008 的 C3 小样本开始，检查前缀、实际反馈、参数可得性、隔离和原生评分一致性，并运行 `tests/test_no_leakage.py`。任何不一致先记录并排查。提交小样本报告后，由用户决定是否扩展 C4 或启动正式批量。
