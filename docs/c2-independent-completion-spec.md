# C2 独立合法完成验证规范与测试设计

状态：设计稿，独立于 ToolMaze Judge；尚未实现验证器、执行本节验收测试或启用新评分。范围仅为 C2。保留原始数据、工具与 Judge，不向策略提供本规范中的参考路径或真值。

## 验证对象与证据

验证一个已记录的实际调用轨迹是否完成所选合法路径，并按声明传递了正确参数。每项判断应关联任务、模板版本、路径、节点、实际 call_id、参数位置、来源 call_id/字段、实际值、规则和证据。参考 execution_trace 用于发现候选规则及矛盾，不能冒充实际调用。

候选规范从模板的 `dag.nodes`、`alternative_groups`、`parameter_bindings`，以及正常路径的 `node_sequence`、`tools` 提取。Gate 2 云端逐任务记录包含全部路径、每个节点的工具、原始参数表达式、递归来源分类和待审查问题。该清单是规范依据，不是已经人工确认的语义真值。

输入还需包括真实任务查询、按时间排序的原始调用及返回、可用工具定义和对应版本。验证者可以读取模板及评估真值，但这些内容不能进入 Agent 输入。结构化 `user_input` 字段存在，不代表 Agent 已看到其值：可见性证据须另指向实际任务查询或先前合法观测。

## 路径、工具与依赖

1. 每条候选路径明确列出节点 ID 与必要工具。判断节点实例，不只判断工具名称集合；同一工具被用于不同节点时，分别匹配参数和有效调用。
2. 一组替代分支允许完成一个完整合法分支；合并后的流程继续验证公共节点。不能把两个分支中互不衔接的局部调用拼成完整分支。
3. 复合工具若是模板中的合法原子节点，可按其公开输入/输出合同验证，不要求重复调用另一分支的分解工具。日志未记录的内部调用不能声称已经核实；内部语义正确性另列证据或“不确定”。
4. 真正数据依赖来自参数绑定；DAG 边另存为流程结构，不能自动认定每条边传递数据。无数据依赖且无其他明确先后约束的调用换序，应作为允许正例，避免照参考序列逐项比较。
5. 生产者必须在消费者调用之前实际产生所需的有效字段。消费者不能凭参考答案中的常量跳过必需生产者；调用失败、字段缺失或已知错误的生产者也不能满足依赖。
6. 重试应区分每次返回的版本。后续参数必须匹配允许使用的有效返回；不能仅因存在一次成功重试就忽略消费者仍使用旧错误值。跨路径复用只限依赖相同、参数及数据有效且合同明确允许的公共结果。

本轮清单中的 82 处引用不属于其所在路径，涉及 37 个任务、74 条路径；引用的逻辑名称为 s2/s3/s4/s6。例如模板 006 的 `{{ s3.price_usd }}` 面对实际节点 s3a/s3b，模板 007 的 `{{ s2.hotel_name }}` 面对 s2a/s2b。它们可能代表替代分支的逻辑别名，不能直接判为数据错误。独立合同须逐模板/路径明确“逻辑节点→所选实际节点→字段”的映射及依据；未确认映射时结论是不确定，不按名称前缀或数值相等自动猜测。

## 参数来源合同

每个参数或嵌套参数保留以下一种来源，不通过值相等猜测来源：

| 来源 | 合同与检查 |
| --- | --- |
| 用户输入 | 保留 `user_input.x` 路径；核对值及任务可见性证据，缺少证据时单列不可确认。 |
| 上游字段 | 保留如 `{{ s4b1.currency }}` 的节点/字段路径；检查生产者存在、先后关系、字段有效及消费者值一致。 |
| 整个上游对象 | 如 `{{ s4b1 }}`；递归比较结构与值，不能只比较 ID 或一个字段。 |
| 字面量 | 与声明常量一致；不允许把本应来自上游的绑定自动改成字面量。 |
| 明确转换 | 转换函数及允许范围必须单独登记，例如格式转换、单位换算；不得用任意字符串包含或宽松相似度代替。 |
| 未解析表达式 | 保留原文，结论为不确定；不能静默略过或自行执行模板字符串。 |

原始参数和工具实际采用的参数应区分；已有类型转换须有版本和记录。数值容差、字符串标准化、日期时区等只按明确合同处理，未定义时不自行放宽。嵌套对象、数组顺序及缺失字段均需明示。

例如 `C2_template_055`：分解分支中 `get_exchange_rate_fixer.from_currency` 来自 `s4b1.currency`，`build_balance_text_report` 的 `balance_data` 和 `rate_data` 分别来自整个 `s4b1`、`s4b2` 对象，`create_document_and_alert` 的内容等字段来自 `s4b3`；直接填入参考报告并跳过这些生产者应被发现。复合分支的 `create_balance_report_and_alert` 则是另一条合法分支，不能按分解分支要求它重复外部调用。

例如 `C2_template_001`：天气节点与 `create_document` 在 DAG 中相邻，但文档 content 明确来自 `user_input.content`；不能凭相邻关系添加“天气输出必须进入文档”的要求。`create_reminder.datetime` 则确实绑定 `s4.departure_time`，标题绑定 `s3.title`。

## 输出、完成语义与来源证明的边界

工具返回“success”或没有 error 字段只是状态证据，不足以确认数据正确。输出需独立检查字段、类型、明确业务约束和任务要求的最终结果。P3/P4 的异常能否被策略识别，与离线验证者能否用真值检查输出是两个问题，结果分开报告。

当前至少存在参考 `document_timestamp` 与实际插件输出不一致的问题：应登记合同冲突并返回不确定，不能自动忽略字段，也不能将全部正常轨迹一律视为合格。必要字段、动态值和语义等价的接受规则须确认后才实现。

普通值轨迹不能证明真实因果来源：正确生产者存在且参数相等，只能证明绑定一致。若 Agent 从另一来源获得了相同值，单条普通轨迹通常无法识别。要证明来源，需要额外的调用/字段来源标注，或在独立的合成测试中改变生产者输出，检查消费者是否随之改变；本任务仅设计此类测试，不修改 Benchmark 输出或新增运行记录能力。

结果至少分四列：必要节点完成、参数/依赖一致、最终结果语义、来源证据。每列使用通过/失败/不确定。缺必需节点、缺上游或明确错值为失败；合同缺失、参考冲突或必要来源证据不可得为不确定；只有规定的检查证据齐全才能通过。最终结论须附反例位置及未验证项，不仅输出一个布尔值。

| 编号 | 测试构造 | 预期发现/结果 |

| V13 | 无数据依赖、无明确流程约束的两个调用换序 | 正例保持通过，避免把参考顺序当作唯一合法顺序。 |

| V20 | 节点绑定、替代分支或引用语法缺失/冲突 | 不确定并列出待确认项；不得默认通过。 |
| V21 | 任务结构化输入中有值，但查询和先前观测未证明策略可得 | 标记可见性未证实，不能把参考参数可得性当作事实。 |
| V22 | 参数引用逻辑节点 s3，而所选分支只有 s3a/s3b | 有经确认且唯一的别名映射时检查实际分支字段；映射缺失/冲突时不确定，不能自动失败或默认通过。 |
